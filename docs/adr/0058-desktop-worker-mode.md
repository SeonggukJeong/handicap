# 0058. 데스크톱 부하기 모드 — 복사 전용 접속 코드 + 설치 ID + in-process 데스크톱 풀 루프

- Status: Accepted (2026-11-17, 2b = 부하기 쪽 「모드 전환」 화면)
- Date: 2026-11-17
- 관련: ADR-0057(셸 소유 설정·모드 전환 — 이 결정이 확장), ADR-0041(풀 모드·토큰), ADR-0042(in-process 임베드)
- 설계: `docs/superpowers/specs/2026-11-17-desktop-worker-mode-design.md`

## Context

1차(ADR-0057)는 서버 PC만 버튼으로 열었고, 부하기 PC는 서버 화면의 명령을 터미널에 붙여넣어야 했다. QA가 앱만으로 부하기도 붙일 수 있어야 한다. 부하기 접속에는 서버 주소(IP 여러 개 가능)·gRPC 포트·토큰 세 값이 필요한데, 손으로 입력하면 오타가 잦고 토큰이 화면에 길게 드러난다.

## Decision

**서버 화면이 접속 코드 한 줄을 만들고(복사 전용), 부하기 PC 앱이 그 코드를 붙여넣어 in-process 풀 부하기를 띄운다.** 부하기 상태는 셸 화면의 상태 패널에 보인다.

- **접속 코드 형식**: `HANDICAP1-` + 16진 문자열. 본문은 `[n u8][IPv4 × n][port u16 BE][token 길이 u16 BE][token][CRC-32 IEEE BE]`이다. 끝 4바이트 검사값이 틀리면 거절한다(오타·잘림 탐지용이며 보안 서명이 아니다). 상한은 주소 16개·코드 4096자·토큰 256바이트(`MAX_CODE_IPS`·`MAX_CODE_LEN`·`MAX_CODE_TOKEN_LEN`). 해석기는 `crates/desktop-core/src/code.rs`.
- **복사 전용**: 서버 화면은 코드를 한 줄로 줄여(말줄임) 보여 주고 「복사」 버튼으로 내보낸다. 코드는 요청형 IPC로만 받고 console·오류 줄·확인 창에 되풀이하지 않는다. **코드는 토큰을 포함하므로 비밀이다** — 공개 채널에 붙이지 않는다.
- **대상 주소 거절**: 부하기는 첫 옥텟 0·루프백·링크 로컬·멀티캐스트·브로드캐스트·240 이상·클라우드 메타데이터 주소 `100.100.100.200`만 거절한다(`is_allowed_target_ip`). CGNAT 대역(100.64/10) 전체는 막지 않는다 — Tailscale 등 CGNAT 주소의 서버로도 붙어야 하기 때문이다.
- **설치 ID**: 셸 설정 파일(`desktop-role.json`)에 설치마다 한 번 만든 영숫자 32–64바이트 ID를 저장하고, 그 설치의 부하기 ID로 쓴다. PC 이름은 같은 이름이 한 대로 합쳐지고 바뀔 수 있어 부적합했다. 서버 PC의 「이 PC도 부하 내기」 자기 부하기도 같은 설치 ID를 쓴다(이전엔 PC 이름).
- **in-process 데스크톱 풀 루프**: 부하기 역할은 `run_pool_desktop`(`crates/worker/src/lib.rs`)을 셸 프로세스 안 태스크로 돌린다. 사이클마다 IP 탐침 → 접속 → 배정 실행, 실패해도 포기하지 않고 간격을 늘려 다시 시도하며, 상태 사건(`pool_status`)을 채널로 셸에 알린다. 서버의 제외(`Disconnect`)는 취소 토큰으로 알아본다.
- **상태 통로**: 상태 사건 → 셸이 한 구조체로 접어 `role_state` 응답의 `worker` 칸에 싣고, 셸 화면이 부하기 역할일 때 1초마다 읽어 그린다(서버 역할은 3초). 상태 문구는 `desktop/src/role.html`의 `renderWorker`와 `REASON`.
- **R8 연동**: 한 부하기가 끊기면 run 전체가 중단되고 사유가 남는다(2a). 그래서 부하기에서 「접속 끊기」·역할 전환 때 run 중이면 확인 창이 「다른 부하기도 함께 멈춥니다」를 고지한다.

## 대안 (기각)

- **손으로 입력하는 PIN·짧은 코드**: 주소 여러 개·포트·토큰을 사람이 입력 가능한 길이로 줄이면 토큰 강도가 약해지고(추측·재사용), 줄이지 않으면 결국 길어 붙여넣기가 낫다. 복사 전용 + 검사값으로 오타만 막는다.
- **부하기를 자식 프로세스로 띄우기**: 1차의 명령 경로와 같다. 상태(연결 끊김·제외·재시도)를 셸이 받으려면 별도 통로가 필요하고, 앱 종료·재기동 때 고아 프로세스 정리가 어렵다. in-process는 취소 토큰 하나로 정리된다.
- **서버 컨트롤러를 부하기 역할에서도 유지**: 부하기 PC는 REST·DB가 필요 없고, 서버와 포트·run 관리가 겹친다. 부하기 역할이면 컨트롤러를 내린다(그동안 이 PC의 시나리오 화면·예약 실행·운영 모니터가 멈춘다고 확인 창이 고지).

## Consequences

- 접속 코드는 평문 토큰을 담는다 — 채널 노출 = 토큰 노출이다. 서버 화면 문구가 회사 망·평문 연결을 상기시킨다.
- 같은 설치 ID로 두 앱 인스턴스를 띄우거나, 설정 파일을 담은 PC 이미지를 복제하면 부하기가 한 대로 합쳐진다. 복제 전에는 서버·부하기로 켜지 않는 것이 원칙이고, 켰다면 복제본에서 설정 파일의 `install_id` 줄을 지운다.
- 이전 버전 앱이 설정 파일을 다시 쓰면 `install_id`·`worker` 칸이 사라져 다음에 새 설치 ID가 된다(1차 직렬화기가 모르는 칸을 버린다).
- 연기: `HANDICAP_WORKER_TOKEN`(명령 경로 토큰의 인자 노출)은 보고될 때까지, 같은 망 자동 찾기·토큰 재발급·Windows/Linux 실기 검증은 roadmap §B.
