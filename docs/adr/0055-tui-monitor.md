# 0055. 터미널(TUI) 모니터 — 컨트롤러 in-process 임베드 + 루프백 REST 클라이언트 + "json 파일이 곧 설정" + 구형 glibc 대상 빌드

- Status: Accepted (2026-11-07, spec-plan-reviewer 3라운드 APPROVE)
- Date: 2026-11-07
- 관련: ADR-0042(in-process 임베드), ADR-0053(운영 모니터), ADR-0054(보드 파일 형식)
- 설계: `docs/superpowers/specs/2026-11-07-tui-monitor-design.md`

## Context

운영 모니터 보드를 띄워 두는 PC는 저사양·EOL OS(당장 Ubuntu 19.04)인 경우가 많다. 현재 Linux 배포물(`.deb`/AppImage)은 `release.yml`의 `ubuntu-24.04` 러너에서 Tauri로 빌드되어 glibc 2.39와 `webkit2gtk-4.1`(Ubuntu 22.04+)을 요구하므로 이 PC에서 실행되지 않는다. 헤드리스 컨트롤러 + 브라우저 경로도 막혀 있을 가능성이 크다 — 19.04 기본 Firefox(66~72)가 Vite 5 기본 빌드 대상(ES2020·Firefox 78+)을 해석하지 못할 것으로 **추정**한다(실기 미확인). 새 Firefox 반입은 회선 사정상 불확실하다.

## Decision

**같은 레포의 새 crate `crates/tui`(바이너리 `handicap-tui`)로 운영 모니터 전용 터미널 화면을 만든다.**

- **엔진·판정 재사용**: 컨트롤러를 `run_in_process`로 프로세스 안에 띄우고(스케줄러 끔, 루프백 바인드), TUI는 그 컨트롤러의 기존 `/api/monitor-boards/*` REST를 루프백으로 부르는 **얇은 클라이언트**다. 점검 루프·링버퍼·스텝 판정·기록 가림은 서버 코드 그대로. 컨트롤러 와이어 변경 없음.
- **컨트롤러 기능 분리**: `in_process` 모듈을 `bundle`(웹 UI 내장)에서 떼어 새 기능 `in-process`로 게이트하고 `bundle`이 그것을 포함한다. TUI는 `in-process`만 켠다 — workspace 기능 통합으로 `ui/dist` 없는 빌드가 깨지거나 컨트롤러 바이너리가 bundle 모드로 바뀌는 일을 막고, TUI 바이너리에 웹 UI를 넣지 않는다.
- **화면 판정만 이식**: ADR-0053이 화면에 둔 규칙(기준선 색·칸 상태·끊김 판정 호출부 규칙·큰 값·연속 실패/평균 줄 게이트·격자)만 Rust로 옮기고 TS 테스트 케이스와 1:1 테스트로 묶는다. GUI 전용 표시 로직(글꼴 맞춤·크기 측정·포커스 배치·깜빡임)은 이식하지 않는다(표현 일부는 2026-11-08 개정 — 아래) — TUI는 터미널 관용(키 안내 줄·방향키·번호 메뉴)을 따른다.
- **json 파일이 곧 설정**: 실행 인자로 받은 `handicap-bundle` 파일을 매 실행마다 **빈 임시 DB**에 가져와 바로 점검을 시작한다. 그래서 ADR-0054 ②a의 겹침 거부를 만나지 않고 ②b(덮어쓰기)를 기다리지 않는다. (슬라이스 2) TUI에서 고친 설정은 같은 파일에 되써서(백업 후 원자적 교체) 재시작 후에도 유지하며, 새 파일로 교체하면 그 PC에서 고친 값은 버려진다(사용자 수용 — 설정은 GUI에서 잡는다).
- **라이브러리**: ratatui(그리기) + crossterm(백엔드, ratatui 기본값).
- **배포**: `cargo-zigbuild`로 **glibc 2.27 대상** x86_64 빌드(폴백: glibc 2.27 컨테이너 빌드). musl 정적 빌드는 기각 — 기본 할당기 성능·DNS 동작 차이가 운영 도구에 불필요한 변수다. 릴리즈 게시는 선택 에셋(실패해도 다른 플랫폼 릴리즈를 막지 않음).
- **자동 시작**: 제품이 아닌 OS 기능(`~/.config/autostart/*.desktop`, `gnome-terminal --full-screen -- sh -c '…; read x'`)에 맡기고 매뉴얼로 안내한다.
- **모니터 화면 가독성(2026-11-08 tui-readability 개정)**: 화면 *표현*은 GUI 전시 화면을 따른다(칸 높이를 채우는 막대·기준선·큰 응답 시간). 큰 값 크기는 GUI처럼 가장 넓은 값(제한 시간) 기준으로 설정·화면 크기에서만 정한다. 글자 크기 자체는 터미널 글꼴(`--zoom`)에 맡긴다. TUI 첫 저장 설정 파일(`~/.config/handicap/tui.json`, 테두리 모양).

**기각**: 별도 레포(번들 형식 `deny_unknown_fields`로 버전이 어긋나면 GUI가 내보낸 파일을 못 읽음·모니터 코드 중복) · 컨트롤러 라이브러리 함수 직접 호출(쓰기 핸들러의 "DB 쓰기 → reconcile" 규약 우회) · TUI가 `bundle` 기능 사용(위 기능 통합 문제·바이너리 비대) · DB 영속 + 재가져오기(②b 선행 필요) · UI 빌드 대상 하향(Monaco 등 보장 없음) · musl.

## Consequences

**Positive**: 구형 Linux에서 바이너리 하나로 보드가 돈다 · 서버 판정 코드 한 벌 유지 · 같은 REST라 GUI와 어긋날 곳이 화면 규칙 몇 개로 좁혀진다 · 나중에 원격 컨트롤러 접속 모드를 붙이기 쉽다.

**Negative / Trade-offs**: 화면 규칙이 TS·Rust 두 벌(테스트로 묶음) · 재시작마다 링버퍼가 비고 보드도 새로 가져온다 · 루프백 REST에 인증이 없어 같은 PC의 다른 사용자·프로세스가 환경 값을 읽을 수 있다(데스크톱 앱과 같은 자세 — 전용 단일 사용자 모니터 PC 전제) · `BoardConfig` 필드 추가 시 TUI도 같이 업데이트해야 한다(ADR-0054 귀결 그대로).
