# 0064. 상태 코드 기본 규칙(400 이상은 오류) + run별 규칙 번호

- Status: Accepted (2026-11-24, http-error-default 슬라이스 ②a)
- Date: 2026-11-24
- 관련: ADR-0017(MVP 리포트), ADR-0028(판정 기준), ADR-0049(실행 전 신뢰도), ADR-0053(운영 모니터), ADR-0061(유지 구간 기준 — 옛 run 숫자 불변 선례), ADR-0063(통과한 요청 표본)
- 설계: `docs/superpowers/specs/2026-11-24-http-error-default-design.md`. ②a(엔진·컨트롤러·리포트·인쇄·비교)를 구현했다. 에디터·안내 화면은 ②b다. ①~④ 사이에는 릴리즈하지 않는다(roadmap §A17).

## Context

상태 코드 검사를 적지 않은 http 스텝은 어떤 상태 코드든 통과였다. 검사를 빼먹으면 서버가 전부 500을 내도 오류율 0%·판정 통과로 나왔다. k6·JMeter·LoadRunner의 HTTP 기본 동작은 400 이상을 실패로 본다. 검사 표기는 값 하나(`status: 200`)뿐이어서 정상 응답이 둘 이상인 스텝(200 또는 409)이나 상태 코드와 상관없이 진행해야 하는 스텝을 적을 수 없었다. 리포트는 열 때마다 다시 만들어지므로 규칙만 바꾸면 이미 끝난 run의 유효성 글이 바뀐다.

## Decision

1. **기본 규칙**: 상태 코드 검사 줄이 하나도 없는 http 스텝은 400 이상이면 오류다(399까지 통과). 검사 줄이 있으면 그 줄만 따른다(모든 줄 만족). 끄는 전역·시나리오 설정은 두지 않는다.
2. **표기 셋**: `- status: 200` · `- status: [200, 409]`(가운데 하나) · `- status: any`(보지 않음). 빈 목록·다른 글자는 읽기 오류. 원소 하나짜리 목록은 값 하나로 읽는다. 목록은 64개까지(오류 글이 목록 전체를 싣기 때문 — 보안 리뷰).
3. **판정 함수 하나**: 엔진 `judge_status`(`Pass`/`Mismatch`/`DefaultRule`)와 `status_unchecked`(줄이 있고 모두 `any`)를 부하 경로·traced 경로·모니터 사유가 같이 쓴다. 오류 글은 계약이다: `status <코드> (>= 400)`, `status <코드> != <기대>`, `status <코드> not in [<a>, <b>]`. 기본 규칙 위반은 `ErrorClass::HttpStatus`, 준비 구간 실패 종류 `http_status`.
4. **run별 규칙 번호**: 마이그레이션 0029 `runs.status_rule INTEGER NOT NULL DEFAULT 1`. `runs::insert`가 2를 적는다(API·스케줄러 모두 이 한 곳). 리포트 `run.status_rule`(1|2)을 늘 싣는다. 리포트·인쇄·비교는 이 번호로 갈래를 나눈다 — 1이면 변경 전 동작 그대로, 2이면 새 규칙(검사 없는 스텝의 4xx·5xx는 오류, `any` 스텝만 「오류에서 제외」 표시).
5. **규칙 2 유효성**: `silent_http_errors` 대신 「상태 코드를 보지 않는 스텝」마다 `status_unchecked_errors`(범위가 적용된 스텝 수에서 4xx+5xx). `no_response_validation`은 늘 실행되는 http 스텝이 모두 `any`이고 판정 기준이 없을 때만.
6. **비교**: 규칙이 다른 run을 견주면 화면·인쇄 비교에 알림을 띄운다.

## 대안 (기각)

- **시나리오 맨 위 `http_errors: fail|pass` 스위치**: 설정 하나로 예전 구멍이 통째로 돌아온다. 스텝별 `any`가 같은 일을 더 좁게 한다.
- **엔진은 그대로, 에디터가 검사를 넣는다**: 에디터는 이미 새 스텝에 200을 넣는다. YAML 직접 작성·HAR 가져오기·지운 검사의 구멍이 남는다.
- **규칙 번호를 `profile_json` 안에**: 다시 실행 미리 채우기·프리셋이 옛 run의 profile을 복사해 새 run에 1이 실려 간다.

## Consequences

- 검사 없는 스텝이 4xx·5xx를 받으면 추출을 건너뛴다 — 그 값을 쓰는 다음 스텝이 있으면 VU가 멈출 수 있다(라이브: 로그인 401 → run `failed` 「all VUs failed」). 대처는 기대 코드 적기·추출 기본값·`any`.
- 옛 판 부하기(LAN 풀·데스크톱 부하기)는 옛 규칙으로 돌고 목록·`any`를 읽지 못한다. 컨트롤러↔워커 판 확인은 비목표 — 같은 판으로 올린다.
- 요청당 워커 CPU는 늘지 않았다(`/perf-ab master` −3.2%).
- 연기·비용·해소법은 roadmap §B93, 구현 결과는 `docs/build-log.md`.
