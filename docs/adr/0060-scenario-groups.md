# 0060. 시나리오 그룹: 시나리오당 글자 칸 1개 + 일괄 지정·이름 바꾸기

- Status: Accepted (2026-11-20, scenario-groups)
- Date: 2026-11-20
- 관련: ADR-0052(run 라벨 — 단일 TEXT 칸 선례), ADR-0054(보드 파일 `handicap-bundle` v1), ADR-0055(TUI 응답 거울), ADR-0035(UI 문구)
- 설계: `docs/superpowers/specs/2026-11-20-scenario-groups-design.md` 「접근」·「설계」 §1–§3

## Context

시나리오가 늘면서 서비스가 다른 같은 기능의 시나리오(서비스A 로그인, 서비스B 로그인)가 한 목록에 섞여 구분하기 어렵다. 사용자는 지금은 서비스 기준으로 나누고, 서비스 하나가 내려간 뒤에는 업무 기준으로 다시 나누고 싶다고 했다. 분류 기준이 고정이 아니고 나중에 통째로 바뀐다. 핵심 기능은 아니어서 작게 만든다.

## Decision

**시나리오 행에 글자 칸 `group_name` 하나를 두고, 그룹 옮기기와 이름 바꾸기를 여러 시나리오에 한 번에 하는 전용 API로 낸다.**

- **저장**: `scenarios.group_name TEXT`(NULL 허용, migration 0026). `ensure_runs_label`과 같은 모양의 Rust 가드 ALTER로 멱등하게 추가한다. NULL은 그룹에 넣지 않았다는 뜻이고 빈 문자열은 저장하지 않는다. 그룹 목록은 시나리오들의 서로 다른 값을 모은 것이라, 마지막 시나리오가 빠지면 그룹도 사라지고 그룹을 만들거나 지우는 절차가 없다.
- **이름 규칙**: 서버 `normalize_group`이 단일 소스다. 앞뒤 공백(`char::is_whitespace`와 U+FEFF)을 자르고, 비면 NULL로 바꾼다. 40 코드 포인트를 넘거나 제어 문자·방향 제어 문자·안쪽 U+FEFF가 있으면 400으로 거부한다. 대소문자는 구분한다. UI는 같은 규칙으로 미리 안내한다.
- **API**: `ScenarioResponse.group`을 항상 직렬화한다(없으면 `null`). `POST /api/scenarios`는 `group`을 선택 입력으로 받는다. `PUT /api/scenarios/{id}`는 그룹을 바꾸지 않고 응답에는 DB의 현재 값을 싣는다. 그룹은 `POST /api/scenario-groups/assign`(시나리오 1–500개를 한 트랜잭션으로 옮기기, `group: null`은 그룹에서 빼기, 키가 없으면 422)과 `POST /api/scenario-groups/rename`(이름 바꾸기, 이미 있는 이름이면 합쳐진다)으로만 바뀐다. 둘 다 `version`·`updated_at`을 건드리지 않는다.
- **화면**: 목록은 그룹이 위, 그룹 없는 시나리오가 아래다. 그룹마다 접을 수 있는 테두리 상자로 묶고, 목록에서 검색·체크·일괄 「그룹 지정」·「이름 바꾸기」를 한다. 편집·새 시나리오 화면에는 그룹 버튼이 있고, 스케줄·모니터의 시나리오 선택 칸 세 곳은 `<optgroup>`으로 묶어 보인다. 묶는 규칙은 `ui/src/scenario/grouping.ts` 한 곳에 둔다.
- **TUI**: 응답 거울(`deny_unknown_fields`)에 `group` 필드만 더한다. 화면에 보여 주지 않는다.

## 대안 (기각)

- **태그(시나리오당 여러 분류) + 필터**: 서비스 기준과 업무 기준이 함께 있을 수 있지만 입력·관리 화면이 커서 입문자에게 어렵다. 서비스 기준은 곧 사라질 예정이라 과하다. 나중에 이 글자 칸을 태그로 넓힐 수 있다.
- **이름 규칙(`서비스A/로그인`)으로 자동 묶기**: DB 변경은 없지만 기준을 바꾸려면 시나리오 이름을 전부 고쳐야 하고, 이름은 run 기록과 스케줄 표시에도 쓰인다.
- **서비스 칸 + 업무 칸 고정 2개**: 세 번째 기준이 생기면 다시 고쳐야 한다.
- **폴더 트리**: 별도 테이블, 트리 화면, 이동 규칙이 필요해 가장 크다.
- **별도 그룹 테이블**: 빈 그룹, 그룹 만들기·지우기·삭제 cascade, 순서 규칙이 따라온다. 글자 칸 하나로 같은 일이 되므로 두지 않는다.

## Consequences

- 빈 그룹이 없다. 그룹 이름은 시나리오가 들고 있는 값일 뿐이므로 그룹만 따로 남거나 지워지지 않는다.
- 그룹 변경은 시나리오 버전과 상관없다. 그룹을 바꿔도 「수정됨」이 되거나 버전이 오르지 않고, 내용 저장의 버전 충돌(409)과도 얽히지 않는다.
- 한 시점에 기준은 하나다. 기준을 서비스에서 업무로 바꿀 때는 일괄 지정과 이름 바꾸기로 옮긴다.
- 이름을 바꿔 이미 있는 그룹과 같아지면 두 그룹이 합쳐진다. 서버는 막지 않고, 화면이 합쳐진다는 것을 확인받는다.
- 보드 파일(`handicap-bundle` v1)에는 그룹을 싣지 않는다. 모르는 키를 거부하는 형식(ADR-0054)이라 싣으려면 형식을 바꿔야 한다. 가져온 시나리오는 그룹 없이 들어온다. roadmap §B에 연기로 적는다(연기 조건: 보드 파일 형식 v1 유지).
- TUI·실행 목록·리포트·비교·내보내기에는 그룹을 보여 주지 않는다.
- 선택 칸에서 고른 뒤 닫힌 `<select>`는 항목 글자만 보여 같은 이름의 시나리오를 구분할 수 없다. 항목 글자를 바꾸면 그룹이 없을 때 지금과 같은 DOM이어야 한다는 조건이 깨지므로 이번엔 그대로 둔다.
