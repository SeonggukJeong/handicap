# 0061. 유지 구간 기준 리포트: run에 저장한 `steady` 표시 + 기준별 리포트(`?basis=`) + 기본 기준

- Status: Accepted (2026-11-22, steady-window 슬라이스 A·B)
- Date: 2026-11-22
- 관련: ADR-0028(SLO criteria·저장 판정 배지), ADR-0031·ADR-0032(open-loop·stages), ADR-0037(VU 곡선), ADR-0030(비교·내보내기), ADR-0059(계단 시험 — 창 계산의 선례)
- 설계: `docs/superpowers/specs/2026-11-21-steady-window-design.md` D1–D10·§3-1·§6. 구현하며 정한 것·연기 = `docs/roadmap.md` §B82

## Context

리포트 요약은 run 전체 구간으로 계산한다. 상승(ramp-up) 구간을 넣은 부하는 낮은 초당 요청 수와 초기 지연이 평균에 섞여 「목표 부하에서의 성능」을 알 수 없다. 사용자가 이 점을 물었다. 리포트는 열 때마다 저장된 1초 창(`run_metrics`)에서 다시 계산하므로, 기준을 아무 표시 없이 바꾸면 이미 만든 run의 숫자가 달라진다. 계단 시험만 구간별 측정을 한다.

## Decision

**run을 만들 때 저장한 `steady` 표시가 있는 run만 유지 구간 기준을 쓰고, 리포트를 기준별로 통째로 만들어 `?basis=steady|whole`로 고른다.**

1. **`steady` 표시가 있는 run만 새 기준**: `Profile.steady`(`ramp_seconds`·`hold_seconds`·`discard_seconds`·open-loop 상승일 때만 `target`)를 `profile_json`에 저장한다(마이그레이션 없음). 표시가 없는 run은 리포트 JSON·판정·내보내기 숫자가 변하지 않는다.
2. **기준별로 통째로 만든 리포트**: `GET /api/runs/{id}/report?basis=steady|whole`. 유지 구간 리포트는 창 안의 행으로 지금의 `build_report` 계산을 돌린다(요약·스텝 표·분포·판정·인사이트가 같은 초를 본다). 리포트에 `basis` 블록(선택 기준·기본 기준·상태·창·다른 기준 핵심 숫자)을 더하고, `steady`가 없는 run은 이 키를 내지 않는다. 시계열(`windows`)은 어느 기준이든 run 전체다.
3. **기본 기준**: `steady`가 있고 유지 구간에 닿았으면(`measured`·`partial`) 유지 구간, 아니면 전체 구간. 닿지 못했거나(`not_reached`) 공통 구간이 없으면(`no_common_window`) 유지 구간을 고를 수 없다.
4. **모든 워커에 공통인 창 하나**: 일을 한 워커마다 시작 시각으로 창을 구해 공통 구간(`max lo`, `min hi`)을 쓴다. 워커 시작 시각은 `run_worker_starts`에 기록한다(VU 고정도 기록하도록 엔진을 바꿨다).
5. **구간으로 나눌 수 없는 집계는 run 전체 값 + 「전체 구간」 표지**: 반복 횟수별·분기·오류 종류·조건 반복 종료·묶음 지연·다운로드 단계·연결 지표는 초 단위로 저장하지 않는다.
6. **저장 판정 배지 = 기본 기준**: 완료 때 저장하는 판정은 기본 기준의 값이다. 판정은 리포트마다 그 기준의 값으로 계산한다.
7. **비교·인쇄·내보내기(슬라이스 B에서 구현)**:
   - 비교 화면과 비교 CSV/XLSX는 run마다 기본 기준 리포트를 쓰고 「집계 기준」을 표시한다. 두 run의 기준이 다르면 화면에 안내 한 줄, 비교 보고서 조건 점검에 「집계 기준」 줄(다르면 「다름」)을 둔다.
   - 인쇄는 한 번에 한 기준(화면에서 보고 있던 기준)만 인쇄한다. 머리에 기준 줄과 다른 기준의 참고 줄을 넣는다. 두 기준을 한 보고서로 묶지 않는다(사용자 결정).
   - CSV는 `?basis=`를 받고 화면의 내려받기는 보고 있는 기준을 넘긴다. XLSX는 두 기준을 담는다 — 주요 시트(`Summary`·스텝 표 등)는 요청한 기준(없으면 기본 기준)이고 반대 기준은 `Other basis` 시트에 둔다. `Summary`에 `basis` 행을 더한다. `basis` 블록이 있는 run의 내보내기 파일 이름에는 `-steady`/`-whole` 접미사가 붙는다. `steady`가 없는 run의 파일은 그대로다.

## 대안 (기각)

- **`ramp_up_seconds > 0`이면 자동으로 유지 구간 기준**: 이미 만든 VU run의 숫자가 바뀐다(US4 위반). 저장한 표시가 있는 run만 새 기준으로 한다.
- **곡선에서 유지 구간을 자동 추정**: 계단 시험 설계에서 이미 기각했다. 자유 곡선의 「측정에 포함」 표시는 다음 슬라이스로 미룬다.
- **요약·판정만 유지 구간이고 나머지는 전체 구간(초안)**: 한 리포트 안에서 기준이 섞여 숫자끼리 맞지 않는다. 사용자 제안으로 기준별 통째 리포트로 바꿨다.
- **워커별 창을 각자 세어 합산**: 요약·스텝 표·판정이 서로 다른 초를 본다. 공통 창 하나로 한다.

## spec과 다르게 구현한 것

spec과 roadmap §B82가 다르면 §B82(실제로 만든 것)가 맞다.

- **「보내지 않음」 수를 창 안에서 직접 센다**: spec D5는 나눌 수 없어 전체 구간 값이라고 했지만, 인쇄 코드가 창 안 요청 수·오류와 run 전체 「보내지 않음」을 섞어 비교해 어긋났다. 보내지 않은 요청은 건수만 올리고 상태 코드를 남기지 않으므로 「요청 수 − 상태 코드 합」으로 정확히 구한다(§B82 (0)).
- **완료 run도 창 끝을 `ended_at`에서 자른다**: spec D3은 완료 run에 제한이 없다고 했지만, `unique` 데이터셋이 바닥나 일찍 끝난 run도 `completed`라 빈 초가 측정 시간에 들어간다. 마지막 메트릭 초로는 자르지 않는다. 완료 run은 여전히 `partial`이 되지 않는다(§B82 (0)).
- **XLSX 시트 구성(슬라이스 B)**: spec D10은 「지금의 시트들은 기본 기준 값 + 「다른 기준」 시트」라고 했다. 구현은 주요 시트가 요청한 기준을 담고 시트 이름은 `Other basis`다. 파일 이름의 접미사와 인쇄의 한 기준 + 참고 줄은 위 결정 ⑦과 같다.

## Consequences

- 표시가 없는 run은 리포트·판정·내보내기가 변경 전과 같다. 새 DB 조회도 없다. `steady` run은 리포트 계산이 두 번 돈다(두 기준 + 참고 줄).
- 구간으로 나눌 수 없는 집계는 유지 구간 리포트에서도 run 전체 값이다. 해소하려면 그 집계를 초 단위로 저장해야 한다(엔진·와이어·마이그레이션)(spec §6 (1)).
- 지연은 응답이 끝난 초에 기록되므로 상승 끝의 느린 요청이 유지 구간 첫 초에 들어갈 수 있다. 버림이 흡수한다. 요청 시작 시각 기준 분류는 하지 않는다(spec §6 (2)).
- 워커 시작 시각 차이가 `hold − discard`보다 크면 공통 창이 비어 `no_common_window`다. 해소는 워커 시작을 맞추는 장치 또는 워커별 창 합산이다(spec §6 (8)·(10)).
- 같은 프리셋의 예전 run과 숫자 기준이 달라진다. 비교의 「집계 기준」 줄이 알린다(spec §6 (4)).
- 판단·연기·못 한 검증 상세는 roadmap §B82와 슬라이스 B 기록을 본다.
