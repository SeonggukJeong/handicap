# 0065. 응답 시간 경계 비교 규칙(µs) + run별 규칙 번호 + 평균·최대·임의 백분위 판정

- Status: Accepted (2026-11-24, verdict-stats ③a 슬라이스)
- Date: 2026-11-24
- 관련: ADR-0012(워커 사전 집계 HDR), ADR-0028(run 판정 기준 — 항목 확장), ADR-0061(유지 구간 기준), ADR-0063(통과한 요청 표본), ADR-0064(상태 코드 규칙 번호 — 이번 규칙 번호의 선례)
- 설계: `docs/superpowers/specs/2026-11-23-verdict-stats-a-design.md`(R1–R16, §10). ③a(서버·와이어)를 구현했다. 입력·인쇄·비교는 ③b, 통계 표시·µs 표시는 ③c다. ①~④ 사이에는 릴리즈하지 않는다(roadmap §A17).

## Context

응답 시간 판정은 분포의 p50·p95·p99를 정수 ms로 내려서 기준과 비교했다. 실제 43.9 ms인 p95가 「p95 ≤ 43」은 통과(43으로 내림)하는데 같은 표의 다른 항목은 정확히 비교하면 한 표 안에서 같은 값이 다르게 판정된다. 1 ms 미만 기준(0.5 ms)은 쓸 수 없었다. 평균·최대·임의 백분위(p90·p99.9)는 판정 항목이 아니었다(LoadRunner·JMeter·k6는 가진다). 리포트는 열 때마다 다시 만들어지므로 규칙만 바꾸면 이미 끝난 run의 판정이 조용히 바뀐다.

## Decision

1. **run별 규칙 번호**: 마이그레이션 0030 `runs.latency_rule INTEGER NOT NULL DEFAULT 1`. `LATENCY_RULE_LEGACY = 1`(내린 ms 비교 — 지금 동작), `LATENCY_RULE_CURRENT = 2`(µs 비교). `runs::insert`가 2를 적는다(API·스케줄러·다시 실행·프리셋 모두 이 한 곳). 모르는 값은 1로 읽는다. 리포트 `run.latency_rule`(1|2)을 늘 싣고 옛 JSON은 1로 읽는다.
2. **규칙 2 = 시간 기준·응답 속도 구간을 µs로 비교**: 판정 표본 분포의 µs 값을 `round(기준 ms × 1000)`와 정수로 비교한다. 응답 속도 구간 경계도 µs(`slow_us`). 규칙 1 run의 판정·결과 행·구간 건수는 바이트 그대로다.
3. **판정 항목 확장(ADR-0028 additive)**: 평균(`max_mean_ms`)·최대(`max_max_ms`)·임의 백분위(`max_percentiles_ms`, 스텝은 `mean_ms`·`max_ms`·`p<N>_ms`). 백분위 순위는 정수 순위(`ceil(N×total/100)`)로 부동소수 오차를 피한다.
4. **60초 칸 실측은 하한**: HDR 상한 60초에 걸린 값은 실제가 더 클 수 있다. 결과 행 `capped`를 싣고 op `max` 기준은 기준과 상관없이 실패로 둔다(거짓 통과보다 거짓 실패).
5. **통계 블록 `stats`(µs)**: 요약·스텝·워커·다른 기준에 `LatencyStats`를 싣는다(표본 없으면 키 없음). 정수 ms 칸(`p50_ms` 등)과 그 계산식은 바꾸지 않는다 — CSV·XLSX도 그대로.

## 대안 (기각, 사용자 결정 2026-11-24)

- **새 항목만 정확히 비교하고 기존 p50·p95·p99는 내림 유지**: 한 표 안에서 같은 43.9 ms가 「p95 ≤ 43」은 통과, 「p90 ≤ 43」은 실패한다.
- **모두 내림 유지**: 1 ms 미만 기준을 쓸 수 없다.
- **규칙 번호를 `profile_json` 안에**: 다시 실행·프리셋이 옛 run의 profile을 복사해 새 run에 1이 실려 간다(ADR-0064와 같은 이유).

## Consequences

- 같은 부하라도 규칙 2 run은 규칙 1보다 경계에서 더 엄하게 판정될 수 있다(43.9 ms vs 기준 43). 규칙이 다른 run을 견주면 화면·인쇄 비교에 알림을 띄운다(③b).
- 평균은 HDR 칸 중간값이라 실제 평균과 0.1% 안쪽으로 다르다(워커 합계 전송은 연기).
- 연기·비용·해소법은 spec §10(roadmap §B에 옮긴다), 구현 결과는 `docs/build-log.md`.
