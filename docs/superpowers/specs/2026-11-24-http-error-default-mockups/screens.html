http-error-default — 화면 목업

에디터 오른쪽 칸(Inspector)의 「응답 검증」 구획과 그 주변. 점선 테두리 = 새로 생기는 것. 단추 묶음은 프로젝트 Segmented 부품(좁은 칸이라 작은 크기), 구획 상자는 Section variant="card", 숫자 칸은 Input numeric size="sm" 그대로다.

1. 「응답 검증」 구획 — 세 가지 중 하나를 고른다

가. 기본 — 아무것도 적지 않은 스텝

▾응답 검증 상태 코드

따로 적지 않아도 400 이상(4xx·5xx) 응답은 오류로 셉니다. 399까지는 통과입니다.

나. 적은 코드만 통과 — 여러 개를 적을 수 있다

▾응답 검증200, 409만 통과 상태 코드
200 409

적은 코드 가운데 하나를 받으면 통과입니다. 그 밖의 코드는 오류로 셉니다.

다. 보지 않음

▾응답 검증상태 코드를 보지 않음 상태 코드

이 스텝은 어떤 상태 코드를 받아도 오류로 세지 않습니다. 4xx·5xx를 받으면 리포트가 따로 알려 줍니다.

「적은 코드만 통과」를 처음 고르면 200이 하나 들어간다. 마지막 코드를 빼면 「400 이상은 오류」로 돌아간다(빈 목록은 저장하지 않는다). 같은 코드를 두 번 넣으면 하나만 남는다. 100–599 밖의 숫자는 「추가」가 눌리지 않는다.

접힌 구획 — 머리 줄만으로 지금 설정이 읽힌다

▸응답 검증
▸응답 검증200, 409만 통과
▸응답 검증상태 코드를 보지 않음

기본(400 이상은 오류)은 머리 줄에 덧글이 없다 — 따로 정한 것이 없어서. 코드가 셋 이상이면 「200, 201 외 N개만 통과」.

3. 옛 표기 — 상태 코드 검사가 두 줄 이상인 YAML

▾응답 검증확인 필요 상태 코드

상태 코드 검사가 두 줄입니다(200 / 201). 두 줄을 모두 만족해야 통과라서 이 스텝은 항상 실패합니다.

YAML에 - status: 200 / - status: 201을 따로 적은 경우다. 엔진은 지금처럼 줄마다 모두 만족해야 통과로 본다(동작을 조용히 바꾸지 않는다). 화면은 알리고, 누르면 한 줄(status: [200, 201])로 합친다.

4. 스텝 목록(FlowOutline, 넓은 화면)의 칩

GET상품 조회추출 1
POST주문 생성검증 200·409추출 2
GET상태 확인상태 코드 안 봄
PUT코드가 많은 스텝검증 200 외 11

기본 스텝에는 검증 칩이 없다. 지금의 「검증 N」(검사 줄 수)은 적은 코드로 바뀐다. 코드가 셋 이상이면 「검증 200 외 N」.

5. 미리 실행 — 검사를 적지 않은 스텝이 404를 받았을 때

GET 상품 조회   404   12 ms

상태 코드 404를 받아 오류로 셌습니다. 검사를 따로 적지 않은 스텝은 400 이상을 오류로 봅니다. 404가 정상이면 「응답 검증」에서 기대하는 코드에 404를 넣으세요.

status 404 (400 이상)

7. 리포트 — 「보지 않음」 스텝이 4xx·5xx를 받은 run

상태 코드를 보지 않는 스텝 1개가 4xx·5xx 응답 1,204건을 받았습니다. 이 응답은 오류로 세지 않았습니다 — 상태 확인

지금의 「HTTP 오류 상태코드가 있으나 엔진 에러 수는 0입니다」 자리(유효성 띠)에 뜬다. 이 변경 전 run은 옛 글 그대로다.

8. 비교 — 규칙이 다른 두 run

두 run이 오류를 세는 규칙이 다릅니다. 한쪽은 상태 코드 검사가 없는 스텝의 4xx·5xx를 오류로 세지 않았습니다 — 오류율을 그대로 견주지 마세요.
