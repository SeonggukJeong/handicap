# 추출 기본값 (extract-default) — 설계

- 날짜: 2026-11-16
- 상태: 완료 (2026-11-16, 코드 `1e078957`..`0eb47460`). R5의 "입력 칸 하나"는 라이브 뒤 사용자 결정으로 「+ 기본값」 접기 방식이 대체했고, 툴팁 3번 문장에 "비밀 값은 적지 마세요 — 시나리오에 그대로 저장됩니다"가 더해졌다. 판단·연기 → roadmap §B63.
- 유형: user-path
- 출처: roadmap §B62 (0) 사용자 제안(2026-11-16) "값이 없을 때 쓸 기본값을 사용자가 고르게 하자"
- 관련: ADR-0056(조건 반복·너그러운 추출), blank-var-url-guard(§B62, 비움 표), ADR-0026(시험 실행 trace), ADR-0053(운영 모니터)

## 사용자 스토리 (US)

- **US1**: 운영자가 조건 반복으로 처리 완료를 기다리는 점검에서, 응답에 주문 번호가 없을 때도 뒤 조회 스텝을 돌리려고 추출 줄의 「값이 없을 때」에 `none`을 적는다 — 성공하면 뒤 요청이 「보내지 않음」으로 막히지 않고 주소에 `none`이 들어가 실제로 나간 것을 대상 서버 접수 기록과 모니터 기록에서 본다.
- **US2**: 운영자가 자기 주소에 직전 응답의 커서를 쓰는 조건 반복 점검에서, 한 회차에 커서를 못 받아도(값 누락·요청 실패) 점검이 그 자리에서 끝나지 않게 하려고 기본값을 적는다 — 성공하면 다음 회차 요청이 기본값으로 나가고, 그 뒤 응답에서 커서를 다시 받으면 반복이 정상 조건으로 끝나는 것을 본다(기본값이 없으면 시험 실행은 「안의 요청을 보내지 못해 여기서 끝났습니다」, 모니터는 「앞 단계 실패」(상세 「… · 값 없음」), 부하 run 리포트는 「마치지 못함」으로 끝난다).
- **US3**: QA가 조건 반복 밖 스텝에서 있을 때도 없을 때도 있는 응답 필드를 뽑을 때, 필드가 없다고 그 실행이 끝나지 않게 하려고 기본값을 적는다 — 성공하면 그 스텝이 에러 없이 통과하고, 뒤 스텝의 조건 분기가 기본값을 읽어 갈라지는 것을 시험 실행에서 본다(기본값을 적지 않은 추출은 지금처럼 그 스텝이 에러이고, 부하 run에서는 뒤 스텝이 그 이름을 쓰는 순간 VU가 죽는다).
- **US4**: 운영자가 모니터 기록 창(GUI·TUI)에서, QA가 시험 실행 결과에서 뽑힌 값을 볼 때 그 값이 서버가 보낸 것인지 기본값인지 가리려 한다 — 성공하면 기본값이 들어간 이름에만 「기본값」 표지가 보이고, 서버가 같은 글자 `none`을 실제로 보낸 경우에는 표지가 없다.

## 1. 배경 — 지금 동작

추출 실패는 스텝 위치에 따라 두 갈래다(`crates/engine/src/executor.rs` `ExtractMode`).

- **조건 반복 본문(너그러운 추출, `evaluate_lenient`)**: 못 뽑은 항목은 빠지고, `blank_missing_extracts`가 선언된 이름에 `""`를 채운 뒤 비움 표(`blank_guard::BlankTable`)에 올린다. 요청이 실패했거나(응답 없음), 응답 검증(assert)이 실패했거나, 스텝이 「보내지 않음」으로 막힌 경우도 선언된 이름이 전부 비워진다. 비움 표에 있는 이름을 주소에 쓰는 요청은 보내지 않는다(§B62).
- **조건 반복 밖(엄격한 추출, `evaluate`)**: 첫 실패에서 `Err` → 그 스텝은 에러로 세고 뽑은 값은 전부 버린다. 실행은 계속되지만 부하 run(runner)에서는 뒤 스텝이 그 이름을 쓰면 렌더 에러(`UnknownVar`)로 VU가 죽는다. 시험 실행·모니터(trace)는 너그럽게 렌더하므로(`render_collecting`) 요청이 빈 자리로 나가고 그 이름이 「미바인딩」에 뜬다. JSON `null`은 `""`로 뽑힌다. 요청 실패·assert 실패 때는 추출을 하지 않는다.

§B62가 남긴 불편(반복 뒤 스텝을 못 돌림, 커서를 한 번 못 받으면 회복 불가, `null`을 받은 값으로 쓸 수 없음)의 해소 경로가 모두 "기본값"이다.

## 2. 접근

검토한 길 세 가지.

- **(가) 추출 항목에 `default` 필드 + "스텝이 끝나면 기본값 있는 이름은 반드시 값을 가진다" 한 규칙 (채택)**. 조건 반복 안팎·실패 사유를 가리지 않는다. 기존 `blank_missing_extracts` 자리(runner `runner.rs` 2곳·trace `trace.rs` 2곳 — 조건 반복 밖에서도 부르게 한다)를 "기본값 있으면 기본값, 없고 너그러운 추출이면 `""`"로 넓히고, 엄격한 추출에는 기본값 있는 항목이 하나라도 있을 때만 쓰는 **형제 함수**를 더한다(R3 — 기존 `evaluate`는 손대지 않는다). 규칙이 하나라 화면 설명이 한 문장이고 runner·trace가 같은 함수를 쓴다.
- **(나) 조건 반복 안에서만** — 엔진 변경은 가장 작지만 반복 밖 스텝에 적은 기본값이 조용히 무시된다(사용자 결정 2026-11-16: 기각, 어디서나 동작).
- **(다) 스텝 단위 "추출 실패 무시" 스위치** — 값을 고를 수 없고(빈 값이 들어가 다시 막힌다), 어느 이름이 대체됐는지 표시할 수 없다. 기각.

## 3. 요구사항

### R0 — 지킬 조건

- `default`가 없는 추출 항목의 동작·YAML·와이어는 바이트 단위로 지금과 같다.
- runner(`execute_steps`)와 trace(`trace_steps`)는 같은 규칙으로 채운다(같은 함수).
- 기본값을 안 쓰는 시나리오의 요청당 추가 비용은 선언된 추출 항목 수만큼의 `Option` 확인뿐이다(할당 없음).

### R1 — 모델 (`crates/engine/src/scenario.rs` `Extract`, `ui/src/scenario/model.ts` `ExtractModel`)

- `Extract::Body`·`Header`·`Cookie`에 `default: Option<String>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`). `Status`에는 없다(적으면 지금의 `decode`처럼 파싱 에러).
- 값 규칙 — 엔진 역직렬화와 UI Zod가 같은 규칙으로 거절한다:
  1. 빈 문자열 금지.
  2. `{{` 또는 `${`가 들어 있으면 금지(기본값은 글자 그대로 넣는다 — 나중에 변수 지원을 더해도 기존 YAML의 뜻이 바뀌지 않게 지금 막는다).
  3. 길이 256 코드포인트 이하(엔진 `chars().count()`, UI `[...s].length`).
  4. 제어 문자(`char::is_control`, CR·LF·탭 포함) 금지 — 헤더에 쓰이면 `HeaderValue` 거절로 VU가 죽는다.
- 엔진 거절 문구는 값을 싣지 않는다(고정 사유만 — 400 응답·로그에 나간다). 구현 방식(필드 `deserialize_with` 또는 newtype)은 plan이 정한다.
- 기본값은 문자열이다. 편집 화면은 YAML에 항상 큰따옴표로 쓴다(`0`·`0x1F`·`true`·`null` 같은 글자가 serde_yaml에서 숫자·불리언으로 읽히지 않게 — `ui/src/scenario/CLAUDE.md` pick-array 줄과 같은 함정). 손으로 쓴 따옴표 없는 `default: 0`은 엔진이 타입 에러로 거절한다(수용 — 따옴표를 붙이면 된다).
- `decode`·`claim`은 기본값에 적용하지 않는다. `:num` 같은 캐스트는 쓰는 자리의 일이라 기본값에도 그대로 적용된다(`default: "0"` + `{{n:num}}` → 숫자 0).

### R2 — 채우기 규칙 (엔진)

http 스텝 하나가 끝난 뒤(정상 실행·요청 실패·assert 실패·「보내지 않음」 차단 모두, 조건 반복 안팎 모두) 그 스텝이 선언한 추출 이름 중 **뽑힌 값이 없는 이름**마다:

| 그 항목에 `default` | 조건 반복 본문 | 조건 반복 밖 |
|---|---|---|
| 있음 | 기본값을 넣는다. 비움 표에 올리지 않고, 표에 있었으면 지운다. | 같다. |
| 없음 | `""`를 넣고 비움 표에 올린다(지금과 같다). | 아무것도 넣지 않는다(지금과 같다). |

- 기본값이 들어간 이름은 "받은 값"이다 — 주소에 써도 막히지 않고, 조건(`while`/`if`)·헤더·본문에서 보통 값으로 읽힌다.
- 같은 이름을 한 스텝의 여러 항목이 선언하면: **실제로 뽑힌 값 중 선언 순서의 마지막**이 이긴다(지금과 같다 — 못 뽑은 항목은 아무것도 넣지 않는다). 뽑힌 값이 하나도 없으면 `default`가 있는 **마지막** 항목의 기본값. 엄격한 추출이 `Err`로 끝난 스텝에서는 "뽑힌 값"에 `default` 있는 항목의 결과만 센다(R3).
- 순서는 `mark_written(실제로 뽑힌 이름)` → 채우기 → **`mark_written(기본값이 들어간 이름)`** → `iter_vars.extend`. 기본값은 사용자가 고른 "받은 값"이므로 우선순위 "추출 > 요청 단위 생성"이 기본값에도 선다 — 넣지 않으면 이름이 겹친 `refresh: request` 변수가 다음 요청에서 기본값을 새 생성 값으로 덮는다(`reqgen.rs` `refresh`). `""`로 비운 이름은 지금처럼 넣지 않는다.
- parallel 분기 병합(`{분기}.{이름}`)은 바뀌지 않는다 — 분기 안에서 기본값이 들어간 이름은 보통 값으로 병합된다.

### R3 — "뽑힌 값이 없다"의 정의 (엔진)

- **너그러운 추출**: 지금과 같다(경로·헤더·쿠키 없음, 본문이 JSON이 아님, JSON `null`, decode·claim 실패, claim이 `null`).
- **엄격한 추출**: 스텝에 `default` 있는 항목이 **하나도 없으면** 지금의 `evaluate`를 그대로 부른다(동작·테스트 무변경). 하나라도 있으면 새 형제 함수를 쓴다 — 모든 항목을 선언 순서로 **끝까지** 평가한다(첫 실패에서 멈추지 않는다): `default` 있는 항목은 너그러운 추출과 같은 집합(JSON `null`·`null` claim 포함)을 "뽑힌 값 없음"으로 보고 건너뛰고, `default` 없는 항목은 지금 규칙 그대로(실패 = 에러, `null` = `""`). 에러 문구는 선언 순서에서 **첫 번째로 실패한 `default` 없는 항목**의 것(지금과 같은 문구 — `default` 있는 항목은 건너뛸 뿐 실패로 세지 않는다).
- 엄격한 추출에서 `default` 없는 항목이 실패해 `Err`가 나면 지금처럼 그 스텝은 에러이고, `default` **없는** 항목이 뽑은 값은 지금처럼 전부 버린다. `default` **있는** 항목이 응답에서 실제로 뽑은 값은 남긴다(사용자 결정 2026-11-16) — 값이 없던 `default` 항목에만 R2가 기본값을 채운다. 한 이름을 `default` 있는 항목과 없는 항목이 함께 선언했으면 `default` 있는 항목의 결과만 남는다.
- 실제 빈 문자열 `""`·빈 헤더 값은 "받은 값"이다. 기본값으로 바꾸지 않는다.
- 기본값만으로 채워진 스텝은 에러가 아니다(요청 수·에러 수·응답 시간 집계 무변경, 시험 실행 `ok` 유지).

### R4 — 기록 표지 (엔진 trace → 컨트롤러 → UI·TUI)

- `StepTrace`에 `defaulted: Vec<String>` — 그 스텝에서 기본값이 들어간 이름, 선언 순서, 중복 없음. 비면 직렬화하지 않는다(`skip_serializing_if`, 역직렬화 `default`).
- 운영 모니터 기록(`monitor/record.rs` `build_record_body`)은 `extracted`를 지금처럼 비우되 `defaulted`(이름뿐, 값 없음)는 남긴다.
- 부하 run(runner)은 표지를 만들지 않는다(§8 연기).

### R5 — 화면 (UI·TUI)

- **편집 (`Inspector.tsx` `ExtractEditor`)**: 본문·헤더·쿠키 줄에 「값이 없을 때」 입력 칸 하나(풀기 선택 뒤). 비어 있으면 YAML에 `default` 키가 없다. 종류를 본문·헤더·쿠키 사이에서 바꾸면 기본값은 유지하고(`decode`·`claim`과 같다), 상태 코드로 바꾸면 버린다. 좁은 폭에서는 줄바꿈되며 겹치거나 잘리지 않는다.
- **편집 칸의 잘못된 입력은 store에 보내지 않는다**: `commitDrafts`가 Zod에 걸리는 값을 `dispatch`하면 `yamlError`가 서서 편집 전체가 잠긴다(`store.ts`, `RequestModel.url` 함정과 같은 종류). 칸에 `maxLength=256`을 두고(HTML `maxLength`는 UTF-16 단위라 이모지 같은 글자는 128자에서 막힌다 — UI가 더 엄격한 쪽이라 그대로 둔다), blur 때 R1 위반(`{{`·`${`·제어 문자)이면 칸 아래에 한국어 안내를 띄우고 그 줄의 `default`는 **직전 유효 값**(없으면 키 없음)으로 커밋한다. 손으로 쓴 YAML의 위반은 기존 문제 표시 경로(`problems.ts`)가 한국어로 낸다.
- **중요한 사항은 툴팁으로 알리거나 입력을 막는다**(사용자 지시 2026-11-16). 막을 수 있는 것은 위처럼 막고(변수 `{{`·`${`, 제어 문자, 256자 초과, 빈 값, 상태 코드 추출), 막을 수 없는 동작 규칙은 「값이 없을 때」 칸 옆 `HelpTip`(ⓘ, 본문은 `ko.glossary`, 버튼은 라벨 밖 형제, 줄마다 하나 — 접근명은 `extractDecodeAria(idx)`처럼 줄 번호를 넣은 함수 키로 줄마다 다르게)에 적는다. 툴팁에 들어갈 내용:
  1. 응답에 값이 없을 때(JSON `null` 포함) 이 글자가 대신 들어간다. 요청이 실패했거나 응답 검증에 실패했거나 보내지 못한 스텝에서도 들어간다.
  2. 기본값이 들어간 값은 받은 값으로 취급한다 — 뒤 요청 주소에 써도 막히지 않고, 그 스텝은 값 누락 때문에 에러로 세지 않는다.
  3. 적은 글자가 그대로 들어간다 — `{{변수}}`·`${ENV}`는 적을 수 없고, 풀기(base64·JWT)는 적용되지 않는다.
  4. 기본값이 쓰였는지는 시험 실행과 모니터 기록의 「기본값」 표시로 본다. 부하 실행 리포트에는 표시되지 않는다.
  
  툴팁은 좁은 인스펙터와 조건 반복 본문 안 스텝에서 잘리지 않아야 한다(라이브에서 rect 실측).
- **조건 반복 경고 「실패해도 재시도」(`loopWarnings.ts` `retryOnFailure`, `condEmptyEval.ts`)**: 지금은 본문 직계 추출 이름을 전부 `""`로 놓고 조건을 본다. 기본값이 있는 이름은 `""` 대신 그 기본값으로 놓는다(같은 이름 여러 항목이면 R2 규칙 — `default` 있는 마지막 항목). 안 고치면 `while: status ne done` + `default: done`에서 경고가 거꾸로 뜬다(`Inspector.tsx`·`FlowOutline.tsx` 두 곳에 보인다). `matches`는 왼쪽이 `""`일 때만 정규식을 돌리는 기존 가드를 그대로 둔다 — 기본값으로 왼쪽이 비지 않으면 `"unknown"`(경고 없음)이 의도된 결과다.
- **시험 실행 (`TestRunPanel.tsx`, 순차 실행 패널 포함)**: 뽑힌 값 칩 `이름=값` 중 `defaulted`에 든 이름의 칩에 「기본값」 꼬리표(색만이 아니라 글자로).
- **모니터 미리보기(`PreviewResult.tsx`)·모니터 기록 창(`CheckRecordDialog.tsx`)·TUI 기록 보기(`crates/tui/src/inspect.rs`)**: 그 스텝 행 상세에 「기본값 사용: 이름, 이름」 한 줄(`defaulted`가 비면 줄 없음). 기록에는 값이 없으므로 이름만 보인다. TUI는 이름을 기존 본문 줄 `sanitize` 경로로 그린다(plan이 확인).
- 문구는 `ko.ts`(UI)·`crates/tui/src/text.rs`(TUI) 경유. 조건 반복 도움말(`loopLenientExtractHelp`)에 "기본값을 적으면 그 값이 들어가고 막히지 않는다" 한 문장을 더한다.

### R6 — 저장·불러오기 경로

- 시나리오 저장(`api/scenarios.rs`)·스텝 템플릿 저장(`api/step_templates.rs` `validate_steps_yaml`)·보드 파일 가져오기(`monitor/board_file.rs`)는 모두 엔진 역직렬화를 거치므로 R1 위반을 거절한다(새 검증 함수 없음). 보이는 문구는 경로마다 지금 방식 그대로다 — 시나리오·템플릿 저장은 엔진 문구(영어, 값 없음), 보드 파일은 「YAML 형식이 올바르지 않습니다(N번째 줄)」, 편집 화면은 `problems.ts` 한국어.
- 옛 워커는 `default` 키를 모르는 필드로 거절한다 → 기본값을 쓴 시나리오는 워커도 새 버전이어야 한다(릴리즈 노트).

## 4. 범위 밖 (하지 않는 것)

- 기본값 안의 `{{변수}}`·`${ENV}` (R1에서 거절, §8).
- 빈 기본값(`default: ""`).
- 상태 코드 추출의 기본값.
- 부하 run 리포트의 "기본값 사용 횟수".
- 헤더·본문의 빈 값 차단(§B62 (3) 그대로).
- 응답 기반 추출 만들기 줄(`ExtractConfirmRow`)에는 기본값 칸을 두지 않는다(만든 뒤 편집 칸에서 적는다).

## 5. 와이어

- 시나리오 YAML: 추출 항목에 선택 키 `default: <문자열>`. 없으면 지금과 바이트 동일.
- `StepTrace` JSON(`POST /api/test-runs`, 모니터 미리보기·기록): 선택 키 `defaulted: [이름…]` — 비면 키 생략(`null` 아님). UI Zod는 `.optional()`.
- proto·DB migration·리포트 JSON 무변경.
- `crates/tui/src/wire.rs`는 바꾸지 않는다 — `CheckRecord.trace`가 엔진 `ScenarioTrace`를 직접 쓰고 `deny_unknown_fields`는 바깥 구조체에만 있다. `StepTrace { … }` 리터럴은 `grep -rc "StepTrace {" crates` 기준 9개 파일 44곳(컨트롤러 `monitor/{check,record,step_judge}.rs`, 엔진 `trace.rs`·`tests/blank_guard_trace.rs`, TUI)이라 필드 추가로 전부 고쳐야 한다.

## 6. 검증

- **엔진 단위**: 엄격한 추출에서 `default` 있는 항목의 일곱 실패(본문 경로 없음·JSON 아님·`null`·헤더 없음·쿠키 없음·decode 실패·claim 없음)가 `Err` 없이 빠지는지, `default` 없는 항목은 지금 그대로인지(기존 테스트 무수정 통과). `default` 없는 항목이 실패한 스텝에서 **그 뒤에 선언된** `default` 있는 항목의 실제 값이 남고 `defaulted`에 오르지 않으며 에러 문구가 앞의 실패 항목 것인지(첫 실패에서 멈추는 구현이면 RED — 순서가 반대면 공허하다). 같은 이름 여러 항목의 R2 규칙(뽑힌 마지막 값 / 없으면 `default` 있는 마지막 항목) 한 건. 채우기 함수의 표(R2) 네 칸. 역직렬화 거절 네 규칙 + 상태 코드 항목의 `default` 거절 + round-trip(없으면 키 없음).
- **엔진 통합(runner·trace 각각)**: US1(반복 뒤 주소에 기본값, 차단 0건) · US2(자기 커서: 못 받은 회차 뒤 기본값으로 요청 → 회복 → 조건으로 종료) · US3(반복 밖: 스텝 에러 0, 뒤 if가 기본값으로 분기) · **반복 밖 배선**(지금 채우기 네 자리는 모두 조건 반복 표지로 막혀 있다 — `runner.rs`의 `cond_pass`, `trace.rs`의 `in_cond_loop`): 기본값 있는 반복 밖 스텝이 (a) 요청 실패했을 때 (b) 앞에서 비워진 이름 때문에 막혔을 때 각각 기본값이 들어가는지(표지 조건을 되살리면 RED) · trace의 `defaulted`가 기본값이 들어간 스텝에만 있고 서버가 같은 글자를 보낸 스텝에는 없음(US4).
- **회귀 가드의 이빨**: 위 통합 테스트는 채우기를 일부러 끄고 RED를 확인한 뒤 되돌린다.
- **UI**: 모델(Zod 네 규칙·상태 코드 거절), 편집 칸(입력→YAML 키 생김, 비움→키 없어짐, 본문↔헤더 전환 시 유지·상태 코드 전환 시 버림, 잘못된 입력 뒤에도 `yamlError`가 서지 않고 다른 편집이 된다), 「실패해도 재시도」 경고가 기본값을 반영, 「값이 없을 때」 툴팁(네 항목 문구가 보이고 라벨 접근명을 오염시키지 않는다), 칩 꼬리표, 기록 창·미리보기 한 줄. TUI: 기록 보기 한 줄.
- **엔진 추가**: 이름이 겹친 `refresh: request` 변수가 기본값을 덮지 않는지(R2 `mark_written`).
- **라이브(US 척추)**: US1–US4를 응답기로 재현(GUI 시험 실행·모니터 보드 GUI·TUI·부하 run 1회). 극단값 — 256자 기본값·긴 이름 여러 개에서 편집 줄·칩·「기본값 사용」 줄의 겹침·잘림 실측. 편집 칸은 마운트되는 모든 진입 화면(새 시나리오·저장된 시나리오 편집·템플릿)에서 확인.
- 보안 리뷰 대상(요청 실행·추출 경로).

## 7. 판단 (틀렸을 때 비용 · 해소 경로) — 마무리 때 roadmap §B에 옮긴다

1. **엄격한 추출이 `Err`로 끝난 스텝에서 `default` 있는 항목의 실제 값은 남고, `default` 없는 항목의 값은 지금처럼 버린다.** 비용: 한 스텝 안에서 항목에 따라 "남는다/버린다"가 갈린다(기본값을 적은 항목만 실패에 강해진다). 해소: `default` 없는 항목도 남기기 — 기본값 없는 시나리오의 동작이 바뀌므로(R0) 이번에는 하지 않는다.
2. **요청 실패·assert 실패·차단 때도 기본값을 넣는다(조건 반복 밖 포함).** 비용: 반복 밖에서 요청이 실패한 뒤, 예전에는 뒤 스텝의 렌더 에러로 VU가 죽던 흐름이 기본값으로 계속 간다 — 기본값을 적은 사용자가 고른 것이지만 실패한 로그인 뒤 스텝이 기본 토큰으로 나간다. 해소: 스텝별 "실패 시에는 기본값을 쓰지 않음" 스위치.
3. **엄격한 추출에서도 `default`가 있으면 JSON `null`을 값 없음으로 본다.** 비용: `null`→`""`에 기대던 항목에 기본값을 더하면 `""` 대신 기본값이 들어간다(기본값을 더한 순간에만). 해소 불필요(선택).
4. **기본값으로만 채워진 스텝은 성공으로 센다.** 비용: 부하 run 리포트에서는 값 누락이 보이지 않는다. 해소: §8 횟수 표시.
5. **모니터 기록에는 이름만 남는다.** 비용: 기록 창에서 어떤 값이 들어갔는지는 요청 주소로만 알 수 있다(시나리오의 기본값 글자는 편집 화면에 있다). 해소: 기록에 기본값 글자를 싣기(시나리오 YAML에 이미 있는 글자라 비밀 문제는 작다).

## 8. 연기 (조건과 함께)

- **기본값 안의 변수 / "못 받으면 직전 값 유지"**(사용자 결정 2026-11-16: 글자 그대로만 — 지금 용도는 모니터). 재개 신호: 커서·etag를 직전 값으로 이어 가야 한다는 보고. 해소: 템플릿이 아니라 "못 받으면 덮어쓰지 않는다" 스위치가 먼저.
- **부하 run 리포트의 기본값 사용 횟수**(사용자 결정 2026-11-16: 뒤로). 재개 신호: 부하 run에서 값 누락 비율을 알아야 한다는 보고. 해소: 새 드레인 벡터(스텝·이름별 횟수), proto·migration.
- **에디터 정적 안내**: 조건 반복 뒤 주소가 기본값 없는 추출 이름을 쓰는 경우 "기본값을 적으면 막히지 않는다" 안내. 재개 신호: 차단을 실행 뒤에야 안다는 보고(§B62 (3)과 같은 신호).
