# 운영실 모니터 — 브레인스토밍 결정 기록 (2026-10-21)

> 이 파일은 3개 슬라이스(① 모니터 화면 본체 → ② 내보내기/가져오기 → ③ 자동 시작+전체화면)의 **공통 원천**이다.
> 각 슬라이스 spec은 이 파일과 같은 폴더의 목업을 근거로 쓰고, 여기 없는 것을 임의로 추가하지 않는다.
> 표기: **[사용자]** = 사용자가 직접 결정/요구, **[Claude]** = 대화 중 Claude가 제안한 판단(사용자 이의 없음, 재검토 가능).

## 배경 (사용자 진술)

- 통신사 회선마다 PC 1대(예: SKT 회선 PC). 각 PC에서 **시스템 2개(더비온 1.0, 2.0)** 로그인 API를 점검. 분산 워커 불필요 — PC별 단독 실행. **[사용자]**
- 현재: Ubuntu PC에서 셸 스크립트가 10초마다 로그인, 200 아니면 실패 메시지를 텍스트로 출력. 재부팅 시 자동 재기동. **[사용자]**
- 불편: 글씨가 작아 멀리서 안 보임 → "줄 길이가 달라지면" 가까이 가서 확인. **[사용자]**
- 모니터링 계정은 준비돼 있음. Grafana 없음. 스피커 없음. **[사용자]**
- 장차 Windows PC로 바뀔 수 있음, Windows에서 설정 후 Ubuntu로 옮길 수도 있음. **[사용자]**

## 제품 위치

- **같은 프로그램(Handicap) 안의 별도 기능 영역**으로 구현. 엔진(시나리오 1회 실행·trace)만 재사용, 부하 run/리포트/스케줄러 파이프라인과 분리. 모니터 점검은 run 기록을 남기지 않는다. **[Claude 제안 → 사용자 진행 승인]**
- ADR-0009(라이브 대시보드 제외)는 **부하를 거는 도중의 실시간 대시보드**에 관한 것(사용자 의도: 그건 APM으로 봄). 운영 모니터는 그 결정의 번복이 아니다. 새 ADR로 "운영 모니터링 모드" 영역 신설 + ADR-0009 범위 명시. **[사용자 교정]**
- 로그인 전용이 아니다 — 범용 API 모니터. 로그인 특화 판단(토큰 고정 판정, 비밀번호 식별) 금지. **[사용자]**

## ① 모니터 화면 본체

### 구조
- **모니터 화면(보드)** = 이름(예: "SKT 회선") + 화면 방식 + 칸(패널) 목록. **[Claude]**
- **칸 = 시나리오 단위** (스텝 단위 아님 — 다단계 흐름이 쪼개지는 문제). 칸 설정: 제목(예: "더비온 1.0"), 시나리오, 환경, 점검 주기. 제목은 시나리오가 아니라 칸 설정에 둔다. **[Claude 제안, 사용자 수용]**
- 2개 이상 시스템 = 한 보드에 칸 여러 개. **[사용자 요구]**

### 점검 주기
- **칸마다 사용자가 초 단위로 입력. 10초는 새 칸의 기본값일 뿐 — 고정 금지.** **[사용자]**
- 점검은 앱(컨트롤러) 안의 루프가 수행, 시나리오 1회 실행. **[Claude]**
- 타임아웃: 응답 없음이 기본 5초를 넘으면 실패(설정 가능). **[Claude]**

### 성공/실패 판정
- 시나리오 자체 판정(상태코드 assert, 추출 실패 등)이 실패면 실패. **[Claude]**
- 추가로 **칸별 "성공 조건"**: 응답에서 값을 골라 규칙 적용 — `값이 있음` / `비어 있지 않음` / `같음` / `같지 않음` / `포함` / `숫자 크다·작다`. 여러 개 가능, 모두 만족해야 성공. **[사용자: "응답에서 추출해서 사용자가 골라서" / 연산자 목록은 Claude]**
- 성공 조건은 **시나리오가 아니라 모니터 칸 설정에** 둔다(같은 시나리오의 부하 테스트 판정 불변). **[Claude]**
- 조건 만들기: "미리 실행" 결과의 **응답 본문에서 값을 클릭하면 조건 생성**(스텝 + JSON 경로). 시나리오에 extract를 미리 정의할 필요 없음. **[Claude 제안, 사용자 흐름 검토 중 이의 없음]**
- 실패 시 칸에 **어느 조건이 왜 실패했는지 크게** 표시(예: `✖ resultCode = E1023`, `HTTP 503`, `3회 연속 · 14:31:50부터`). **[Claude]**
- 참고(엔진 사실): 현재 `Assertion`은 `Status`만(`crates/engine/src/scenario.rs:337`), extract 경로 미존재 시 스텝 error(`executor.rs:279`), JSON `null`은 빈 문자열로 추출 성공(`extract.rs:103`) — `비어 있지 않음`이 이를 실패로 잡아야 함.

### 화면 표시 (목업: `01-display-styles-ABC.html`, `02-latency-bars-final.html`/`.png`)
- **화면 방식 A·B·C 모두 구현, 사용자가 선택**: A=칸 전체 배경색(신호등), B=어두운 칸+색 테두리, C=평소 조용·실패 칸 확대. **[사용자: "다 마음에 드네. 선택해서 쓸 수 있게"]**
- **응답속도는 ms 정수 표시**(`1,350 ms`), 소수점 초 금지. (01 목업의 "0.42초" 표기는 폐기) **[사용자]**
- 느려짐 파악 = **막대 그래프 방식만**(목업 latency-trend의 ③). "평소의 N배"(②)·별도 느림 상태 산출 방식(①)은 채택 안 함 — 단 색은 기준선 기반. **[사용자: "3번만 마음에 드네"]**
- 막대 그래프:
  - 막대 높이 = 그 회차 응답 ms, 색 = 넘은 기준선의 색(기준 미만 초록), 실패 회차 = 빨강 빗금 + ✖ 풀높이. **[Claude, 사용자 만족]**
  - **칸 좌우를 최대한 넓게. 처음엔 왼쪽부터 채움, 꽉 차면 가장 왼쪽이 사라지고 오른쪽에 새 데이터.** **[사용자]**
  - **기준선 개수·색·값 커스터마이징 + 기준값 표시.** **[사용자]**
  - **기준값 숫자는 그래프 오른쪽 전용 칸으로 — 기준선/숫자가 막대를 침범 금지.** 단위 `(ms)`는 한 번만 표시. **[사용자]**
  - 막대 개수 설정(예: 60 = 10초×60 = 최근 10분), 그래프 최대 높이(ms) 설정 — 초과 값은 맨 위에 붙음. **[Claude]**
- 레이아웃: 제목·상태(✔ 정상 / ▲ 느림 / ✖ 실패)를 칸 위쪽 한 줄, 현재 ms는 크게(상태 색), 나머지 공간은 그래프. **[사용자: 상하로 키우되 글씨가 작아지면 안 됨 → v4 비율]**
- **글자 크기 설정**(작게/보통/크게/아주 크게) — 커질수록 그래프 영역 감소. **[Claude, 사용자 이의 없음]**
- 보드 헤더: 보드 이름 + **마지막 점검 시각** + 주기. **[Claude]**
- **점검이 멈추면 회색 "확인 불가"**(멈춘 화면이 초록불을 보여주는 것 방지). **[Claude]**
- 막대 기록은 메모리에만 — 앱 재시작 시 빈 상태에서 다시 채움. **[Claude]**
- 색만으로 구분하지 않기: 상태 글자+아이콘 병기. 어두운 배경 고대비. **[Claude]**

### 깜빡임 (알림)
- 소리 알림 없음(스피커 없음). **화면 깜빡임, 켜기/끄기 가능.** **[사용자]**
- 대상 선택: "실패만"(기본) / "느림+실패". 1초 주기 부드러운 배경 밝기 변화(빠른 점멸 금지). **[Claude]**

### 전체화면
- "모니터 시작" → 전체화면. **ESC 또는 마우스 아무 버튼(좌/우/휠) 클릭으로 빠져나옴.** **[사용자]**
- 빠져나와도 **점검은 계속**, 창 모드 화면 + "전체화면" 버튼. 전체화면 중 커서 숨김(움직이면 잠깐 표시). 마우스 이동만으로는 안 빠져나옴. **[Claude]**

### 사용 흐름 (사용자 검토 완료)
1. 시나리오 에디터에서 시나리오 준비(기존과 동일)
2. "모니터" 메뉴 → 새 보드(이름, 화면 방식)
3. 칸 추가: 제목·시나리오·환경·주기
4. "미리 실행" → 스텝별 상태·ms·본문 → 본문 값 클릭으로 성공 조건 생성 + 규칙 선택
5. 기준선(값·색), 막대 개수, 깜빡임, 글자 크기
6. 저장 → "모니터 시작" → 전체화면

## ② 내보내기/가져오기

- 보드 설정 전체(화면 방식·칸·제목·주기·기준선·성공 조건·깜빡임·글자 크기)를 **파일 하나로** 내보내기/가져오기. 시나리오 YAML 내보내기와 같은 감각. **[사용자]**
- 칸이 쓰는 **시나리오도 함께 담는다**(받는 PC에 시나리오가 없어도 동작). **[Claude]**
- **환경 값(비밀번호 포함) 그대로 포함.** 프로그램은 무엇이 비밀번호인지 판단하지 않는다(범용 도구). **[사용자]**
- 내보내기 옆에 고정 문구 한 줄: "이 파일에는 시나리오와 환경 값이 그대로 들어갑니다. 보관에 주의하세요." (값 검사 아님) **[Claude]**
- Windows ↔ Ubuntu 동일 형식. **[사용자 요구에서 도출]**

## ③ 자동 시작 + 전체화면 실행

- **재부팅 후 자동으로 모니터 화면이 다시 떠야 함**(현재 셸 스크립트도 그렇게 함). **[사용자]**
- 설정 "로그인 시 자동 시작" → 앱 실행 + 지정 보드 전체화면. OS 자동 로그인은 전제(기존 운영 방식). **Ubuntu·Windows 모두.** **[Claude]**
- 현재 desktop 번들 타깃에 deb/appimage 있음, 자동시작 기능은 없음(`desktop/src-tauri/tauri.conf.json:17`).
