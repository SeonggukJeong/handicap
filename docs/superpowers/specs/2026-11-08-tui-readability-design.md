# 터미널 운영 모니터 — 원거리 가독성 (tui-readability) — 설계

- 날짜: 2026-11-08 · 유형: `user-path` · 상위 설계: [tui-monitor 설계](2026-11-07-tui-monitor-design.md) §5.1(모니터 화면)을 이 문서가 **개정**한다 · 결정 기록: [ADR-0055](../../adr/0055-tui-monitor.md)
- 목업: [`2026-11-08-tui-readability-mockups/`](2026-11-08-tui-readability-mockups/) — **`00-final-agreed.png`가 합의된 모습**(나머지는 비교 과정). 목업은 실제 터미널 문자로 그릴 수 있는 것만 썼다.
- 순서: tui-monitor 1a 다음, 1b(오류 보기)보다 먼저(사용자 지시 2026-11-08).

## 사용자 스토리 (US)

사용자 원문(앵커): ① 1a 라이브 데모 직후 "멀리서 봐야하는데 빈공간이 너무 많아. 글씨 크기도 너무 작고." ② 2026-11-08 "GUI와 같은 시각적인 효과를 원했는데 … 그래프가 아무 의미가 없잖아. 높낮이가 없어. 그리고 기준선 표시를 안해주고 있어." 실사용 목표는 **한 보드 6칸**("지금은 1~2개가 뜨고 있지만, 6개 정도 띄우려고 이걸 만든거야").

- **US1**: 운영자가 6칸 보드를 띄운 모니터를 자리에서 떨어져 본다 — 성공하면 각 칸의 상태·응답 시간(블록 문자 큰 숫자)·화면 표시 값(응답 값)이 읽히고, 느림·실패 칸은 바탕색으로도 구분되며, 칸 안에 크게 비어 있는 줄이 남지 않는다. (관찰 기준: 112×31(≈글꼴 ×1.6) 6칸에서 응답 시간이 3줄 이상 높이의 큰 숫자로 그려지고, 정상·느림 칸 안쪽의 빈 줄이 1줄 이하 — 한글 실패 사유처럼 큰 글꼴로 못 그리는 값이 든 칸은 제외.)
- **US2**: 운영자가 칸의 막대를 보고 응답 시간이 기준선을 넘었는지·점점 느려지는지 판단한다 — 성공하면 막대 높이가 응답 시간에 따라 달라 보이고(그래프 최대값 기준, 칸 높이를 채움), 기준선이 그 색 점선과 오른쪽 숫자로 보이며, 넘은 막대는 그 기준선 색, 실패 막대는 빨강 빗금으로 끝까지 올라간다.
- **US3**: 운영자가 모니터 앞에서 `Ctrl`+`+`/`−`로 터미널 글꼴 크기를 바꿔 본다 — 성공하면 TUI가 바로 새 크기에 맞춰 다시 배치되고(칸 1~9개 어느 경우에도 깨짐 없음), 도움말에 고른 크기를 자동 시작에 고정하는 방법(`--zoom=`)이 보인다.
- **US4**: 운영자가 키 하나로 칸 테두리를 굵은 선 ↔ 반 칸 블록으로 바꿔 비교한다 — 성공하면 즉시 바뀌고, TUI를 다시 띄워도 마지막 선택이 유지되며, 선택한 칸은 테두리가 아니라 흰 바탕 제목(`▶ 로그인`)으로 구별된다.

## 1. 배경 — 1a 화면 실측

1a 바이너리(`master` `d25c8a00`)를 tmux 180×50(1920×1080 전체화면 가정), 6칸 보드로 띄운 캡처(`mockups/01-current-1a-capture.png`):

- 칸 안쪽 22줄 중 **4줄**(상태·막대·시각·평균)만 차고 18줄이 빈 줄 — 1a 줄 배정(`model.rs` `panel_rows`)이 줄마다 1줄씩만 쓴다.
- 막대는 **한 줄**에 8단계(`BLOCKS ▁…█`, `bar_of`의 `clamp(1, 8)`) — 그래프 최대 2000 ms에 수 ms 응답이면 전부 `▁`. 높이 차이가 1/8칸 단위라 멀리선 평평하다.
- 기준선은 **그리지 않는다** — `crates/tui/src/view/`에서 `thresholds`는 막대 색(`bar_color`)과 상태 판정에만 쓰인다.
- 글자 크기는 터미널 글꼴로 정해지고, 6칸이면 칸 하나에 한글 몇 글자 + 숫자 몇 개가 전부라 멀리서 읽히지 않는다.

GUI 전시 화면(`LatencyBars.tsx`)은 막대 영역이 칸 남는 높이를 채우고, 기준선을 그 색 점선(`threshold-line`)+오른쪽 숫자 열(`threshold-labels`)로 그리며, 실패는 빨강 빗금(`FAIL_STRIPES`) 전체 높이다.

## 2. 목표 / 비목표 / 반목표

**목표**: 위 US1~US4. 1a 설계의 "TUI는 GUI를 흉내 내지 않고 TUI 관용대로"(2026-11-07 결정)는 **모니터 화면의 시각 표현에 한해 개정** — GUI 전시 화면과 같은 시각 효과(큰 응답 시간·칸을 채우는 막대·기준선)를 터미널 문자로 낸다. 키 조작·도움말·오류 화면 같은 조작 관용은 1a 그대로.

**비목표**
- 한글을 픽셀 글꼴로 크게 그리기 — 목업 B안(`03-pixel-hangul-B-rejected.png`) 사용자 기각("한글이 흘러내리는 느낌"). 상태 문구를 크게 할 필요도 없다(사용자: "상태문구를 크게 볼 필요는 없어").
- TUI가 터미널 글꼴 크기를 직접 바꾸기 — 대상 터미널(gnome-terminal, VTE)이 프로그램의 글꼴 크기 변경 요청을 받지 않는 것으로 안다(외부 지식, 미검증 — 틀려도 이 설계는 터미널 쪽 확대만 쓰므로 영향 없음).
- GUI 보드 설정의 `display_style`(fill/border/focus)·`font_scale`·`blink` 반영 — TUI는 한 가지 모양만. (글자 크기는 터미널 글꼴이 대신한다.)
- GUI 변경(실패 막대의 ✖ 제거 등) — GUI 0-diff. 사용자는 GUI의 ✖도 마음에 들지 않는다고 했으나 이 슬라이스 범위 밖(§10 후속 후보).
- 1b(오류 보기·칸 설정 보기) 기능.
- 막대를 칸 폭에 압축해 `bar_count` 전부 그리기 — 1a 규칙(막대 1개 = 1칸, 칸 폭에 들어가는 최신 쪽만) 유지.

**반목표**(기술적으로 동작해도 실패)
- 점검 값(응답 시간·사유 길이)에 따라 **크기 단계나 줄 위치(칸 배치)**가 바뀌어 화면이 흔들림 — GUI 전시 화면의 원칙(배율은 설정·화면 크기로만 고정)과 같다. 예외는 §4.2에 명시한 두 가지뿐: ⓐ **상태**가 실패로 바뀌어 사유 작은 줄·연속 실패 줄이 생기면 막대 영역이 그만큼 낮아진다(값이 아니라 상태 변화 — GUI도 사유 줄이 생기면 그래프가 줄어든다), ⓑ 큰 글꼴로 못 그리는 값은 같은 큰 값 블록 자리에 일반 글자로 그린다(블록 줄 수·위치는 그대로). 크기 단계는 어떤 경우에도 점검 값·상태로 바뀌지 않는다.
- 칸 1~9개 × 어떤 터미널 크기에서든 글자 겹침·칸 밖 넘침·단어/숫자 중간 자르기(1a 교훈: 좁으면 통째 단위로 줄인다).
- 큰 숫자 때문에 막대가 사라지거나 1~2줄로 납작해져 US2가 다시 깨짐.

## 3. 글자 크기 = 터미널 글꼴 (US3)

- 사용자는 `Ctrl`+`+`/`Ctrl`+`−`(gnome-terminal 자체 기능, `Ctrl`+`0` 원래대로)로 글꼴을 키우고 줄인다. 터미널이 창 크기(칸 수)가 바뀌었다고 알리면 TUI는 1a에 이미 있는 크기 변경 처리(`app.rs` `Event::Resize` → 다시 그림)로 새 칸 수에 맞춰 배치한다. TUI 코드가 글꼴 크기를 알 필요는 없다 — **배치는 오직 칸 수(터미널 크기)로 정한다**.
- 터미널은 확대 값을 기억하지 않으므로 고정은 자동 시작 줄의 `gnome-terminal --zoom=<배율>`로 한다. 도움말(`?`)과 매뉴얼(`docs/dev/tui-monitor.md` 자동 시작 예시)에 이 방법을 적는다.
- **실기 확인 항목**(사용자, Ubuntu 19.04 gnome-terminal 3.32): `--zoom=` 옵션과 전체화면에서 `Ctrl`+`+`/`−`가 동작하는지. 동작하지 않으면 매뉴얼에 프로필 글꼴 크기 변경으로 대체 안내(코드 영향 없음).

## 4. 칸 배치 (US1)

목업 `00-final-agreed.png` 기준. 용어: **칸** = 보드의 한 패널, **글자 칸** = 터미널의 한 셀.

### 4.1 크기 단계 — 설정과 화면 크기로만 정한다

큰 응답 시간을 그리는 글꼴 크기를 세 단계로 둔다.

| 단계 | 큰 값 블록 | 배치 |
|---|---|---|
| **L** | 블록 문자 큰 글꼴 **5줄**(글꼴 점 1개 = 글자 칸 2개×1줄) | §4.2 |
| **M** | 블록 문자 큰 글꼴 **3줄**(반 칸 블록 `▀▄█`, 점 1개 = 글자 칸 1개×반 줄) | §4.2 |
| **S** | 일반 굵은 글자 1줄 | §4.3(1a 배치 기반) |

**단계 결정 규칙**(보드 전체에 하나, 그리기 전에 한 번 — 점검 값·상태를 보지 않는다):

1. 칸마다 **기준 폭** = 그 칸의 제한 시간 `timeout_seconds × 1000`을 큰 값 형식으로 쓴 글자(예 `30,000`)를 그 단계 글꼴로 그린 폭 + 단위 `ms` 자리. (GUI가 `worstMs = timeout_seconds * 1000`으로 글자 배율을 정하는 것과 같은 원리.)
2. 칸마다 **예약 줄 수**(그 단계에서) = 머리 줄 1 + 큰 값 블록(5|3) + 사유 작은 줄 1 + 연속 실패 줄 1 + 시각 줄 1 + 평균·최대 줄(보드 `show_latency_stats`가 켜져 있을 때만 1) + **최소 막대 줄 수**. 사유·연속 실패 줄은 지금 실패가 아니어도 예약에 넣는다(최악 경우 — GUI가 가장 긴 상태 문구·사유 후보로 칸을 재는 것과 같은 원리). 최소 막대 줄 수는 구현자 재량이되 **3 이상**.
3. 칸의 안쪽 크기(L·M은 좌우 여백 1글자 칸씩 뺀 폭)가 기준 폭(+ `display_items`가 설정된 칸이면 화면 표시 값 최소 자리, §4.2)과 예약 줄 수를 모두 담는 가장 큰 단계가 그 칸의 단계. 보드의 단계 = 칸들 중 **가장 작은** 단계.
4. 그 결과 그리기 시점에는 단계를 바꿀 일이 없다(실패 줄이 실제로 생겨도 예약 안에서 막대 영역이 낮아질 뿐 최소 막대 줄 수는 지켜진다).

- 터미널 크기가 바뀌면(글꼴 확대 포함) 다시 계산한다 — 단계를 바꾸는 것은 화면 크기와 보드 설정뿐이다.
- 칸 최소 크기 24×6과 "창을 키워 주세요" 화면(1a `layout`·`TooSmall`)은 그대로.

### 4.2 L·M 단계 줄 구성 (위에서 아래로)

안쪽 좌우 여백 **1글자 칸**(새로 생김 — 1a는 `block.inner` 바로 안에서 시작한다).

1. **머리 줄**: 왼쪽 제목(굵게, 길면 1a처럼 `…`) · 오른쪽 상태 문구(굵게, 상태 색, 1a `state_label` 그대로 — 크게 그리지 않는다). 제목은 위 테두리에서 이 줄로 옮긴다. 제목과 상태 문구 사이는 1글자 칸 이상(모자라면 제목을 줄인다).
2. **큰 값 블록**(L 5줄 / M 3줄, 오른쪽 정렬): 이 줄들은 상태와 무관하게 **항상 이 자리**에 있다.
   - 응답 시간(정상·느림)은 숫자·쉼표를 큰 글꼴로, 단위 `ms`는 블록 맨 아래 줄 오른쪽 끝에 일반 굵은 글자로(목업처럼).
   - **큰 글꼴로 그릴 수 없는 값**은 블록 **가운데 줄**에 일반 굵은 글자로 오른쪽 정렬해 그린다(1a `big_fit` 줄임 규칙 그대로): ① 큰 글꼴 문자 집합 밖의 글자가 있는 값(한글 사유, `—`(`NO_VALUE` — 확인 중·확인 불가·지연 없음)), ② 그 단계 큰 글꼴로 그리면 **허용 폭을 넘는** 값. 블록 줄 수·위치는 그대로다(§2 반목표 예외 ⓑ).
   - **허용 폭**: 응답 시간(정상·느림)은 **기준 폭**(제한 시간 글자 — 예: 흐름 전체 응답 시간이 제한 시간보다 길면 일반 글자). 실패류 큰 값(사유)은 `display_items`가 설정된 칸이면 기준 폭(왼쪽 화면 표시 값 자리를 지킨다), 설정되지 않은 칸이면 **안쪽 사용 폭 전체** — 그래서 화면 표시 값이 없는 칸의 `HTTP 503`은 합의 목업(`00-final-agreed.png` 주문 조회 칸)처럼 큰 글꼴로 그려진다. 둘 다 설정만으로 정해지는 폭이다(점검 값 아님).
   - 큰 글꼴 문자 집합: 숫자·`,`·`.`·공백·영문 대문자(+사유에 흔한 기호 몇 개 — 구현자 재량). 소문자·한글은 없다.
   - 큰 값 색은 1a `big_color` 그대로(정상 = 흰색, 그 외 상태 색).
   - **화면 표시 값**(`display_items` 최대 2개, 1a `display_values` 규칙 그대로): 큰 값 블록 줄들 중 위 두 줄의 **왼쪽 자리**에 한 줄씩(첫 값 흰색 굵게, 둘째 값 연한색 — 1a 색). 왼쪽 자리의 폭 = 안쪽 폭 − **기준 폭** − 1(실제 값의 폭이 아니라 기준 폭으로 재므로 응답 시간이 바뀌어도 자리가 고정된다). 그 자리에 넘치면 `…`로 줄인다. 단계 결정(§4.1 ③)에서 `display_items`가 설정된 칸은(실제 값 유무가 아니라 설정 기준 — 실제 값은 정상·느림·실패에서만 생겨 상태에 따라 달라진다) 이 왼쪽 자리가 최소 폭(구현자 재량, 예 6글자 칸) 이상이어야 그 단계가 성립한다 — 그래서 "자리가 없어 아래로 내려가는" 경우는 생기지 않는다.
3. **사유 작은 줄**·**연속 실패 줄**: 1a 문구·색·줄임 그대로, 큰 값 블록 바로 아래. 해당 없으면 그 줄은 막대 영역이 쓴다(§2 반목표 예외 ⓐ).
4. **막대 영역**: 남는 줄 전부(§5).
5. **시각 줄**: 1a `axis_marks` 그대로(§5.4).
6. **평균·최대 줄**: 1a `stats_for_width` 그대로(보드 설정이 켜져 있을 때). 설정이 켜져 있으면 값이 없을 때(모두 실패·확인 중 등 `latency_stats`가 없음)도 이 줄은 **빈 줄로 자리를 지킨다**(막대 영역 높이를 바꾸는 것은 예외 ⓐ의 실패 줄뿐).

### 4.3 S 단계

1a 배치를 바탕으로 한다(안쪽 여백 없음, 위 테두리 제목, 상태 줄 = 상태 문구 + 큰 값 일반 글자, 1a의 사유 작은 줄·연속 실패·시각·평균·최대·화면 표시 값 줄). 바뀌는 것:

- **줄 배정**: 막대가 아닌 줄들을 1a 우선순위(상태 > 막대 > 시각 > 연속 실패 > 사유 작은 줄 > 평균·최대 > 화면 표시 값)로 고른 뒤 — 막대 1줄은 1a처럼 상태 다음 우선순위로 보장 — **남는 줄을 모두 막대 영역에 준다**. 즉 다른 줄이 다 들어가는 칸에서만 막대가 여러 줄이 되고, 모자라면 1a와 똑같이 낮은 우선순위 줄부터 빠진다.
- **S 단계 기준선 판정**: 기준선·숫자 열을 그릴지(§5.4 "막대 영역 3줄 이상")는 그 칸의 **최악 경우 막대 줄 수**(사유 작은 줄·연속 실패 줄이 다 있을 때 남는 막대 줄 수)로 정한다 — 상태가 바뀌어도 숫자 열이 생기고 사라지며 막대가 옆으로 밀리지 않게(단계 규칙과 같은 원리). 실제 막대 높이는 그때 남는 줄 수(예외 ⓐ). 평균·최대 줄도 L·M과 같이, 보드 설정이 켜져 있고 그 줄이 우선순위상 들어가는 칸이면 값이 없을 때 빈 줄로 자리를 지킨다(1a는 값이 없으면 줄을 뺐다).
- 막대·기준선은 §5, 테두리·선택 표시·바탕 물들이기는 §6.

## 5. 막대 그래프 (US2)

### 5.1 높이·색
- 막대 영역 높이 `R`줄 → 막대 하나의 높이 단위는 `R × 8` 단계(맨 위 글자 칸은 `▁…▇`, 아래는 `█`).
- 높이 = `latency_ms / graph_max_ms`(0~1로 자름) × `R × 8`, 반올림, **최소 1단계**(1a처럼 아주 빠른 응답도 바닥에 보인다). GUI `pct()`와 같은 비율.
- 색 = 1a `bar_color`(넘은 기준선 중 가장 높은 것의 색, 없으면 초록).

### 5.2 가로 배치
- **막대 영역 폭** `W` = 안쪽 폭 − (기준선 숫자 열이 있으면 숫자 열 폭 + 1).
- 막대 1개 = 1글자 칸. 보이는 막대 = `bar_slots`(1a) 중 최신 쪽 `min(bar_count, W)`개, **막대 영역의 오른쪽 끝에 붙여**(최신이 숫자 열 바로 왼쪽) 그린다. `bar_count < W`이면 왼쪽이 비고, 빈 슬롯(결과가 아직 없는 쪽)도 빈 글자 칸이다. (1a는 왼쪽 정렬이었다 — roadmap §B45 "막대 영역을 오른쪽 정렬" 해소를 여기서 채택. GUI는 슬롯이 칸 폭을 꽉 채우고 최신이 오른쪽 끝이다.)

### 5.3 판정별 모양 (GUI `LatencyBars.tsx`를 터미널 문자로)
- **실패(`fail`)**: 막대 영역 **전체 높이**, 빨강 **빗금 무늬**(꽉 찬 블록과 옅은 음영 블록을 줄마다 어긋나게 섞어 대각선처럼 — 목업 `06-fail-bars.png`의 셋째, 사용자 선택). **맨 위 `x`/✖ 표시는 없다**(사용자: "맨위 X는 없는게 더 나을거 같아").
- **설정 오류(`config_error`)**: 전체 높이, 회색 빗금(GUI `CONFIG_STRIPES`).
- **확인 못 함(`upstream_failed`)**: 낮은 회색 막대(GUI 높이 12%와 같은 비율, 최소 1단계).
- **분기 제외(`branch_skipped`)**: 막대 없이 바닥 줄에 작은 회색 표시 1개(GUI 빈 원). 글자는 구현자 재량 — 모호 폭 문자는 1a가 이미 쓰는 것 안에서 고른다.

### 5.4 기준선
- **그리는 조건**: 막대 영역이 **3줄 이상**일 때만(1~2줄이면 기준선들이 한두 줄에 몰려 뜻이 없다 — 그때는 막대 색만으로 넘음을 보인다). L·M은 §4.1에서 항상 3줄 이상, S는 칸 높이에 따라.
- 칸의 `thresholds` 각각을 **그 기준선 색 점선**(가로 점선 문자, 예 `╌`)으로 막대 영역 **폭 `W` 전체**에 긋는다(GUI 점선이 막대 영역 가로 전체인 것과 같다). 줄 위치 = 막대 높이와 같은 비율(`t.ms / graph_max_ms`)이 속한 줄. `graph_max_ms` 이상인 기준선은 맨 윗줄(GUI가 100%로 자르는 것과 같다). 두 기준선이 같은 줄이면 **높은 쪽 색**으로 긋는다.
- 막대가 있는 글자 칸은 막대가 이긴다(점선은 그 줄에서 막대가 닿지 않은 글자 칸에만). 넘었는지는 막대 색으로 보인다.
- **기준선 숫자 열**: 막대 영역 오른쪽 1글자 칸 띄우고, 안쪽 오른쪽 끝에 붙는 열. 숫자 = 천 단위 쉼표(`1,200`), 굵게, 그 기준선 색, 그 기준선 줄에 오른쪽 정렬. 두 기준선이 같은 줄이면 **높은 쪽 숫자만**(GUI `placeLabels`가 높은 쪽부터 겹치는 숫자를 빼는 것과 같다). 열 폭 = max(보이는 숫자 중 가장 넓은 것, 4) — 4는 시각 줄의 `(ms)`가 그 열 아래에 들어가기 위한 폭.
- 숫자 열이 있으면 시각 줄의 숫자 열 아래 자리에 `(ms)`(GUI `axisUnit`).
- 숫자 열을 두면 `W`가 너무 줄어드는 칸(기준 = 구현자 재량, 예: `W` 12글자 칸 미만)은 숫자 열·`(ms)` 없이 점선만, `W` = 안쪽 폭.
- 기준선이 없는 칸은 숫자 열도 `(ms)`도 없고 `W` = 안쪽 폭.

### 5.5 시각 줄과의 관계
시각 줄은 1a 규칙(`axis_marks`) 그대로, 다만 입력 = **보이는 막대 슬롯**이고 그리는 위치 = 그 막대들이 놓인 가로 범위(§5.2 오른쪽 정렬). 막대와 시각 줄은 계속 같은 가로 범위(1a spec §5.1 마지막 항 유지).

### 5.6 뷰 모델 변경 (계획 첫 작업)
1a `Bar { glyph }`는 한 줄짜리 글리프를 미리 계산해 둔다(`model.rs` `bar_of`). 여러 줄 높이·무늬·"막대가 이긴다" 판정에는 막대마다 **판정 종류와 높이 비율**이 필요하고, 칸 뷰(`PanelView`)에 `thresholds`·`graph_max_ms`·`timeout_seconds`가 필요하다(지금 없음). 1a 글리프·`panel_rows` 테스트(`crates/tui/tests/view_test.rs`)는 이에 맞춰 다시 쓴다.

## 6. 테두리·선택·배경 (US1·US4)

- **테두리 모양 2가지**: `굵은 선`(`┏━┓┃┗┛`, **기본** — 사용자 선택) / `반 칸 블록`(`▛▀▜▌▐▙▄▟`). 모든 칸이 같은 모양, 색은 1a `border_color`(상태 색).
- **`b` 키**(2벌식 `ㅠ`도)로 두 모양을 번갈아 바꾼다 — 모니터 화면에서 칸이 그려져 있을 때만("창을 키워 주세요" 화면·도움말·종료 확인·오류 화면에선 무시 — 보이지 않는 변경을 저장하지 않게), 즉시 다시 그린다.
- **기억**: 바꿀 때마다 TUI 설정 파일 `$XDG_CONFIG_HOME/handicap/tui.json`(기본 `~/.config/handicap/tui.json`)에 저장하고 시작할 때 읽는다. 내용은 테두리 모양 하나(`{"border": "heavy"}` / `"block"`). 보드 json에 넣지 않는다 — 보드 파일은 보드 설정이고 테두리는 그 PC의 보기 취향이라, 보드 파일을 새 것으로 바꿔도 유지된다. (브레인스토밍 중 `~/.config/handicap-tui/`로 말했으나 로그가 쓰는 `~/.local/state/handicap`과 맞춰 `handicap`으로 정함 — 구현자 판단으로 표기.)
  - 파일이 **없음** → 조용히 기본값(굵은 선; 첫 실행마다 경고가 쌓이지 않게). **못 읽음·형식이 틀림** → 기본값 + 로그 경고(오류 화면 아님).
  - **모르는 키는 무시**한다 — crate의 와이어 거울(`wire.rs`)이 쓰는 `deny_unknown_fields` 관례를 **일부러 따르지 않는다**: 이 파일은 서버 응답이 아니라 TUI 자신의 취향 파일이라, 나중 버전이 키를 더해도 옛 바이너리가 기본값으로 무너지지 않게(되쓸 때 모르는 키는 사라진다 — 수용).
  - `XDG_CONFIG_HOME`·`HOME`이 둘 다 없으면(1a `state_dir_from`과 같은 판정) 파일 없이 이번 실행 메모리에만 두고 시작 시 로그에 한 번 남긴다.
  - 저장 실패 → 로그 경고, 이번 실행에선 바꾼 모양 유지.
  - 저장은 같은 디렉터리의 **고유한 이름의** 임시 파일 → 이름 바꾸기(중간에 꺼져도 깨진 파일이 남지 않게, TUI 여러 개가 동시에 저장해도 서로의 임시 파일을 밟지 않게 — `tempfile`은 이미 의존성). 디렉터리가 없으면 만든다. 동시에 저장하면 마지막 것이 이긴다(수용).
- **선택한 칸**: 테두리 굵기로 구분하지 않는다. L·M 단계는 머리 줄 제목을 **흰 바탕 어두운 글자 `▶ 제목`**으로(사용자 승인), S 단계는 위 테두리의 제목을 같은 모양으로.
- **배경 물들이기**(구현자 판단, 사용자 승인한 정리에 포함): `느림` 칸은 최신 막대 색, `실패` 칸은 빨강을 칸 바탕에 옅게 섞은 어두운 색으로 칸 안쪽 전체를 칠한다(고정 — 깜빡이지 않는다). 다른 상태는 칠하지 않는다. GUI의 기본(`border`) 화면 방식은 바탕을 칠하지 않는다 — 바탕색은 `fill` 방식에서만이고, `blink` 설정은 칠하기가 아니라 밝기 깜빡임이다. 그래서 **TUI 전용 표현**이다(깜빡임은 없다). 섞는 비율은 구현자 재량이되 그 위 글자·기준선 숫자가 읽혀야 한다.

## 7. 키 안내 줄·도움말·매뉴얼

- 모니터 화면 키 안내 줄에 `b 테두리` 조각 추가(1a 규칙: 좁으면 앞 조각부터 통째로 빠지고 `q 종료`는 남는다 — 새 조각의 자리는 `? 도움말` 앞).
- 도움말 키 목록에 `b` 줄과 글자 크기 줄 추가: 예 `Ctrl + + / −` — `글자 크기(터미널 기능) · 고정은 자동 시작 줄 --zoom=1.6`. 1a 도움말은 높이가 모자라면 키 줄을 **뒤에서부터** 뺀다(`overlay.rs` `render_help`) — US3이 기대는 글자 크기 줄은 키 목록 **맨 앞**에 둬서 가장 늦게 빠지게 한다.
- 문구는 1a처럼 `text.rs` 한 곳에(GUI `ko.ts`에 대응 문구가 없는 TUI 전용 문구 — 1a `KEYS_*`와 같은 취급).
- 매뉴얼 `docs/dev/tui-monitor.md`: 자동 시작 예시 `Exec=` 줄에 `--zoom=` 추가와 고르는 법, 테두리 키와 설정 파일 위치(`~/.config/handicap/tui.json`, 사용자 지시: 사용 방법에 제대로 명시).
- **ADR-0055 덧붙임**: ADR-0055는 GUI 글자 배율 로직을 옮기지 않는다고 적었다 — 이 슬라이스가 "가장 넓은 값(제한 시간) 기준으로 크기를 고정"하는 원리를 터미널 단계 선택에 옮기고, TUI 첫 저장 설정 파일을 더한다는 것을 짧게 덧붙인다(새 ADR 아님).

## 8. 테스트·검증

- **화면 단위**(ratatui `TestBackend` 버퍼 단언): 막대 높이가 응답 시간에 비례해 여러 줄에 걸침(낮음·중간·`graph_max_ms` 초과 자름·최소 1단계) · 기준선 줄 위치·점선이 막대가 닿지 않은 글자 칸에만·같은 줄 두 기준선이면 높은 쪽 색·숫자 열·같은 줄 두 기준선이면 높은 쪽만·`(ms)` · 실패/설정 오류 전체 높이 무늬, 맨 위 표시 없음 · 확인 못 함 낮은 막대·분기 제외 표시 · 단계 선택 회귀 가드(반목표 1) — 조건을 고정한다: `timeout_seconds = 30`(기준 폭 `30,000`)인 칸을, **`2 ms`라면 L이 들어가지만 `30,000`은 L이 안 들어가는** 안쪽 폭으로 두고, 응답 `2 ms`와 `29,871 ms` 두 경우 모두 **M**인지 단언(고의로 실제 값 폭으로 단계를 고르게 바꾸면 `2 ms` 쪽이 L이 되어 RED가 나는지 실증). 같은 방식으로 실패 줄 유무(정상 vs 연속 실패 중)가 단계를 바꾸지 않는지, 화면 표시 값 왼쪽 자리가 응답 시간에 따라 움직이지 않는지(기준 폭 기준)도 · 큰 값 글꼴 폴백(한글 사유·`—`·허용 폭을 넘는 값은 블록 가운데 줄 일반 글자, 블록 줄 위치 불변) · `display_items` 없는 칸·제한 시간 5초·M 단계에서 `HTTP 503`이 큰 글꼴(허용 폭 = 안쪽 사용 폭) · `display_items` 있는 칸에선 같은 사유가 기준 폭을 넘으면 일반 글자 · S 단계에서 정상→실패 전환 시 숫자 열·막대 가로 위치 불변 · 평균·최대 줄 값 없을 때 빈 줄 유지 · 화면 표시 값 왼쪽 배치·`…` 줄임 · S 단계 줄 배정(다른 줄이 다 들어간 뒤 남는 줄이 막대, 모자라면 1a 우선순위) · 막대 영역 2줄 이하에선 기준선 없음(S는 최악 경우 막대 줄 수 기준) · 막대 오른쪽 정렬·시각 줄 같은 범위 · 선택 칸 흰 바탕 제목(L·M·S) · 테두리 2모양 · 배경 물들이기 상태별.
- **설정 파일**: 없음/깨짐/모르는 키 → 기본값, 저장 왕복, 저장 실패 시 세션 유지(임시 디렉터리, `XDG_CONFIG_HOME` 주입 — 1a `state_dir_from`처럼 환경값을 인자로 받는 순수 함수로).
- **키**: `b`/`ㅠ` → 모양 전환 액션, 모니터 화면에 칸이 그려진 때만(작은 화면·도움말·종료 확인·오류에선 무시).
- **라이브(머지 전 필수)**: 1a 하네스(tmux 매트릭스)로 **칸 1~9개 × 크기**(80×24, 칸 최소 크기, 112×31(≈×1.6), 180×50(≈×1), 그리고 그 사이 1~2개)를 캡처해 겹침·넘침·중간 자르기·막대 납작함 없음 확인(사용자 지시 "검증 갯수별로 다 확인" 승계 + 극단값: 긴 제목·긴 한글 사유·화면 표시 값 2개·기준선 3개 이상·`graph_max_ms` 초과 응답). 응답 시간이 고르게 변하는 응답기(예: 50~1,500 ms 무작위)로 높낮이가 보이는지. US1~US4 통과 신호 표. US3의 실제 `Ctrl`+`+`/`−`는 macOS 터미널에서 글꼴 확대로 같은 크기 변경 경로를 확인하고, gnome-terminal 실기는 사용자 확인 항목(§3)으로 build-log에 남긴다.

## 9. 보안 표면

새 네트워크·비밀 값 경로 없음. 새로 쓰는 파일은 테두리 모양 하나만 담는 설정 파일(비밀 아님). 화면 표시 값·사유는 1a가 이미 그리는 값을 위치만 바꾼다. `finish-slice` §0 grep이 판정한다.

## 10. 알려진 한계 / 후속 후보

- 글꼴을 키우면 칸 폭이 줄어 **보이는 막대 수(이력 길이)가 준다**(1a 규칙: 막대 1개 = 1칸). 예: ×1.6에서 6칸이면 칸당 약 25개.
- 모호 폭 문자(`▀▄▌▐▛▜▙▟`, `┏━┃`, `╌`, 음영 블록, 선택 표시 `▶`)는 1a와 같은 위험 — ko_KR 실기에서 정렬 확인(1a 사용자 확인 항목에 합침).
- 터미널이 확대 값을 기억하지 않는다 → `--zoom=` 고정 필요(§3).
- 후속 후보(이 슬라이스 밖): GUI 실패 막대의 ✖ 제거(사용자 언급), TUI 칸 바탕 물들이기를 GUI에도.

## 11. 구현자 재량

큰 글꼴 글리프 모양·문자 집합 세부, 단계 경계 수치(§4.1 최소 막대 줄 수 ≥ 3 조건 안에서)·화면 표시 값 왼쪽 자리 최소 폭, 빗금 무늬 패턴, 점선 문자, 배경 섞는 비율, 숫자 열 생략 기준 폭, 모듈 분할, 설정 파일 읽기/쓰기 함수 모양.
