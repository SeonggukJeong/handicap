# ui/CLAUDE.md 재분배 2차 — 압축·추상화 안전 방침 (사전 결정)

- 상태: **방침(설계 전)**. 2차 슬라이스(roadmap §B44)가 시작될 때 이 문서를 spec의 입력으로 쓴다. 이 문서 자체는 구현 지시가 아니다.
- 출처: 2026-11-07 사용자 질문("공통 함정을 추상화해 넓게 적용 vs 구체 사례를 각각 보유")과 사용자 지시("가능한 안전하게 가도록 계획").
- 전제: 1차(`docs/superpowers/specs/2026-11-06-ui-claude-md-redistribute-design.md`)가 머지됐다. 1차는 원문 그대로 이동만 했고, 압축·병합·추상화는 하지 않았다.

## 1. 원칙 — 규칙은 추상, 앵커는 구체

권장 불릿 형태:

```
- **<일반 규칙: 무엇을 하라 / 안 하면 무엇이 깨지나>** (적용 범위 + 형제의 의도적 예외) — 사례: `파일A` `식별자`, `파일B` `식별자` (slug)
```

- **추상만으로는 안 되는 이유:** 편집 순간의 상기는 "지금 고치는 파일·함수 이름이 문서에 있다"에 기댄다. 범위 없는 일반 규칙은 형제의 의도된 거동을 지우는 편집을 부른다(report-advice-noise, `ValidityBadge` ok 렌더). 무손실 검사(토큰 차분·grep 발견성)도 구체 식별자에 기댄다.
- **구체만으로는 안 되는 이유:** 같은 함정이 여러 곳에 갈라져 표류하고(1차 분류의 205↔24·162↔`useThinkTimePair`), 새 코드로 전이되지 않으며, 크기가 커진다.
- **크기의 주범은 서사다**(발견 경위·사건 이야기·superseded 상태·동형 사례 꼬리). 추상화보다 서사 이관이 먼저이고 더 안전하다.

## 2. 단계 분리 — 위험이 다른 작업을 섞지 않는다

2차는 **두 슬라이스(또는 최소 두 task·두 커밋·두 리뷰)**로 나눈다.

| 단계 | 하는 일 | 규칙 문면 | 위험 |
|---|---|---|---|
| **2a 서사 이관** | 각 불릿에서 서사만 `docs/dev/ui-gotcha-narratives.md`로 옮긴다(이동만, 삭제 금지) | **처방·증상·식별자·범위·slug는 문자 그대로 유지** | 낮음 — 규칙 줄은 부분 문자열 삭제뿐 |
| **2b 추상화 승격** | 같은 패턴의 여러 불릿을 일반 규칙 1개 + 사례 목록으로 병합 | 새 문장을 쓴다 | 높음 — 사람 판단·의미 변경 가능 |

2b는 2a가 머지되고 크기가 실측된 뒤에 **필요할 때만** 한다. 2a만으로 목표(≤ 60 KiB)에 닿으면 2b는 생략할 수 있다.

## 3. 2b 승격 조건 (전부 충족 시에만)

1. **같은 패턴의 사례가 3개 이상**이다. 2개면 병합하지 않고 서로 상호참조만 한다.
2. 후보는 **기계로 먼저 찾는다**(공통 식별자·공통 증상 문구 클러스터). 후보 목록을 **사용자에게 제시해 승인**받은 것만 승격한다.
3. 일반 규칙은 **사례들의 실수 지점을 모두 덮는 가장 좁은 문서**에 둔다(1차 §3.2 실수 지점 규칙의 확장). 사례 고유 세부(그 컴포넌트에만 맞는 예외·수치)는 원래 문서에 남긴다.
4. 일반 규칙엔 **적용 범위와 형제의 의도적 예외**를 반드시 적는다.

## 4. 기계 안전장치 (2차 spec이 게이트로 구체화할 것)

- **S1 식별자 보존:** base 불릿의 backtick 토큰이 이동 후에도 존재해야 한다.
  - 처방·증상에 쓰인 식별자는 **자동 로드 문서(ui/CLAUDE.md·하위 문서)**에 있어야 한다. narratives에만 남으면 FAIL로 띄우고 리뷰 판정을 받는다.
  - 기존 coverage 토큰 차분의 corpus를 "로드 문서"와 "narratives"로 나눠 판정한다.
- **S2 병합 회계(2b):** 승격마다 흡수한 원 불릿 anchor 전부를 `merge` 행으로 선언한다.
  - 1차 리뷰에서 확인된 한계를 먼저 고친다. 현 merge는 생존 불릿 섹션에 바닥을 귀속하고, 교차 파일 merge를 정의하지 않는다. → absorbed 쪽 base 섹션 귀속 + 교차 파일 merge 검증을 게이트에 **선행** 추가한다.
- **S3 1:1 추적 유지:** 1차의 `check-bullet-conservation.py`(D3)를 확장해, base 불릿마다 "원문 그대로 / 서사 이관(move 행) / 병합(merge 행)" 중 정확히 하나로 귀속시킨다. 미귀속 0이어야 한다.
- **S4 처방·증상 보존 리뷰:** 압축·승격된 불릿 **전수**에 대해 per-task 리뷰(`model: opus`)가 세 요소 — 처방 동사·실패 증상·식별자 — 의 잔존을 대조한다. ui-claude-md-curation에서 이관 조각 속 현행 계약 12건이 적발된 클래스다.
- **S5 블라인드 회귀 시뮬레이션:** 압축·승격 불릿 무작위 표본(≥ 10)마다 "이 함정을 밟는 편집 시나리오" 질문을 만든다. **잔류 문서만 받은 fresh subagent**가 올바른 처방을 답하는지 본다. 하나라도 틀리면 그 불릿을 원복하고 재검토한다(ui-claude-md-curation의 육안 대조 3행을 확장·블라인드화한 것).
- **S6 이빨:** 새 게이트마다 지정 FAIL 문구 RED → 원복 GREEN을 실증한다(1차 Task 3 자체 테스트 하네스에 케이스 추가).

## 5. 우선순위와 밸브

- **no-forget > 크기 목표.** 60 KiB에 못 미쳐도 규칙을 깎지 않는다. 정직 도달치를 실측해 사용자와 재협상한다(선례: ui-claude-md-curation 96→100 KiB, 1차 84→90 KiB).
- 2a에서 서사인지 규칙인지 애매한 조각은 **규칙으로 취급해 남긴다**(잘못 남기는 비용 = 몇 바이트, 잘못 빼는 비용 = 반복 사고).
- 1차에서 사용자 결정으로 잔류한 경계 5행(86·94·177·178·188)은 2차에서 **실수 지점을 코드로 재판정**한다. 크기 때문에 옮기지 않는다.
