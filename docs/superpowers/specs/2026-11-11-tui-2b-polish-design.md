- 출처: roadmap §B52 (2) 연기 항목 3건 — 사용자 선택(2026-11-11 `/start-slice`: "B. TUI 소형 보완", US 승인 "빈 화면도 포함").
- 범위: `crates/tui`만(`pick.rs`·`view/edit.rs`·`view/values.rs`·`view/inspect.rs`·`app.rs`·`text.rs` + 테스트) + 문서. **컨트롤러·엔진·proto·DB·GUI(`ui/`) 0-diff.**
- 상태: 설계 초안(리뷰 중)

## 사용자 스토리 (US)

**US1은 버그 — 재현 / 기대 / 실측**
- 재현: 응답 본문 `{"big":1e300,"tiny":1.5e-300}` → 요청·응답 `a` → `$.big` 줄 → `조건으로 추가` → `Enter`.
- 기대: 조건이 저장되고 다음 점검에서 통과한다.
- 실측: 값 칸에 `1` 뒤에 `0`이 300개 붙은 301자가 채워지고, 저장하면 서버가 `비교값은 200자 이하여야 합니다`로 거절한다. 원인: `crates/tui/src/pick.rs`의 `visit_f64`가 `format!("{v}")`(Rust `f64` `{}` — 지수 표기를 안 쓴다)로 글자를 만든다.

- **US1**: 운영자가 값 목록에서 아주 크거나 아주 작은 수를 골라 조건으로 추가한다 — 성공하면 조건 칸의 비교값이 GUI와 같은 짧은 글자(`1e+300`·`1.5e-300`)로 채워지고, `Enter`로 저장되며, 다음 점검에서 그 조건이 통과한다.
- **US2**: 운영자가 경로가 긴 본문 값의 조건을 새로 만들거나(값 목록) 이미 있는 조건을 고칠 때(칸 설정 11번) 어느 값에 대한 조건인지 확인한다 — 성공하면 조건 칸의 `대상`이 여러 줄로 이어져 경로 끝과 스텝 이름까지 읽힌다.
- **US3**: 운영자가 하위 화면(오류 보기·자세히·칸 설정·하위 목록·변수 화면·값 목록)을 보는 중에 그 화면이 그릴 칸이나 상태를 찾지 못하게 된다 — 성공하면 빈 화면 대신 맨 위 줄·안내 문구·`Esc 뒤로`가 보인다. (TUI 안에서는 칸이 지워지는 길이 없어 라이브로 재현할 수 없다 — 사용자 승인 2026-11-11: 단위 테스트로만 확인.)

## 1. 목표 / 비목표

**목표**: US1~US3.

**비목표**
- 2^53을 넘는 정수의 글자를 GUI와 맞추기 — GUI는 정밀도를 잃은 값(`12345678901234567000`)을 쓰고 TUI는 본문 글자 그대로(`12345678901234567890`)를 쓴다. 판정은 같다(서버가 f64로 비교). 정확한 쪽을 틀린 쪽에 맞추지 않는다.
- 서버의 사유·화면 표시 값에 나오는 숫자 글자(`1e300`·`1.0` — 엔진 `extract::stringify`) 바꾸기 — §9.
- `받은 값` 줄 줄바꿈(받은 값 전체는 선택 창 머리가 보여 준다 — tui-2b §3.1).
- 값 칸(입력줄)의 줄바꿈 — 가로 창 그대로.
- §B52 (2)의 나머지(비밀 짐작·GUI 선재 갭·서버 제어 문자 거절·`fit_head` 1칸·높이 6줄 이하) — 그대로 연기.

## 2. 동작 규칙 (정본)

### 2.1 숫자 글자 (US1 — tui-2b §2.4의 "숫자 글자" 불릿을 대체)

본문 값 줄의 숫자 글자(`PickValue::Number` — 값 목록의 `받은 값` 열, 선택 창 머리, 조건 칸 `받은 값` 줄, 조건의 비교값에 **같은 글자**가 쓰인다):

1. 정수 꼴 글자(`serde_json`이 `u64`·`i64`로 읽는 것)는 본문 글자의 값 그대로 십진 표기 — 지금과 같다.
2. 그 밖의 수(`f64`로 읽는 것)는 **JavaScript `String(number)`와 같은 글자**:
   - 값이 0이면(`-0.0` 포함) `0`.
   - 십진 지수 `e`(값 = `d.ddd… × 10^e`, 가장 짧은 왕복 자릿수)가 **−6 ≤ e ≤ 20**이면 지수 없는 십진 표기(지금과 같다 — `0.000001`·`100.25`·`100000000000000000000`).
   - 아니면 지수 표기: `{가수}e{부호}{지수}` — 가수는 가장 짧은 왕복 자릿수(소수점 뒤가 없으면 정수만), 지수가 0 이상이면 `+`를 붙인다(`1e+300`·`1.7976931348623157e+308`·`1e+21`), 음수면 `-`(`1e-7`·`1.5e-300`·`5e-324`).
3. 기준 벡터(§11 ①로 만든 GUI 쪽 글자 — 테스트가 이 표를 그대로 쓴다):

| 본문 글자 | 숫자 글자 | | 본문 글자 | 숫자 글자 |
|---|---|---|---|---|
| `1e300` | `1e+300` | | `1e-6` | `0.000001` |
| `1.5e-300` | `1.5e-300` | | `1e-7` | `1e-7` |
| `5e-324` | `5e-324` | | `0.00000123` | `0.00000123` |
| `1.7976931348623157e308` | `1.7976931348623157e+308` | | `1.5e-7` | `1.5e-7` |
| `1e21` | `1e+21` | | `-1e300` | `-1e+300` |
| `1e20` | `100000000000000000000` | | `-2.5e-10` | `-2.5e-10` |
| `123456789012345680000` | `123456789012345680000` | | `-0.0` | `0` |
| `1.0` | `1` | | `0.0` | `0` |
| `1.5` | `1.5` | | `100.25` | `100.25` |
| `1e5` | `100000` | | `3.0e2` | `300` |
| `0.1` | `0.1` | | `12345678901234567890`(정수 꼴 — 1번) | `12345678901234567890` |

4. 결과: 숫자 글자는 26자를 넘지 않는다(§6 테스트가 `f64` 극값으로 단언). 서버 한도 200자·GUI 기준 40자에 걸리지 않는다.
5. 판정은 달라지지 않는다 — 서버는 실제 값이 숫자이고 비교값이 `parse_finite`로 읽히면 f64끼리 비교한다(`crates/controller/src/monitor/check.rs` `op_passes`). `"1e+300".parse::<f64>()`는 `Ok(1e300)`(§11 ②).

### 2.2 조건 칸의 `대상` 줄 (US2 — tui-2b §3.2·2a 조건 수정 칸)

조건 칸은 두 화면에 뜬다 — 값 목록(새 조건)과 하위 목록 11번(기존 조건). 두 화면에 같은 규칙:

1. `대상` 글자(`sanitize` 뒤)를 값 칸 폭 `fw`(= 조건 칸 폭 − 라벨 칸 9)로 **표시 폭 기준 줄바꿈**한다(`view::wrap_width` — 도움말 경로 줄과 같은 함수). 둘째 줄부터는 라벨 칸이 빈칸이다.
2. 줄 수 우선순위는 지금 규칙 뒤에 붙는다: **필수 줄(대상 첫 줄·규칙·값·체크·오류) → `받은 값` → 안내 → 대상의 이어지는 줄**. 대상이 한 줄에 들어가면 화면은 지금과 글자까지 같다.
3. 이어지는 줄은 **위 목록에 3줄(제목·표 머리·고른 줄)이 남는 한도까지만** 늘린다 — 조건 칸 높이 `h = min(본문 높이, 지금 높이 + min(이어지는 줄 수, 본문 높이 − 3 − 지금 높이))`(뺄셈은 0에서 멈춘다). "지금 높이"는 필수 줄 + `받은 값`·안내 줄 중 있는 것(현행 `cond_form_lines`).
4. 줄이 모자라 다 못 보이면 **보이는 마지막 대상 줄의 끝을 `…`로** 맺는다(그 줄을 폭 `fw`에 맞춰 `fit`). 이어지는 줄이 0줄이면 지금처럼 한 줄 `fit`.
5. 조건 칸 안의 줄 순서: 대상(1줄 이상) · `받은 값` · 규칙 · 값 · 체크 · 오류 · 안내 — 대상 줄이 늘어도 순서는 그대로.

### 2.3 칸·상태를 못 찾은 하위 화면 (US3)

1. 하위 화면(`Screen::Errors`·`Record`·`Body`·`Settings`·`EditList`·`EnvVars`·`ScenarioVars`·`Values`)을 그리는 함수가 **아무것도 그리지 못하고 돌아오는 모든 경우**(그 칸이 보드에 없음·화면 상태 없음·하위 목록 종류를 못 정함)에 대체 화면을 그린다. 세션이 없거나 머리 줄을 만들 수 없는 경우(`running`·`monitor_screen()`이 `None`)는 대상이 아니다 — 하위 화면이 뜰 수 없는 상태다.
2. 대체 화면 = 다른 하위 화면과 같은 틀(맨 위 줄 + 본문 + 키 줄). 본문 첫 줄에 `이 칸을 찾을 수 없습니다 — Esc로 돌아가세요`(흐리게, 폭이 좁으면 `wrap_width` 줄바꿈). 키 줄은 `Esc 뒤로` · `q 종료`(종료 확인창이 떠 있으면 다른 하위 화면과 같은 확인 키 2개).
3. 키 동작은 바꾸지 않는다 — `Esc`·`q`는 지금도 칸 유무와 무관하게 듣는다.
4. 정상 경로(칸이 있다)의 화면은 글자까지 같다.

## 3. TUI 구조

- **`pick.rs`**: `fn number_text(v: f64) -> String`(순수) — `format!("{v:e}")`를 `e`에서 갈라 지수를 정수로 읽고 §2.1의 갈래로. `visit_f64`가 이것을 쓴다. `PickValue::Number` 주석을 "정수는 그대로, 그 밖은 `String(number)`와 같은 글자"로.
- **`view/edit.rs`**: 순수 함수 `cond_form_height(v, body_w, body_h) -> u16`(§2.2-3)이 `cond_form_lines`를 대체한다(호출 2곳 — `render_list_with_form`·`view/values.rs` `render_values`). `render_cond_form`은 받은 `area.height`에서 `받은 값`·안내 줄 표시 여부(현행 `extras_shown`)를 정한 뒤 **남는 줄 수만큼** 대상의 이어지는 줄을 그린다 — 높이를 정한 쪽과 그리는 쪽이 같은 줄 수 계산(순수 함수 하나)을 쓴다.
- **`view/inspect.rs`**: `render_missing(f, head, keys)` — 틀(`render_frame`) + 안내 줄.
- **`app.rs`**: `draw_sub`의 화면별 갈래(`draw_edit`·`draw_values` 포함)가 "그렸는가"를 `bool`로 돌려주고, `false`면 `draw_sub`가 `render_missing`을 부른다. 키 줄 조각은 순수 함수(`missing_keys(quit_confirm)`)로.
- **`text.rs`**: `SUB_MISSING` 한 줄.

## 4. 영향 범위

- 저장되는 조건의 `value` 글자가 지수 범위 수에서 달라진다(301자 → `1e+300`). 그 범위의 수는 지금 저장이 거절되므로(200자 초과 — `1e200` 이상·`1e-198` 이하) 이미 저장된 조건과 어긋날 것이 없고, 그 사이 범위(`1e21`~`1e199`, `1e-7`~`1e-197`)는 옛 글자(긴 십진)로 저장된 조건이 있어도 판정이 같다(§2.1-5).
- 보드 파일 형식·와이어 0-diff.

## 8. 보안 표면

- 새 입력 경로·새 저장 값 없음. 숫자 글자는 `f64`에서 만든 ASCII(숫자·`.`·`e`·`+`·`-`)뿐이다.
- 대상 줄은 지금처럼 `sanitize` 뒤에 폭을 잰다(`crates/tui/CLAUDE.md` — 원격 문자열은 폭 계산 전에). 줄바꿈이 `sanitize`를 건너뛰지 않는 것을 테스트 ⑤ 옆에서 `\u{FFFD}` 긍정 단언으로 확인한다(경로에 bidi 제어 문자를 넣은 조건).
- `finish-slice` §0 grep과 "값을 새 sink로 옮기는가"(working-rules §3)는 구현 뒤 다시 본다 — 예상: 옮기지 않는다.

## 9. 알려진 한계 / 연기

- **숫자 글자가 세 가지다** — TUI·GUI는 이 슬라이스로 지수 범위까지 같아지지만, 서버가 사유·화면 표시 값에 쓰는 글자는 엔진 `extract::stringify`(`serde_json` 표기: `1e300`·`1.0`)다. 시나리오 추출과 같이 쓰는 함수라 건드리지 않는다. 판정에는 영향 없음(숫자 비교). 해소 방향: 모니터 판정 쪽만 쓰는 숫자 표기 함수를 따로 두기(컨트롤러 변경).
- 2^53을 넘는 정수 글자는 GUI와 다르다(§1 비목표).
- 500자 경로는 40열 이하 화면에서 끝까지 보이지 않는다(`…`) — 화면에 줄이 없다. 전체는 값 목록의 선택 창 머리(새 조건)에서 본다. 11번(기존 조건)에는 그 길이 없다.
- `draw_sub` → `render_missing` 연결은 단위 테스트·라이브 어느 쪽으로도 확인하지 못한다(§2.3-1의 경우를 만들 길이 없다). 틀리면 지금과 같은 빈 화면이 남는다.
- cloud 세션 제약: `cargo-nextest` 없음(`cargo test --workspace`로 대신) · GUI 클릭 경로 대조 불가 — 맥에서 확인할 것으로 §B 블록 머리에 남긴다.

## 10. 판단 기록 (설계자 몫)

- **숫자 글자를 GUI에 맞춘다**(Rust `{:e}`의 `1e300`이 아니라 `1e+300`): 상위 규칙이 "GUI와 같은 설정"이고(tui-2b US1), 같은 값을 GUI와 TUI에서 추가한 보드 파일이 글자까지 같아진다. 대안(Rust 표기 그대로)은 한 줄 짧지만 세 번째 표기를 만든다.
- **대상 줄바꿈의 우선순위를 맨 뒤에 둔다**: 낮은 화면에서 지금 보이는 것(받은 값·안내)이 사라지지 않게 — 변경 전 화면이 변경 후의 부분집합이 된다.
- **대체 화면을 "그리지 못한 모든 경우"에 한 곳에서**: 갈래마다 문구를 넣으면 새 갈래가 빠진다(US3 선택 때 사용자에게 제시한 "모든 하위 화면에").
