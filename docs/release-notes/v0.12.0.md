## 하이라이트

### 운영 모니터 — 점검 묶음 (스텝별 칸)

로그인이 필요한 흐름을 **계정 하나로, 로그인 한 번으로** 스텝마다 나눠 감시할 수 있게 됐습니다. 설정 화면에서 **+ 점검 묶음 추가**를 누르고 시나리오를 고른 뒤, 칸마다 **볼 스텝**을 고르면 됩니다.

- **한 번 실행, 여러 칸 판정**: 묶음은 주기마다 시나리오를 한 번만 실행하고, 각 칸이 자기 스텝의 응답 속도와 성공 조건으로 따로 판정합니다. 칸이 5개여도 로그인 요청은 주기당 한 번입니다.
- **앞 단계가 실패하면 "확인 못 함"**: 흐름 중간(예: 2.0 로그인)이 실패하면 그 칸만 빨강으로 사유를 보이고, 뒤 칸들은 회색 **"― 확인 못 함 · 앞 단계 실패 · 2.0 로그인에서 멈춤"**으로 표시됩니다. 깜빡이지 않고 연속 실패로 세지도 않습니다. 실패한 스텝에 칸이 없으면 그 뒤 첫 칸이 빨강으로 원인을 대신 보여 줍니다.
- **안 탄 분기는 "분기 제외"**: 응답 값에 따라 갈리는 분기(경마일/비경마일 등)에서 이번에 타지 않은 쪽 칸은 빨강이 아니라 **"○ 분기 제외"**와 함께 실제 값(`isRaceDay = false`), 기대 조건, 분기 이름을 보여 줍니다. 쿠키·인증 헤더에서 꺼낸 값은 화면에 그대로 내보이지 않고 `(인증 값)`으로 가립니다.
- **칸마다 제한 시간**: 칸별로 "이 API는 N초"를 정하면 그 스텝이 N초를 넘을 때 그 칸만 `시간 초과(N초)`가 되고 뒤 칸은 "확인 못 함"이 됩니다.
- **막대를 누르면 그 스텝이 펼쳐진 기록 창**: 묶음 칸의 막대를 누르면 그 회차 기록이 이 칸이 보는 스텝을 펼친 채 열립니다.
- 기존 보드(묶음 없음)는 그대로 동작합니다. 묶음 밖의 칸은 **단독 실행**으로 표시됩니다.

### 운영 모니터 — 보드 내보내기/가져오기

보드와 그 보드가 쓰는 시나리오·환경을 **파일 하나로 내보내** 다른 PC로 옮길 수 있습니다. 모니터 목록에서 보드를 골라 **선택한 보드 내보내기**, 또는 설정 화면의 **파일로 내보내기**를 씁니다. 가져올 때 이미 있는 보드·시나리오와 겹치지 않으면 원래 ID 그대로 꺼진 상태로 추가하고, 겹치면 아무것도 넣지 않고 겹친 항목을 보여 줍니다. 파일에는 환경 값과 시나리오에 적은 비밀번호·토큰이 그대로 담기므로 보관에 주의하세요.

### 운영 모니터 — 개선

- **성공 조건 규칙 추가**: `≥`·`≤`·`∈`(여러 값 중 하나)를 쓸 수 있고, 화면의 실패 사유도 `=`·`≥`·`∈` 같은 기호로 짧게 표시합니다. 문자열 안에 JSON을 감싸 보내는 응답도 풀어서 판정합니다.
- **화면에 표시할 값**: 판정과 상관없이 응답의 값을 칸에 최대 2개까지 띄울 수 있습니다(미리 실행 결과에서 값을 눌러 추가).
- **평균·최대 줄**: 최근 응답 시간의 평균·최대를 칸에 표시하고, 전시 화면 버튼으로 켜고 끕니다. 막대는 오른쪽(최신)부터 채워집니다.
- **점검 기록 창**: 전시 화면의 막대를 누르면 그 회차에 실제로 보낸 요청과 받은 응답을 볼 수 있습니다. 인증 값은 서버에서 가리고, 요청 본문은 기본으로 가려져 있습니다. 보드마다 기록 본문 상한(16~1024KB)을 정합니다.
- **설정 화면 정리**: 칸을 접고 펼 수 있고, 접힌 칸은 한 줄 요약으로 보입니다. 오른쪽에 칸 목록이 고정되고, 저장 오류가 난 칸은 자동으로 펼쳐집니다.
- 전시 화면에서 점검을 정지한 뒤 **점검 시작**으로 바로 다시 켤 수 있습니다.

### 시나리오 편집기

- 조건 칸에 `{{ }}` 없이 변수 이름만 쓰면 안내와 함께 **수정** 버튼을 보여 줍니다.
- 스텝 목록에서 긴 조건 요약이 칸 밖으로 넘치던 문제를 고쳤습니다.

### 고친 문제

- 성공 조건 **"값 있음"**이 응답 값이 빈 목록 `[]`이나 빈 객체 `{}`일 때도 통과하던 문제를 고쳤습니다. 이제 "비어 있음" 실패로 판정합니다. 이 조건을 쓰던 기존 칸도 같은 규칙이 적용됩니다.
- 모니터 미리 실행에서 긴 응답 본문의 머리 줄이 두 번 나오던 문제를 고쳤습니다.

|---|---|---|
| Windows (설치) | `Handicap_0.12.0_x64-setup.exe` | 권장. 컨트롤러·워커·UI·DB 내장 |
| Windows (설치, MSI) | `Handicap_0.12.0_x64_en-US.msi` | 사내 배포 도구·그룹 정책으로 일괄 설치할 때 |

| Ubuntu 22.04+ (설치) | `Handicap_0.12.0_amd64.deb` | App Center에서 설치하거나 `apt install` 사용 |
| Ubuntu 22.04+ (설치 없이) | `Handicap_0.12.0_amd64.AppImage` | 실행 권한 필요, FUSE 런타임 필요 |

Linux 서버·폐쇄망·LAN 분산 워커·Kubernetes 설치는 [README](https://github.com/SeonggukJeong/handicap)의 **"시작하기 — 환경별 설치 절차"** 절을 참고하세요.

## 참고

- 코드 서명이 **없는** 배포라 Windows SmartScreen이 경고를 띄웁니다. **"추가 정보" → "실행"** 으로 진행합니다. macOS는 Gatekeeper가 차단할 수 있습니다 — 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)로 실행합니다.
- 이번 릴리즈에는 DB 마이그레이션이 없습니다. 기존 시나리오·run·모니터 보드는 그대로 동작합니다.
- 업그레이드 전에 열어 둔 모니터 전시 화면 탭은 한 번 새로고침하세요(새 판정 상태 표시를 위해).
- 모니터 점검은 컨트롤러 안에서 실행되므로 워커 업그레이드와는 무관하지만, LAN 분산 워커·Kubernetes를 쓰는 경우 컨트롤러와 워커를 함께 0.12.0으로 올리는 것을 권장합니다.
- 변경 내역 전체: [`v0.11.0...v0.12.0`](https://github.com/SeonggukJeong/handicap/compare/v0.11.0...v0.12.0), 기능별 상세는 [`docs/build-log.md`](https://github.com/SeonggukJeong/handicap/blob/master/docs/build-log.md).
