## 하이라이트

### 운영 모니터 모드 (새 기능)

운영실 벽 화면에 띄워 두는 **점검 보드**를 추가했습니다. 로그인·조회 같은 핵심 흐름을 셸 스크립트로 주기 점검하던 일을 Handicap 시나리오로 대신합니다. 왼쪽 메뉴의 **모니터**에서 보드를 만듭니다.

- **칸마다 시나리오 하나**: 칸에 시나리오·환경·점검 주기·제한 시간(최대 30초)을 정하면, 주기마다 시나리오를 한 번씩 실행해 결과를 칸에 표시합니다. 부하 테스트가 아니라 한 번 실행(미리 실행과 같은 방식)이라 대상 서버에 부담이 거의 없습니다.
- **멀리서도 읽히는 전시 화면**: **모니터 시작**을 누르면 전체화면으로 바뀝니다. 정상/느림/실패/확인 불가를 색과 큰 글자로 보여 주고, 최근 응답 시간 막대와 기준선(느림 기준)을 함께 그립니다. 실패한 칸은 깜빡입니다. F·ESC·마우스 버튼으로 전체화면을 해제해도 점검은 계속됩니다.
- **화면 방식 3가지**: 테두리(기본), 칸 전체를 상태 색으로 칠하는 **신호등**, 실패한 칸만 크게 띄우고 나머지는 작은 카드로 모으는 **실패만 크게** 중에서 고릅니다. 켜진 화면에도 1~2초 안에 반영됩니다.
- **클릭으로 성공 조건 만들기**: 설정 화면의 미리 실행 결과에서 JSON 값·헤더·상태코드·본문을 누르면 "이 값이 0000과 같으면 성공" 같은 조건이 바로 만들어집니다. 시나리오는 바꾸지 않고 모니터 칸 설정에만 저장되며, 칸마다 최대 10개까지 둘 수 있습니다. 조건이 실패하면 벽 화면에 실제 값과 어떤 규칙이 어긋났는지가 표시됩니다.
- **서버가 꺼졌다 켜져도 이어서**: 켜 둔 보드는 컨트롤러(데스크톱 앱 포함)가 다시 시작될 때 자동으로 점검을 재개합니다. 화면이 서버 응답을 받지 못하면 "서버 응답 없음"과 마지막 점검 시각을 표시합니다.
- **벽 화면에는 안전한 문구만**: 벽 화면의 실패 사유는 정해진 문구와 작성자가 붙인 스텝 이름(그리고 성공 조건이 비교한 값)만 보여 줍니다. 요청 URL·응답 원문은 설정 화면의 미리 실행에서만 볼 수 있습니다.

### 그 밖의 변경
- macOS Intel(x64) 빌드는 이번 릴리즈부터 제공하지 않습니다. Apple Silicon용 dmg만 첨부됩니다.

## 다운로드

| 환경 | 파일 | 비고 |
|---|---|---|
| Windows (설치) | `Handicap_0.11.0_x64-setup.exe` | 권장. 컨트롤러·워커·UI·DB 내장 |
| Windows (설치, MSI) | `Handicap_0.11.0_x64_en-US.msi` | 사내 배포 도구·그룹 정책으로 일괄 설치할 때 |
| Windows (포터블) | `Handicap_0.11.0_x64-portable.exe` | 설치 없이 exe 한 파일 |
| macOS (Apple Silicon) | `Handicap_0.11.0_aarch64.dmg` | 서명·공증 없음 — 우클릭 → 열기로 실행 |
| Ubuntu 22.04+ (설치) | `Handicap_0.11.0_amd64.deb` | App Center에서 설치하거나 `apt install` 사용 |
| Ubuntu 22.04+ (설치 없이) | `Handicap_0.11.0_amd64.AppImage` | 실행 권한 필요, FUSE 런타임 필요 |

Linux 서버·폐쇄망·LAN 분산 워커·Kubernetes 설치는 [README](https://github.com/SeonggukJeong/handicap)의 **"시작하기 — 환경별 설치 절차"** 절을 참고하세요.

## 참고

- 코드 서명이 **없는** 배포라 Windows SmartScreen이 경고를 띄웁니다. **"추가 정보" → "실행"** 으로 진행합니다. macOS는 Gatekeeper가 차단할 수 있습니다 — 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)로 실행합니다.
- DB 마이그레이션이 하나 추가됩니다(`monitor_boards` 테이블). 처음 실행할 때 자동으로 적용되며, 기존 시나리오·run은 그대로 동작합니다.
- 모니터 점검은 컨트롤러 안에서 실행되므로 워커 업그레이드와는 무관하지만, LAN 분산 워커·Kubernetes를 쓰는 경우 컨트롤러와 워커를 함께 0.11.0으로 올리는 것을 권장합니다.
- 전시 화면의 전체화면 동작은 Chromium 브라우저에서 확인했습니다. 데스크톱 앱(Windows·macOS·Ubuntu) 창 안의 전체화면은 아직 실기기 확인 전입니다.
- 변경 내역 전체: [`v0.10.1...v0.11.0`](https://github.com/SeonggukJeong/handicap/compare/v0.10.1...v0.11.0), 기능별 상세는 [`docs/build-log.md`](https://github.com/SeonggukJeong/handicap/blob/master/docs/build-log.md).
