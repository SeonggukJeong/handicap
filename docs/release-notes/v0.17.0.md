## 올리기 전에 꼭 읽어 주세요

- **컨트롤러와 부하기(워커·LAN 부하기·데스크톱 부하기)를 같은 판으로 함께 올리세요.** 옛 부하기는 준비 스텝(`setup`)이 든 시나리오를 거절해 run이 바로 실패하고, 상태 코드 목록·`any` 표기를 읽지 못하며, 옛 규칙으로 돌면서 리포트에는 새 규칙 run으로 적힙니다.
- **상태 코드 검사를 적지 않은 스텝은 이제 400 이상(4xx·5xx) 응답을 오류로 셉니다.** 끝난 run의 숫자는 그대로이고, 예약·프리셋 실행은 다음 실행부터 바뀝니다. 자세한 것은 아래 「상태 코드 기본 규칙」.
- **리포트의 응답 시간은 이제 통과한 요청만으로 계산합니다.** 이전 run은 숫자가 그대로이고 「모든 요청 (실패한 요청 포함)」 표시가 붙습니다.
- **새로 만든 run은 응답 시간 기준을 µs까지 정확히 비교합니다.** 예전에는 43.9 ms가 「≤ 43 ms」를 통과했지만 이제 실패합니다. 이전 run의 판정은 그대로입니다.
- **CSV·XLSX 내보내기의 열이 바뀌었습니다.** 응답 시간 칸이 정수 ms에서 ms 소수 3자리로 바뀌고 열이 늘었습니다. 옛 파일을 읽던 스크립트는 고쳐야 합니다.
- 옛 판 handicap은 상태 코드 목록·`any`가 든 시나리오·보드 파일을 읽지 못합니다.

## 하이라이트

### 준비 스텝 — 로그인처럼 사용자마다 한 번만

시나리오에 **준비 스텝**을 둘 수 있습니다. 로그인처럼 VU마다 한 번만 실행하고, 리포트 요약·판정에서는 빠집니다.

- **에디터**: 준비 스텝을 바로 추가하고, 끌어서 순서를 바꾸거나 본 스텝과 서로 옮길 수 있습니다(Inspector의 「준비 스텝으로 옮기기」도 있습니다). 스텝을 목록 맨 위로 끌면 「놓으면 준비 스텝이 됩니다」가 보입니다. 새 시나리오의 「로그인 흐름」 예시는 로그인을 준비 스텝으로 둡니다.
- **미리 실행·사이징**: 미리 실행 결과와 흐름 칩이 준비 스텝을 따로 표시하고, 사이징 도우미는 준비 스텝을 뺀 반복을 잽니다. test-run·운영 모니터는 변수가 비어 있는 준비 요청을 보내지 않습니다.
- **실행**: 실행 창과 스케줄 폼이 준비 스텝이 한꺼번에 나가는 경우·데이터 행이 모자란 경우를 미리 알립니다. 실행 중에는 준비를 마친 사용자 수가 run 화면에 보입니다(open-loop은 완료한 슬롯 수).
- **결과**: 준비 스텝 결과가 리포트, 인쇄 보고서 본문, CSV·XLSX 내보내기, run 비교에 들어갑니다. 준비 스텝이 실패해 요청이 0건인 run의 리포트는 원인을 준비 실패로 알립니다.
- 본 스텝이 없는 시나리오는 준비 스텝만 실행하고 끝납니다(그전에는 실행 시간이 끝날 때까지 돌았습니다).

### 응답 시간을 통과한 요청 기준으로

- 리포트의 응답 시간(p50·p95·p99·평균)을 **통과한 요청만으로** 계산합니다. 실패가 빨리 끝나 응답 시간이 좋아 보이던 문제가 없어집니다.
- 리포트에서 표본을 단추로 바꿔 볼 수 있습니다 — 통과한 요청(기본)·실패한 요청·모든 요청. 판정과 인사이트는 바뀌지 않고 응답 시간 숫자만 바뀝니다.
- 요청이 전부 실패하면 응답 시간 판정 기준은 「통과한 요청 없음」으로 실패합니다(전에는 0ms로 통과). 요청이 하나도 없이 끝난 새 run은 응답 시간 기준을 판정하지 않습니다.
- 계단 내보내기는 표본 없는 계단의 응답 시간을 빈 칸으로 씁니다.

### 상태 코드 기본 규칙 — 검사가 없으면 400 이상은 오류

- 상태 코드 검사를 적지 않은 스텝은 400 이상 응답을 오류로 셉니다. 에디터에서 새로 만든 스텝은 검사 없이 시작합니다(201·204·302는 통과).
- 「응답 검증」에서 **「적은 코드만 통과」**로 기대 코드를 여러 개 적거나(`status: [200, 401]`), **「보지 않음」**(`status: any`)을 고를 수 있습니다. 옛 에디터가 코드마다 줄을 하나씩 만든 스텝은 알림과 함께 한 줄로 합칠 수 있습니다.
- 검사 없는 스텝이 4xx·5xx를 받으면 값 추출을 건너뜁니다. 그 값을 쓰는 다음 스텝이 있으면 VU가 멈출 수 있으니 기대 코드를 적거나, 추출 기본값을 두거나, 「보지 않음」을 고르세요.
- 검사 없는 준비 스텝의 4xx·5xx는 준비 실패가 됩니다. 「준비될 때까지 404」를 기다리는 조건 반복은 그 스텝에 `status: [200, 404]`를 적으세요.
- 운영 모니터: 검사 없는 점검 스텝이 4xx·5xx를 받으면 칸이 실패로 바뀝니다.
- 신뢰도 「미리 실행 확인됨」 표시가 모든 시나리오에서 한 번 풀립니다. 미리 실행에서 검사로 통과한 4xx·5xx는 더 이상 실패(✗)로 보이지 않습니다.

### 판정 기준 — 평균·최대·임의 백분위, µs까지 정확히

- 실행 창·스케줄 폼에서 **평균·최대 응답 시간과 p90·p99.9 같은 다른 백분위**(10개까지)를 판정 기준으로 걸 수 있고, 스텝 기준에도 평균·최대·백분위가 생겼습니다. 잘못된 기준 값은 실행·저장 전에 막고 이유를 보여 줍니다.
- 새 run은 응답 시간 기준을 µs까지 정확히 비교합니다(응답 속도 구간 건수도 같은 경계). 판정 표의 실측은 소수 셋째 자리까지·천 단위 쉼표로 보입니다.
- 60초를 넘긴 응답은 60초로 기록되므로, 그 영향을 받은 실측에는 「≥」가 붙고 상한 기준은 실패로 판정합니다.
- 인쇄 보고서 판정과 비교 화면·인쇄 비교도 새 항목과 응답 시간 판정 규칙 차이를 알려 줍니다.

### 응답 시간 통계와 그래프

- 리포트 요약에 **평균 응답 시간 카드**가 생기고, 스텝 표의 **「응답 시간 통계 더 보기」**로 최소·평균·최대·표준편차·p90과 모든 스텝 합계를 볼 수 있습니다. 1ms 미만 응답 시간은 「350 µs」처럼, 60초를 넘긴 응답은 「≥ 60,000」으로 보입니다.
- 리포트의 「p95 응답 시간」 그래프가 **「응답 시간」 그래프**로 바뀌어 초마다 모든 스텝을 합친 평균과 정확한 p95를 함께 그립니다. p95가 같은 초의 모든 요청을 합친 값이 되어 전보다 낮게 나올 수 있습니다(전에는 스텝들 중 가장 큰 값). 그 아래 「스텝별로 보기」를 펼치면 스텝마다 작은 평균 그래프를 같은 눈금으로 볼 수 있습니다.
- **CSV·XLSX 내보내기**: 응답 시간 칸이 ms 소수 3자리로 바뀌고 최소·평균·p90·최대·표준편차와 `capped`(60초를 넘긴 응답이 있음) 칸이 생겼습니다. XLSX Summary·Other basis 시트의 행이 늘어 유효성 행이 아래로 밀립니다.
- **비교 화면**: 평균·최소·최대·표준편차·p90 행과 스텝별 「응답 시간 통계 더 보기」가 생기고, 값이 ms 소수 3자리로 보입니다. **변화율 화살표가 값의 방향(▲ 늘어남·▼ 줄어듦)을 뜻하게 바뀌었습니다 — 좋고 나쁨은 색입니다**(전에는 ▲가 「나빠짐」이라 처리량이 줄면 ▲로 보였습니다). 비교 XLSX의 Δ 칸도 같은 규칙입니다. 60초를 넘긴 응답이 낀 비교는 변화율 대신 「—」로 보입니다. 비교 CSV·XLSX에 스텝별 통계가 들어갑니다.
- 60초 칸에 든 최소 응답 시간이 59,998이 아니라 「≥ 60,000」으로 보입니다.

### 유지 구간 기준 리포트

- 고정 부하에 **상승 시간·앞부분 버림**을 둘 수 있습니다(도착률 고정에도 상승 시간). 리포트와 SLO 판정을 유지 구간 기준으로 보고, 전체 구간 기준으로 바꿔 볼 수 있습니다.
- 리포트 시계열에 상승·버림 띠와 유지 구간 점선이 보입니다. 비교 화면·비교 보고서·인쇄·내보내기에 집계 기준이 표시되고, 인쇄와 내려받기는 화면에서 보던 기준을 따릅니다. XLSX에는 두 기준이 함께 들어갑니다.
- 화면 낱말: run 길이는 「실행 시간」, 상승은 「상승 시간」, 리포트 집계 구간 길이는 「측정 시간」입니다.

### 인쇄 보고서

- **이전·이후 비교 보고서**를 비교 화면에서 A4로 인쇄할 수 있습니다(표준판·요약판 1장) — 나아졌는지의 답, 핵심 지표 변화, 조건이 같은지 점검, 남은 문제. 표준판에는 단계별 응답 시간 변화 그림(95%·평균), 90%·최대 응답 시간, 단계별 오류 변화 표, 시간에 따른 변화 겹쳐 보기, 응답 속도 구간 비교가 들어갑니다.
- 인쇄 보고서에 **단계별 응답 속도 구간 표**, **「단계별 응답 시간 통계」 절**(뒤 절 번호가 하나씩 밀립니다), 응답 시간 그래프, 맨 뒤 「단계별 평균 응답 시간」 부록이 생겼습니다.
- 판정에 쓰인 측정값·기준값을 반올림 없이 표시합니다. 「응답시간」이 「응답 시간」으로 바뀌고, 60초를 넘긴 값은 「60초 이상」으로 찍힙니다.
- 단계의 「느림」 표지가 평균·최대·백분위 기준도 봅니다. 통계가 없는 옛 리포트에서는 전에 보이던 「느림」이 사라질 수 있습니다.
- 표가 쪽 경계에서 한 행만 남기고 나뉘지 않습니다. 요청을 전부 보내지 않은 단계의 95% 응답은 「–」로 표시합니다.

### 시나리오 그룹

시나리오를 그룹으로 묶어 볼 수 있습니다. 목록에서 여러 개를 체크해 한 번에 그룹을 정하고, 그룹 이름도 한 번에 바꿉니다. 목록에 검색 칸이 생겼고, 스케줄·모니터의 시나리오 선택 칸도 그룹별로 묶입니다. 보드 파일로 옮긴 시나리오는 그룹 없이 들어옵니다.

## 수정

- **오래 돌린 run의 리포트 메모리**: 1시간쯤 돌린 run이 끝나거나 그 리포트를 열 때 컨트롤러가 메모리를 수 GB씩 쓰다 멈출 수 있던 문제를 고쳤습니다. 리포트 숫자는 그대로입니다.
- **만들자마자 중단한 run**: 부하가 나가지 않습니다(전에는 설정한 시간만큼 끝까지 나갔습니다). 시작 전에 중단한 run에 중단 사유가 표시되고, 시작하지 못한 run의 리포트 기간·초당 요청 수가 0으로 나옵니다. 중단 버튼이 이미 끝난 run의 상태를 바꾸지 않습니다. run을 만드는 도중에 중단하면 생성 요청·스케줄 기록이 실패가 아니라 중단된 run으로 남습니다.
- **상승이 긴 VU 고정 run**이 상승 중에도 메트릭을 보냅니다(상승이 시작 감시 대기보다 길면 「부하 없음」으로 실패할 수 있었습니다).
- **도착률 단위**를 iter/s(초당 시나리오 반복)로 표기합니다 — 계단 시험의 목표·판정 문구가 req/s로 적혀 있던 것을 바로잡았습니다(값·동작은 그대로).
- **헤더 값이 `?`나 `:`로 시작하면**(`sec-ch-ua-mobile: ?0` 등) 새 시나리오의 미리 실행·저장이 파싱 오류로 실패하던 문제를 고쳤습니다. `0b101`·`+0x1F` 같은 글자를 헤더 값·변수·템플릿 삽입 값으로 넣으면 서버가 숫자로 읽던 문제도 고쳤습니다.
- **템플릿 삽입**에서 숫자·true/false로 보내는 변수(`{{n:num}}` 등)를 값으로 바꾸면 문자열로 들어가던 문제를 고쳤습니다 — 타입에 맞는 값만 받고, 이름을 바꿔도 `:num` 등이 유지됩니다.
- 긴 시나리오 이름이 에디터 머리 줄·실행 기록 제목·경로 표시에서 말줄임으로 보이고, 이름 입력칸이 넓어졌습니다.
- 단추 묶음에서 화살표 키로 고르면 초점도 함께 옮겨 갑니다(실행 창 포함).

## 알려진 제한

- 비교 XLSX에는 색이 없어 Δ 칸의 화살표만으로는 좋아짐/나빠짐을 알 수 없습니다(화살표는 값의 방향입니다).
- run 비교의 준비 스텝 행은 60초를 넘긴 값을 그대로(예: 60030) 쓰고 그 값으로 변화율을 냅니다.
- 비교 인쇄의 99%·95%·평균 행은 정수 ms로, 화면은 µs로 계산해 변화가 5% 근처일 때 인쇄는 「비슷」, 화면은 변화율로 보일 수 있습니다.
- 좁은 화면(390px)에서 비교 화면이 가로로 스크롤됩니다.
- 스텝 id가 32,767자를 넘으면 비교 XLSX 내보내기가 실패합니다.
- 인쇄 통계 표의 「–」(통과한 요청이 없음) 뜻은 「단계별 결과」 범례에서 찾아야 합니다.
