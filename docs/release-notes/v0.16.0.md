## 하이라이트

### 계단 시험 — 어느 부하에서 포화되는지 한 번에 찾기

도착률 실행에 **「계단」** 탭이 생겼습니다. 목표 부하를 단계별로 올리면서 시스템이 어느 목표에서 무너지는지 찾습니다.

- **계단 만들기**: 목표 목록을 직접 적거나(예: `100, 200, 400`), 도우미에 시작·끝·배수를 넣어 「목록 만들기」로 만듭니다. 계단마다 올리는 시간·유지 시간·버리는 앞부분을 정하고, 실행 전에 「8계단 · 총 4분 24초」처럼 요약을 보여 줍니다. 프리셋·스케줄·다시 실행에서도 같은 설정을 씁니다.
- **계단 결과 표와 판정**: 리포트가 계단마다 달성(끝난 반복 수 기준)·지연·오류·버림을 표로 보여 주고, **어느 목표에서 포화됐는지**와 마지막 정상 계단을 판정합니다. 계단 곡선·1초 계단 띠 차트가 함께 나옵니다.
- **슬롯 부족과 시스템 포화를 구분합니다**: 부하기의 동시 실행 한도 때문에 못 보낸 경우는 시스템 포화로 세지 않고 「슬롯 부족 의심」으로 알려 줍니다.
- **내보내기**: 계단 표는 CSV(`report-stairs.csv`)·XLSX(`Stairs` 시트)·인쇄(표준·요약)로 내보낼 수 있고, 문구는 화면과 같습니다.

### 계단 자동 정지 — 무너지면 스스로 멈춤

운영에 가까운 환경을 시험할 때 무너진 시스템에 부하를 계속 주지 않도록, 계단 run이 스스로 멈춥니다.

- **포화 정지**: 연속 두 계단이 실패하면 멈춥니다(고르면 첫 실패에서 멈춤).
- **즉시 정지**: 오류율·p99가 정한 기준을 몇 초 연속 넘으면 계단이 끝나기를 기다리지 않고 멈춥니다. 초당 완료 수가 너무 적은 구간은 판단을 보류합니다.
- 언제 왜 멈췄는지가 리포트·CSV·XLSX·인쇄 맨 위에 한 줄로 남고, run 상세·목록에 자동 정지 표지가 붙습니다. 자동 정지로 끝난 run은 중단이 아니라 **완료**입니다.
- **새 계단 run은 자동 정지가 기본으로 켜져 있습니다.** 예전에 저장한 프리셋·스케줄·다시 실행은 꺼진 채 열립니다.

### 실행 중 「계단 진행」 패널

계단 실행 중 run 상세에 지금 상태가 보입니다.

- 지금 몇 계단째인지, 계단마다 정상 / 실패(다음 계단 확인 중) / 튄 계단 / 포화인지를 칩으로 보여 줍니다.
- 실패한 계단은 **이유를 같이** 보여 줍니다 — 「2 튄 계단(오류 4.6%)」·「3 포화(p99 3.9×)」. 끝난 뒤 리포트 사유와 같은 글자이고, 칩에 마우스를 올리면 계단별 이유가 나옵니다.
- 「다음 계단이 실패하면 자동으로 멈춥니다」 예고와 즉시 정지 감시의 현재값이 보이고, 멈추는 순간 이유가 맨 위에 뜹니다.

### 포화 진단 — 「서버 응답이 가끔 멈춤」 구별

도착률 run에서 버림이 생겼을 때, 대상 서버가 가끔 멈춰서 생긴 버림을 슬롯 부족과 구별합니다.

- 이전에는 「슬롯 부족 → 슬롯을 N으로 늘리세요」로 안내했습니다. 이제는 「서버 응답이 가끔 멈춤」으로 알리고, 평소 쓰인 슬롯 수와 버림이 몰린 초 수를 보여 줍니다(권장 숫자 없음).
- 그런 run 뒤에는 실행 창의 슬롯 도우미가 권장값 대신 안내를 보입니다.

### 값 추출 — 문자열로 감싼 JSON 안쪽까지

- 시나리오 값 추출과 에디터 미리 실행 본문 트리가 **문자열로 감싼 JSON**(`{"data":"{\"id\":7}"}`) 안쪽 경로(`$.data.id`)를 찾습니다. 운영 모니터에 먼저 들어갔던 기능이 시나리오에도 적용됐습니다. 원래 본문을 먼저 찾고, 없을 때만 풀어서 찾습니다.
- 감싼 JSON을 풀어 찾을 때 본문을 복사하지 않습니다. 경로를 못 찾고 본문에 감싼 JSON이 있을 때 부하기 CPU가 크게 줄었습니다(150 KB 본문에서 요청당 약 40%). 추출 결과는 그대로입니다.

### 화면 다듬기

- **응답 줄을 눌러 추출·조건 추가**: 시험 실행·모니터 기록의 응답 헤더·본문 값 줄은 마우스를 올리면 강조되고, 줄 어디를 눌러도 그 줄의 버튼과 같은 동작을 합니다. 글자를 드래그하면 선택한 글자를 바로 복사합니다(「복사됨」 표시).
- **상단 메뉴를 세 묶음으로**: 만들기(시나리오·스텝 템플릿·데이터셋·환경) │ 실행(스케줄·모니터) │ 부하기·설정. 좁은 화면에서는 「메뉴」 버튼으로 접힙니다.
- 「+ 추가」·「추출」 선택 상자가 누른 자리 바로 아래에 뜹니다.
- 좁은 화면에서 run 상세·실행 창·run 목록 표가 페이지를 옆으로 밀어내지 않습니다. run 상세 프로필 줄은 그 부하 모드가 쓰는 값만 보여 줍니다.
- 데스크톱 앱 서버 화면의 **접속 코드와 부하기 명령의 토큰을 기본으로 가립니다**(「보기」로 펼침, 복사는 그대로). 「부하기로 접속」 확인 창이 믿을 수 있는 서버의 코드만 붙여넣으라고 안내합니다.
- 인쇄 보고서와 리포트의 일부 제목을 보고서 문체로 바꿨습니다(「2. 단계별 결과」, 「결과 해석의 범위와 한계」 등).

### 그 밖에 고친 것

- http로 접속한 화면(LAN의 다른 PC)에서 본문 보기 「복사」가 복사되지 않았는데 「복사됨」을 띄우던 문제를 고쳤습니다.
- 운영 모니터 점검 화면에서 막대와 마우스 강조 영역이 어긋나던 문제를 고쳤습니다.
- API: 곡선 run(`stages`·`vu_stages`)에서 `duration_seconds`를 생략할 수 있습니다. 이전에는 안내대로 빼면 422가 났습니다.
- 24시간을 넘는 도착률 run에서 컨트롤러 로그에 거짓 시계 경고가 계속 찍히던 문제를 고쳤습니다.

## 여러 PC로 부하를 낼 때 꼭 볼 것

- **서버와 모든 부하기 PC를 함께 0.16.0으로 올리세요.** 서버는 부하기 버전을 확인하지 않습니다.
  - 계단별 달성·버림과 「서버 응답이 가끔 멈춤」 진단은 새 부하기가 보내는 초 단위 계수로 계산합니다. 옛 부하기가 섞이면 리포트가 「예전 버전 부하기라 계단별 달성·dropped를 모릅니다」로 안내하고 지연·오류로만 판정합니다.
  - 옛 부하기는 문자열로 감싼 JSON 안쪽 경로를 찾지 못해 「값 추출 실패」로 셉니다.
- 데스크톱 앱 「모드 전환」(서버로 열기·부하기로 접속)을 **Windows ↔ Windows 실기에서 확인했습니다**(같은 대역 PC 2대, 접속 코드 버튼으로 연결해 부하 실행). 그 환경에서는 방화벽 「액세스 허용」 창이 뜨지 않았는데, PC 정책에 따라 뜰 수 있으니 뜨면 허용하세요. Linux 데스크톱 실기는 아직 확인하지 못했습니다 — 동작하지 않으면 명령 방식을 쓰고 이슈로 알려 주세요.
- 부하기 한 대만 끊겨도 run 전체가 중단되는 것은 v0.15.0과 같습니다. 긴 계단 시험이라면 부하기 PC의 절전을 꺼 두세요.

## 참고

- 코드 서명이 **없는** 배포라 Windows SmartScreen이 경고를 띄웁니다. **"추가 정보" → "실행"** 으로 진행합니다. macOS는 Gatekeeper가 차단할 수 있습니다 — 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)로 실행합니다.
- **판정·동작이 바뀔 수 있는 곳**:
  - 문자열로 감싼 JSON 안쪽 값을 찾게 되면서, 전에 「값 추출 실패」이던 시나리오·운영 모니터 칸이 정상 진행으로 바뀔 수 있습니다. 기본값·조건 반복 추출은 기본값(빈 값) 대신 실제 값을 받습니다.
  - 에디터 미리 실행 트리에서 감싼 문자열 **통째**의 `+추출` 버튼은 없어졌습니다(이제 객체 칸으로 보입니다). 경로를 손으로 적으면 전과 같이 원래 문자열을 뽑습니다.
  - 버림이 있던 도착률 run의 포화 진단이 「슬롯 부족」에서 「서버 응답이 가끔 멈춤」으로 바뀔 수 있습니다. 이 진단은 실제 시스템에서의 확인이 더 필요합니다 — 판정이 어색하면 이슈로 알려 주세요.
- **인사이트 CSV/XLSX 내보내기의 헤더가 바뀝니다.** 끝에 열 4개(`typical_in_flight`·`max_in_flight`·`drop_seconds`·`measured_seconds`)가 붙습니다(17 → 21열). 열 위치로 읽는 스크립트는 그대로 동작하고, 열 개수를 검사하는 스크립트는 고쳐야 합니다.
- 계단 표의 「달성」은 그 계단에서 **끝난** 반복 수 기준입니다(시작한 수가 아닙니다). 느려지는 시스템이 100%로 보이지 않게 하기 위해서입니다. 시작한 수는 내보내기의 `launched_rate` 열에 따로 있습니다.
- 계단 실패를 오류율로 잡으려면 시나리오에 응답 검증(`assert: - status: 200`)이 있어야 합니다. 검증이 없으면 5xx가 오류로 세어지지 않아 계단이 「정상」으로 판정됩니다.
- 이번 릴리즈에는 **DB 마이그레이션 2개**(0024·0025)가 있습니다. 첫 실행 때 자동 적용되고, 기존 시나리오·run·프리셋·모니터 보드는 그대로 동작합니다. 옛 버전으로 되돌릴 가능성이 있으면 올리기 전에 DB 파일을 복사해 두세요. gRPC 프로토콜 변경은 필드 추가뿐입니다.
- **Windows 터미널 모니터의 알려진 제한**은 v0.13.0과 같습니다(매뉴얼 §1-1).
- 변경 내역 전체: [`v0.15.0...v0.16.0`](https://github.com/SeonggukJeong/handicap/compare/v0.15.0...v0.16.0), 기능별 상세는 [`docs/build-log.md`](https://github.com/SeonggukJeong/handicap/blob/master/docs/build-log.md).
