## 하이라이트

### 생성 변수를 요청마다 새로 뽑습니다 ("요청마다 새로 뽑기")
지금까지 생성 변수(날짜·랜덤 정수·UUID·랜덤 문자열·선택 배열)는 반복(시나리오 1회 실행)이 시작될 때 한 번만 값을 정하고, 그 반복 동안 모든 스텝이 같은 값을 썼습니다. 이제 변수 편집기의 **요청마다 새로 뽑기** 체크박스를 켜면, 그 변수를 쓰는 요청이 나갈 때마다 새 값을 뽑습니다.

- **언제 쓰나**: 스텝마다 다른 체크박스 배열, loop로 같은 요청을 반복할 때 회차마다 다른 수량·ID, 요청마다 보낸 시각(`date` + `unix_ms`) 같은 값.
- **기존처럼 공유도 됩니다**: 주문 번호처럼 한 반복 안에서 같아야 하는 값은 체크박스를 끈 채로 두면 됩니다. 변수마다 따로 정할 수 있습니다.
- **우선순위는 그대로**: 같은 이름을 데이터셋이나 추출(extract) 값이 채우면 그 값이 우선하고, 그 뒤로는 다시 뽑지 않습니다. parallel 분기 안에서도 같은 규칙입니다.
- **YAML로도 씁니다**: 변수 선언에 `refresh: request`를 붙이면 됩니다(예: `flags: {gen: pick_array, length: 10, min: 1, max: 3, refresh: request}`). 켠 변수는 변수 패널 접힘 행에 `요청마다` 배지가 붙습니다.
- **기존 시나리오는 영향 없음**: 옵션을 쓰지 않은 시나리오는 YAML과 실행 결과가 지금과 같습니다.
- 미리 실행(test-run)에서도 같은 규칙으로 동작하므로, 스텝별로 실제 어떤 값이 나가는지 바로 확인할 수 있습니다.

### 그 밖의 개선
- 큰 시나리오에서 미리 실행 준비가 느려질 수 있던 계산을 선형 시간으로 바꿨습니다.
- 최신 Rust 툴체인의 코드 검사(clippy) 경고를 해소해 CI를 복구했습니다.

## 다운로드

| 환경 | 파일 | 비고 |
|---|---|---|
| Windows (설치) | `Handicap_0.10.0_x64-setup.exe` | 권장. 컨트롤러·워커·UI·DB 내장 |
| Windows (설치, MSI) | `Handicap_0.10.0_x64_en-US.msi` | 사내 배포 도구·그룹 정책으로 일괄 설치할 때 |
| Windows (포터블) | `Handicap_0.10.0_x64-portable.exe` | 설치 없이 exe 한 파일 |
| macOS (Apple Silicon) | `Handicap_0.10.0_aarch64.dmg` | 서명·공증 없음 — 우클릭 → 열기로 실행 |
| macOS (Intel) | `Handicap_0.10.0_x64.dmg` | 서명·공증 없음 — 우클릭 → 열기로 실행 |

Linux 서버·폐쇄망·LAN 분산 워커·Kubernetes 설치는 [README](https://github.com/SeonggukJeong/handicap)의 **"시작하기 — 환경별 설치 절차"** 절을 참고하세요.

## 참고

- 코드 서명이 **없는** 배포라 Windows SmartScreen이 경고를 띄웁니다. 정상적인 경고이며 **"추가 정보" → "실행"** 으로 진행합니다. macOS는 Gatekeeper가 차단할 수 있습니다 — 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)로 실행합니다.
- **워커를 따로 띄워 쓰는 경우(LAN 분산 워커·Kubernetes)는 컨트롤러와 워커를 함께 0.10.0으로 올리세요.** 이전 버전 워커는 `refresh` 키가 든 시나리오를 읽지 못해 run이 시작 직후 실패합니다.
- DB 마이그레이션은 없습니다. 기존 시나리오·run은 그대로 동작합니다.
- 변경 내역 전체: [`v0.9.0...v0.10.0`](https://github.com/SeonggukJeong/handicap/compare/v0.9.0...v0.10.0), 기능별 상세는 [`docs/build-log.md`](https://github.com/SeonggukJeong/handicap/blob/master/docs/build-log.md).
