## 하이라이트

### 데스크톱 앱만으로 여러 PC에서 부하 나눠 내기

설치판 앱 상단의 **「모드 전환」** 에서 이 PC를 서버로 열고, 다른 PC를 부하기로 붙일 수 있습니다. 명령줄·Kubernetes 없이 사무실 PC 여러 대로 부하를 나눠 냅니다.

- **서버 PC**: 「서버로 열기」를 누르면 이 PC가 서버가 됩니다. 서버 PC도 부하를 냅니다(「이 PC도 부하 내기」로 끌 수 있음). 「혼자 쓰기로 돌아가기」로 원래대로 돌아갑니다.
- **부하기 PC — 버튼으로**: 서버 화면의 **「부하기 PC 접속 코드」** 를 「복사」 → 부하기 PC 앱의 「모드 전환」 → **「부하기로 접속」** 에 붙여넣고, 확인 창에서 서버 주소를 확인하면 합류합니다. 상태 화면에서 연결 중·연결됨·실행 중·다시 시도 중·제외됨·끊김을 보고, 「접속 끊기」·「다시 접속」을 할 수 있습니다. 부하기 ID는 설치마다 하나라서 PC 이름이 같아도 따로 보입니다.
- **부하기 PC — 명령으로**: 서버 화면에서 Windows·macOS·Linux용 부하기 명령을 복사해 붙여넣어도 됩니다.
- 포터블 exe의 `--worker-mode pool`이 **이번 버전부터 실제로 동작**합니다(이전 버전은 이 옵션을 무시했습니다). `--worker-token`이 필요하고, `--worker-mode kubernetes`는 거절합니다.
- 서버와 부하기 사이 연결은 **암호화되지 않습니다**. 사내망(사설 망)에서만 쓰세요. 사설 망이 아닌 주소로 서버를 열거나 접속하면 화면이 경고합니다.

### 분산 부하기 동작 개선

- **부하기 한 대가 멈추면 run 전체가 멈추고, 사유가 남습니다.** Ctrl+C·SIGTERM·K8s Pod 퇴출로 부하기 한 대가 멈추면 다른 부하기도 함께 멈춥니다. 그 사유는 run 기록(API·인쇄 보고서)과 실행 화면에 남습니다. 이전에는 run이 중단으로 표시되는데도 다른 부하기가 끝까지 부하를 냈습니다.
- 실행 화면이 **중단된(`aborted`) run의 사유도** 보여 줍니다.
- run이 끝나면 풀 부하기가 **곧바로(약 2초 → 수십 ms) 다시 등록**합니다. 그래서 앞 run 직후에 시작한 run도 부하기를 모두 받습니다.
- 풀 부하기가 run마다 서버 연결을 하나씩 남기던 문제를 고쳤습니다. 오래 켜 둔 부하기의 연결·메모리가 늘고, 실행 중에 끊은 부하기가 서버 목록에 계속 「사용 중」으로 남던 현상입니다.
- run을 끝낸 부하기가 다시 등록하는 동안에도 서버 목록의 라벨·용량·「비우기」 설정이 유지됩니다.
- run 직후 「제외」한 부하기가 다시 들어와 부하를 받던 드문 틈을 막았습니다.
- 재등록 없이 사라진 부하기는 30초가 아니라 **약 10초 뒤** 목록에서 사라집니다.
- 풀 모드가 아닌 컨트롤러는 풀 부하기 등록을 `controller is not in pool mode`로 거절합니다. 이전에는 부하기가 배정을 받지 못한 채 기다렸습니다.

### 조건 반복 — 「될 때까지 다시 보내기」

대기 응답(예: 상태 200인데 본문의 처리 상태가 아직 `PENDING`)을 받으면 잠시 쉬었다가 같은 요청을 다시 보내는 시나리오를 만들 수 있습니다.

- **반복 스텝의 「반복 조건」**: 본문을 먼저 한 번 돌고, 조건이 참이면 다시 돕니다. 반복 횟수는 이때 「최대 횟수」가 됩니다(비우면 run이 끝날 때까지). 최대 횟수까지 풀리지 않으면 그 반복을 끝내고 시나리오 처음부터 다시 시작합니다.
- **「이 반복 안의 think time은 항상 적용」**(기본 켜짐): 도착률 기준 실행·시험 실행·운영 모니터처럼 think time을 무시하는 실행에서도 이 반복 안에서는 쉽니다.
- 조건 반복 안에서는 응답에 없는 값을 에러로 세지 않고 빈 값으로 둡니다. 단, 그 빈 값(JSON `null` 포함)을 뒤 요청의 **주소**(경로·쿼리 문자열)에 쓰면 그 요청은 보내지 않고 에러 「보내지 않음 (앞 스텝 값 없음)」으로 셉니다. 헤더·본문에는 빈 값이 그대로 들어갑니다. 반복 안의 요청이 모두 이렇게 막히면 그 반복과 이번 실행을 끝냅니다.
- **리포트**: 조건 반복이 있었던 run의 리포트에 재시도·중단·회차 분포가 표시됩니다. 스텝 표·막대 보기에서는 그 스텝의 응답 시간이 「반복을 끝낸 응답 / 재시도로 이어진 응답」 두 줄로 나뉩니다. 인쇄 보고서에는 「보내지 않음」 칸이 생겨 응답을 받은 뒤의 실패와 구분됩니다.
- 시험 실행·모니터 기록(GUI·TUI)에 반복 조건 판정 줄이 보입니다. 에디터는 쉬지 않는 재시도·실패해도 계속되는 반복을 경고합니다.
- 요청 없이 조건 판정만 반복하는 시나리오는 시험 실행·모니터 점검이 상한에서 끊깁니다(`판정 줄 상한 초과`). 빈 반복은 곧 끝납니다. 순차 데이터 시험 실행에서 판정 줄 예산이 정확히 바닥난 뒤의 행은 「미실행」으로 보입니다.

### 추출 기본값

추출 줄의 **「+ 기본값」** 에 값을 적으면, 응답에 값이 없을 때(요청이 실패했을 때 포함) 그 글자가 대신 들어갑니다. 기본값이 들어간 이름은 뒤 요청 주소에 써도 막히지 않습니다. 시험 실행과 모니터 기록(GUI·TUI)에 「기본값」 표시가 뜹니다.

### 터미널 모니터 `handicap-tui`

- 머리 줄이 `마지막 점검 {시각}  ▰▰▰▱▱▱  4초`로 바뀌었습니다. 시각은 마지막으로 점검한 시각이고, 막대는 다음 점검까지 차오르며, 숫자는 남은 초입니다. 왼쪽의 「Handicap 모니터」 제목은 뺐습니다. 점검을 끈 보드는 머리 줄도 「점검 꺼짐」으로 보입니다.
- 응답에서 값을 골라 조건을 만들 때, 이름이 비밀처럼 보이면(`token`·`session`·`key`·`auth`·`cookie` 등) 비교값을 채우지 않습니다. 「화면에 추가」 할 때도 안내합니다.
- 아주 크거나 작은 숫자 표시, 조건 칸 대상의 줄바꿈, 낮은 화면의 선택 창, 칸을 찾지 못한 하위 화면의 안내를 다듬었습니다. 글자 폭 재기를 터미널이 실제로 그리는 폭에 맞췄습니다.

### 그 밖에

- **응답 소수를 정확히 읽습니다.** 일부 16–17자리 소수(예: `972.0979928970337`)를 끝자리 하나 다르게 읽던 문제를 고쳤습니다. 그래서 GUI에서 만든 소수 `=` 조건이 늘 실패하던 일이 없어집니다. 엔진 추출·모니터 판정·리포트 모두 해당합니다.
- 에디터 변수 패널을 종류와 상관없이 이름 순(한글 먼저, 대소문자 무시, `item2` < `item10`)으로 정렬합니다. YAML의 선언 순서는 그대로입니다.
- 시험 실행 잘림 문구에 판정 줄 수가 함께 보입니다.

## 여러 PC로 부하를 낼 때 꼭 볼 것

- **서버와 모든 부하기 PC를 함께 0.15.0으로 올리세요.** 서버는 부하기 버전을 확인하지 않습니다.
  - 조건 반복·추출 기본값을 쓴 시나리오는 옛 부하기가 읽지 못해 run이 실패합니다(옛 워커는 `default` 키를 거절합니다).
  - 조건 반복 리포트의 재시도·회차 분포·응답 시간 두 줄은 옛 부하기 몫만큼 조용히 빠집니다.
  - 옛 부하기는 소수를 옛 방식(끝자리 1 차이)으로 읽습니다.
- **부하기 한 대만 끊겨도 run 전체가 중단됩니다**(부하기 일부만으로 계속하지 않습니다). 긴 시험이라면 부하기 PC의 절전·화면 잠금으로 인한 네트워크 끊김을 꺼 두세요.
- **복제 이미지로 만든 PC 이름이 같다면** 「부하기로 접속」 버튼을 쓰세요. 복사한 **명령**에는 `--worker-id`로 PC 이름이 들어가서, 이름이 같은 PC들이 서버 목록에서 한 대로 겹칩니다. 명령을 쓴다면 `--worker-id` 값을 PC마다 다르게 고치세요.
- 「모드 전환」 화면(서버로 열기·부하기로 접속)은 macOS에서 확인했고, **Windows·Linux 실기에서는 아직 확인하지 못했습니다.** 그 화면이 동작하지 않으면 명령 방식(서버: 포터블 `--worker-mode pool`, 부하기: 복사한 명령)을 쓰고 이슈로 알려 주세요. 첫 실행 때 OS 방화벽 창이 뜨면 「액세스 허용」을 누르세요. 놓치면 부하기가 「다시 시도 중」에서 멈춥니다.
- 서버의 gRPC 포트가 이미 쓰이고 있으면 빈 포트로 열고 저장합니다. 그 전에 나눠 준 명령·접속 코드는 더 이상 쓸 수 없으니, 「모드 전환」 화면에서 새로 복사하세요.

## 참고

- 코드 서명이 **없는** 배포라 Windows SmartScreen이 경고를 띄웁니다. **"추가 정보" → "실행"** 으로 진행합니다. macOS는 Gatekeeper가 차단할 수 있습니다 — 우클릭 → 열기(또는 `xattr -dr com.apple.quarantine`)로 실행합니다.
- **판정이 바뀔 수 있는 조건**:
  - 숫자 값에 건 `포함` 조건: 서버가 숫자를 GUI에 보이는 글자로 적습니다(`1.0`이 아니라 `1`, `1e+16`이 아니라 `10000000000000000`, `1e-6`이 아니라 `0.000001`). 그래서 `포함 ".0"`처럼 통과하던 조건이 실패하거나, `포함 "0000"`처럼 실패하던 조건이 통과할 수 있습니다. 숫자 칸에는 `=`·`>` 같은 비교를 쓰세요. 화면 표시 값·실패 사유의 숫자도 같은 글자로 바뀝니다.
  - v0.14.0 TUI `a` → `조건으로 추가`로 만든 16–17자리 소수 조건은 끝자리가 1 다른 글자로 저장돼 있을 수 있습니다. 업그레이드 뒤 `=`/`∈`가 실패로 바뀌면 받은 값으로 다시 추가하세요. 시나리오 YAML에 시험 실행 기록의 값을 그대로 옮겨 둔 소수 조건도 같습니다. `12.34` 같은 짧은 소수는 해당하지 않습니다.
- 제어 문자·방향 제어 문자가 든 보드 파일은 가져오기·TUI 시작에서 거절됩니다. 오류가 가리키는 칸을 고치세요.
- 서버의 「이 PC도 부하 내기」 부하기 ID가 PC 이름에서 설치 ID로 바뀌었습니다. 그래서 워커 화면에서 그 줄의 라벨·「비우기」 설정이 한 번 초기화됩니다.
- 서버 설정의 토큰이 256바이트를 넘으면 시작할 때 새로 만듭니다. 그 토큰으로 붙던 명령 부하기는 새 명령이 필요합니다.
- 이번 릴리즈에는 DB 마이그레이션이 없습니다. 기존 시나리오·run·모니터 보드는 그대로 동작합니다. gRPC 프로토콜 변경은 필드 추가뿐입니다.
- **Windows 터미널 모니터의 알려진 제한**은 v0.13.0과 같습니다(매뉴얼 §1-1).
- 변경 내역 전체: [`v0.14.0...v0.15.0`](https://github.com/SeonggukJeong/handicap/compare/v0.14.0...v0.15.0), 기능별 상세는 [`docs/build-log.md`](https://github.com/SeonggukJeong/handicap/blob/master/docs/build-log.md).
