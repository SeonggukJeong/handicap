# handicap-tui 운영 매뉴얼 (터미널 모니터)

Ubuntu 19.04 같은 저사양 모니터 PC에서 Handicap GUI의 "운영 모니터 보드"를 터미널 화면으로 계속 띄워 두는 프로그램이다. 설계: `docs/superpowers/specs/2026-11-07-tui-monitor-design.md`, 결정: ADR-0055.

## 1. 설치

릴리즈 에셋 `handicap-tui_<ver>_linux-x86_64.tar.gz`를 받아 푼다(바이너리 + 이 매뉴얼). 추가 라이브러리 설치는 필요 없다(glibc 2.27 이하 심볼만 사용).

```sh
tar xzf handicap-tui_<ver>_linux-x86_64.tar.gz
sudo mkdir -p /opt/handicap
sudo cp handicap-tui_<ver>_linux-x86_64/handicap-tui /opt/handicap/
sudo chmod +x /opt/handicap/handicap-tui
/opt/handicap/handicap-tui --version
```

보드 파일은 Windows GUI에서 보드를 만든 뒤 **내보내기**(보드·시나리오·환경이 든 json 하나)로 만들어 같은 PC의 원하는 경로(예: `/home/ops/board.json`)에 복사한다.

실행: `handicap-tui /home/ops/board.json`

## 2. 자동 시작 (로그인하면 바로 점검 화면)

자동 로그인 전제다. `~/.config/autostart/handicap-tui.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=Handicap 모니터
Exec=gnome-terminal --full-screen -- sh -c '/opt/handicap/handicap-tui /home/ops/board.json; echo; echo "핸디캡 모니터가 종료됐습니다. Enter를 누르면 창이 닫힙니다."; read x'
X-GNOME-Autostart-enabled=true
```

- `--full-screen`은 상단 바와 Ubuntu Dock까지 가린다(F11로 해제). 상단 바를 남기려면 `--maximize`로 바꾼다.
- `sh -c '…; read x'`로 감싸는 이유: glibc 로더 오류·크래시처럼 **프로그램 밖에서 프로세스가 죽어도** 터미널 창이 남아 원인이 보이게 하려는 것이다. 빼면 오류와 함께 창이 즉시 닫힌다.
- 네트워크가 늦게 올라오면 지연을 준다. Xorg 세션: `X-GNOME-Autostart-Delay=20`(초) 줄을 추가. Wayland 세션: `Exec=` 명령 앞에 `sleep 20;`을 붙인다(`sh -c 'sleep 20; /opt/handicap/handicap-tui …'`).

## 3. 키

| 키 | 동작 |
|---|---|
| 방향키 / `h` `j` `k` `l` | 칸 선택 이동 |
| `Tab` / `Shift+Tab` | 다음/이전 보드(보드가 2개 이상일 때) |
| `?` | 도움말(모든 키·파일 경로·로그 경로) |
| `q` / `Ctrl+C` | 종료 확인창. **`y`만 종료**, 그 외 키는 취소(확인창에서의 `Ctrl+C`도 취소) |
| `Esc` | 한 단계 뒤로 |
| 마우스 왼쪽 클릭 | 그 칸 선택(칸 격자에서만) |
| 오류 화면: `r` / `q` | 다시 시도 / 종료 |

- 마우스 모드를 켜 두므로 텍스트를 복사하려면 **Shift+드래그**를 쓴다.
- Caps Lock이 켜져 있거나 한글 입력기(두벌식)가 켜져 있어도 같은 키로 동작한다(ㅂ=`q`, ㅛ=`y`, ㅗ ㅓ ㅏ ㅣ=`h` `j` `k` `l`, ㄱ=`r`).

## 4. 화면 읽는 법

- 맨 위 줄: 보드 이름, 순번(보드가 여러 개일 때), 서버 시각, 점검 상태(끊겼으면 원인).
- 칸: 제목 · 상태 문구와 큰 값 · 연속 실패 줄 · 막대 이력(높이 = 지연, 초록 = 성공, 빨강 = 실패, 회색 = 설정 오류/확인 못 함/분기 제외) · **시각 줄** · 평균·최대.
- **시각 줄**: 막대 바로 아래 한 줄에 막대들의 실제 점검 시각(이 PC의 로컬 시각)을 눈금으로 쓴다. 보이는 구간이 10분 이상이면 `HH:MM`, 10분 미만이면 `HH:MM:SS`다. 자리를 비운 사이 지나간 실패 막대가 대략 몇 시였는지 이 눈금으로 읽는다. 점검이 밀리거나 끊긴 구간은 눈금 간격이 고르지 않게 보인다. 하루(24시간)를 넘는 구간은 날짜가 없어 같은 글자로 보일 수 있다.
- 창이 작으면 "창을 키워 주세요(현재 W×H, 필요 W×H)"가 뜬다. 칸 하나의 최소 크기는 24×6이다.
- 맨 아래 줄은 현재 화면에서 쓸 수 있는 키 안내다.

## 5. 파일 교체 (새 칸 반영)

GUI에서 칸을 추가한 뒤 보드를 다시 내보내 **같은 경로의 파일을 덮어쓰고 TUI를 다시 띄운다**(`q` → `y`로 종료한 뒤 자동 시작 명령을 다시 실행하거나 PC 재로그인). 시작할 때마다 파일을 새로 가져오므로 새 칸을 포함해 점검이 시작된다. 재시작하면 막대 이력·기록은 비워지고 처음부터 쌓인다.

## 6. 로그

`$XDG_STATE_HOME/handicap/`(기본 `~/.local/state/handicap/`):

- `tui.log` — 이번 실행 로그(실행마다 새로 씀)
- `tui.log.1` — 직전 실행 로그 하나
- `tui-check.log` — `--check` 전용 로그(돌고 있는 화면의 로그를 건드리지 않으려고 분리)

로그 파일은 권한 0600, 새로 만든 로그 디렉터리는 0700이다(`HOME`·`XDG_STATE_HOME`을 모두 알 수 없으면 임시 폴더로 대신하지 않고 "로그 없음"으로 표시한다). 터미널 화면에는 로그가 나오지 않는다. 문제가 생기면 이 파일을 본다(기본 수준 `info`, `RUST_LOG=debug` 등으로 조정). 비정상 종료 시 터미널에 "로그: <경로>" 한 줄이 남는다.

## 7. `--check` (점검 1회 후 종료)

`handicap-tui --check /home/ops/board.json` — 모든 칸을 한 번 점검해 칸마다 한 줄(`보드 / 칸  상태  큰 값`)을 출력하고 종료한다. 배포 전·문제 확인용이고 화면은 열지 않는다.

| exit | 뜻 |
|---|---|
| 0 | 모든 칸의 결과를 받았다(칸이 실패 상태여도 0 — 상태는 출력으로 본다) |
| 1 | 기동·파일 가져오기·시작 실패, 또는 종료 신호(SIGHUP/SIGTERM/SIGINT)로 중단 |
| 2 | 대기 상한 초과(⌈실행 단위 수/32⌉ × 칸들의 `check_budget_seconds` 최댓값 + 10초) |

## 8. 보드 수와 PC 부담

- 파일에 든 보드는 **전부** 시작되어 계속 점검한다(화면에서 폴링하는 것은 보이는 보드만). 한 파일 최대 50보드까지 허용하지만 저사양 PC에서는 내보낼 보드를 꼭 필요한 것만 고른다.
- 칸마다 기록(요청·응답)을 메모리에 쌓는다. 최악치는 칸 수 × 막대 수(`bar_count`, 최대 300) × 기록 상한(`record_limit_kb`)이다. 메모리가 빠듯한 PC는 GUI에서 `record_limit_kb`를 낮게 잡아 내보낸다.

## 9. 보안 전제

내장 컨트롤러의 REST는 루프백에만 열리지만 **인증이 없다** — 같은 PC의 다른 사용자·프로세스는 환경 값(평문 포함)까지 읽을 수 있다. **전용 단일 사용자 모니터 PC**에서만 쓴다.

- **이 PC에서 웹 브라우저로 인터넷을 보지 않는다.** TUI가 떠 있는 동안 악성 웹페이지가 DNS 재바인딩으로 `127.0.0.1`의 이 인증 없는 API에 접근해 환경 값을 읽을 수 있다.
- 임시 DB는 `$XDG_RUNTIME_DIR`(없으면 시스템 임시 폴더) 아래 **전용 디렉터리** `handicap-tui-<pid>-<무작위>/`(권한 0700, 안의 DB 파일 0600)에 둔다. 정상 종료(`q`→`y`)와 창 닫기·로그아웃(SIGHUP/SIGTERM/SIGINT)에서는 이 디렉터리째 지운다(신호 뒤 5초 안에 정상 종료하지 못하면 강제로 지우고 끝낸다). `kill -9`·전원 차단으로 죽으면 다음 시작 때(또는 재부팅 때) 정리될 때까지 남는다. 이는 이 전제 아래의 위생 조치일 뿐 보안 경계가 아니다.
- 로그 파일은 권한 0600이다(§6).
- 보드 json에도 환경 값이 들어 있으니 파일 권한을 `chmod 600`으로 둔다.

## 10. 문제 해결

- 실행하자마자 `exec format error` → 대상 PC가 32비트 사용자 공간으로 설치된 경우다(이 바이너리는 x86_64 전용). `uname -m`·`getconf LONG_BIT`로 확인.
- 터미널 창이 바로 닫힘 → 자동 시작 `Exec=`를 위 `sh -c '…; read x'` 형태로 감싸 원인을 남긴다.
- 화면 가운데에 오류가 뜨고 안 닫힘 → 파일 경로·json 내용 문제다. 원인이 화면에 적혀 있고 `r`로 다시 시도할 수 있다.
- 막대(`▂…█`)·테두리 문자 폭이 어긋남 → 터미널의 "모호 폭 문자" 설정과 로케일(ko_KR) 문제일 수 있다. 실기 확인 결과는 build-log 참고.
