# handicap-tui 운영 매뉴얼 (터미널 모니터)

Ubuntu 19.04 같은 저사양 모니터 PC에서 Handicap GUI의 "운영 모니터 보드"를 터미널 화면으로 계속 띄워 두는 프로그램이다. 설계: `docs/superpowers/specs/2026-11-07-tui-monitor-design.md`, 결정: ADR-0055.

## 1. 설치

Linux(Ubuntu): 릴리즈 에셋 `handicap-tui_<ver>_linux-x86_64.tar.gz`를 받아 푼다(바이너리 + 이 매뉴얼). 추가 라이브러리 설치는 필요 없다(glibc 2.27 이하 심볼만 사용).

```sh
tar xzf handicap-tui_<ver>_linux-x86_64.tar.gz
sudo mkdir -p /opt/handicap
sudo cp handicap-tui_<ver>_linux-x86_64/handicap-tui /opt/handicap/
sudo chmod +x /opt/handicap/handicap-tui
/opt/handicap/handicap-tui --version
```

보드 파일은 Windows GUI에서 보드를 만든 뒤 **내보내기**(보드·시나리오·환경이 든 json 하나)로 만들어 같은 PC의 원하는 경로(예: `/home/ops/board.json`)에 복사한다.

실행: `handicap-tui /home/ops/board.json`

### 1-1. Windows (v0.13.0부터)

릴리즈 에셋 `handicap-tui_<ver>_windows-x86_64.zip`을 받아 원하는 폴더(예: `C:\handicap\`)에 푼다(`handicap-tui.exe` + 이 매뉴얼). 코드 서명이 없어 SmartScreen이 경고하면 **"추가 정보" → "실행"**.

```powershell
C:\handicap\handicap-tui.exe --version
C:\handicap\handicap-tui.exe C:\handicap\board.json
```

- **Windows Terminal에서 실행한다**(Windows 11 기본). 옛 콘솔 창(conhost)은 막대·테두리 블록 문자와 한글 폭이 어긋날 수 있다. 전체화면 바로가기: 대상 `wt.exe -F C:\handicap\handicap-tui.exe C:\handicap\board.json`, 로그인 시 자동 시작은 그 바로가기를 `shell:startup` 폴더에 둔다.
- exe를 더블클릭하면 파일 인자가 없어 사용법만 찍고 창이 바로 닫힌다 — 위처럼 보드 파일 경로를 붙여 실행한다.
- 키·화면·`--check`는 Linux와 같다. 종료 신호는 `Ctrl+C`뿐이다(Linux의 SIGHUP/SIGTERM 처리는 없다).

**Windows의 알려진 제한 (v0.13.0)** — 실제 Windows PC에서는 아직 확인 전이다(CI의 Windows 러너에서 빌드와 `--check` 스모크만 통과).

- **로그와 `b` 테두리 기억이 기본으로 꺼진다**: 둘 다 `HOME`(또는 `XDG_STATE_HOME`·`XDG_CONFIG_HOME`) 환경 변수로 위치를 찾는데 Windows에는 기본으로 `HOME`이 없다. 쓰려면 사용자 환경 변수를 한 번 만든다: `setx HOME "%USERPROFILE%"`(새 창부터 적용). 그러면 로그는 `%USERPROFILE%\.local\state\handicap\`, 설정은 `%USERPROFILE%\.config\handicap\tui.json`에 생긴다.
- **창의 X 버튼으로 닫으면 임시 DB가 남을 수 있다**: 임시 DB(환경 값 포함)는 `%TEMP%\handicap-tui-<pid>-<무작위>\`에 둔다. `q`→`y` 정상 종료(와 `--check` 중의 `Ctrl+C`)는 지우지만, 창 닫기는 처리하지 않는다. 또 Linux와 달리 **다음 시작 때 남은 디렉터리를 지우지 않으므로**, 창을 닫아 끝냈다면 `%TEMP%`의 `handicap-tui-*` 폴더를 직접 지운다.
- 위 두 제한은 후속 수정 예정이다(roadmap §B48).
- 0600/0700 권한 지정은 Linux 전용이다(Windows는 사용자별 `%TEMP%` 폴더 권한을 따른다). §9의 "전용 단일 사용자 PC" 전제는 그대로다.

## 2. 자동 시작 (로그인하면 바로 점검 화면, Linux)

자동 로그인 전제다. `~/.config/autostart/handicap-tui.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=Handicap 모니터
Exec=gnome-terminal --full-screen --zoom=1.6 -- sh -c '/opt/handicap/handicap-tui /home/ops/board.json; echo; echo "핸디캡 모니터가 종료됐습니다. Enter를 누르면 창이 닫힙니다."; read x'
X-GNOME-Autostart-enabled=true
```

- **글자 크기 고르기**: 전체화면에서 `Ctrl`+`+`/`Ctrl`+`-`(원래대로 `Ctrl`+`0`)로 보기 좋은 크기를 찾고 그 배율을 `--zoom=`에 적는다(터미널은 확대 값을 기억하지 않는다). 6칸이면 1920×1080에서 1.6 안팎.
- `--full-screen`은 상단 바와 Ubuntu Dock까지 가린다(F11로 해제). 상단 바를 남기려면 `--maximize`로 바꾼다.
- `sh -c '…; read x'`로 감싸는 이유: glibc 로더 오류·크래시처럼 **프로그램 밖에서 프로세스가 죽어도** 터미널 창이 남아 원인이 보이게 하려는 것이다. 빼면 오류와 함께 창이 즉시 닫힌다.
- 네트워크가 늦게 올라오면 지연을 준다. Xorg 세션: `X-GNOME-Autostart-Delay=20`(초) 줄을 추가. Wayland 세션: `Exec=` 명령 앞에 `sleep 20;`을 붙인다(`sh -c 'sleep 20; /opt/handicap/handicap-tui …'`).

## 3. 키

| 키 | 동작 |
|---|---|
| `Ctrl + + / -` | 글자 크기(터미널 기능). 도움말 줄 `글자 크기 · 고정: --zoom=1.6` — 고른 배율은 자동 시작 줄의 `--zoom=`으로 고정(§2) |
| 방향키 / `h` `j` `k` `l` | 칸 선택 이동 |
| `Tab` / `Shift+Tab` | 다음/이전 보드(보드가 2개 이상일 때) |
| `?` | 도움말(모든 키·파일 경로·백업 경로·로그 경로). 오류 보기·칸 설정 화면에서는 동작하지 않는다(입력줄에서는 글자) |
| `b` | 테두리 모양 바꾸기(굵은 선 / 반 칸 블록, 저장됨 — §3-1). 도움말 줄 `테두리 모양 바꾸기(굵은 선 / 반 칸 블록, 기억됨)` |
| `e` | 선택 칸 오류 보기(§4-1). 도움말 줄 `선택 칸 오류 보기(실패 목록)` |
| `Enter` (모니터) | 선택 칸 설정 보기·수정(§4-2) — 번호나 `↑↓`로 항목을 고르고 `Enter` |
| 오류 목록: `↑↓` · `PgUp`/`PgDn` · `Home`/`End` | 회차 고르기 |
| 오류 목록: `a` | 전체 회차 / 실패만 바꾸기 |
| 오류 목록: `Enter` | 고른 회차 자세히 |
| 자세히: `↑↓`(`j`/`k`)·`PgUp`/`PgDn`(10줄씩)·`Home`/`End` / `Enter` | 스텝 고르기 / 그 스텝의 요청·응답(조건 분기 줄에서는 무동작) |
| 요청·응답: `↑↓` · `PgUp`/`PgDn` · `Home`/`End` | 스크롤 |
| 요청·응답: `←` / `→` | 같은 기록의 이전 / 다음 스텝(조건 분기 줄은 건너뛰고, 양 끝에서는 그대로) |
| 요청·응답: `v` | 요청 본문 보기 / 가리기(요청 본문이 있을 때만 키 줄에 보인다) |
| 칸 설정: `↑↓`(`j`/`k`) · `PgUp`/`PgDn` · `Home`/`End` | 항목 고르기 |
| 칸 설정: `1`–`9` | 그 번호 항목으로 바로 이동. `1`을 누르고 1초 안에 `0`–`4`를 누르면 10–14번 |
| 칸 설정: `Enter` | 고른 항목 수정(입력줄·목록 창·하위 화면이 열린다. 고칠 수 없는 항목은 이유를 한 줄로 보여 주고 다음 키에 닫힌다) |
| 입력줄: 글자 키 | **친 글자 그대로 들어간다** — `q`·`j`·`?`·한글도 글자다(종료·이동이 아니다). 숫자 항목은 숫자만(6자리까지) |
| 입력줄: `Enter` / `Esc` | 저장 / 취소 |
| 입력줄: `←` `→` · `Home`/`End` · `Backspace`/`Delete` · `Ctrl+U` | 커서 이동 · 지우기 · 전부 지우기 |
| 입력줄: 붙여넣기 | 터미널 붙여넣기(보통 `Ctrl+Shift+V`)로 넣을 수 있다. 줄바꿈·제어 문자는 빠지고, **붙여넣기만으로는 저장되지 않는다**(`Enter`를 눌러야 저장). 브래킷 붙여넣기를 지원하지 않는 옛 터미널에서는 붙여넣은 줄바꿈이 `Enter`로 들어와 바로 저장될 수 있다(gnome-terminal·tmux는 지원) |
| 목록 창(환경·볼 스텝·응답 시간 기준): `↑↓`(`j`/`k`) / `Enter` / `Esc` | 고르기 / 저장 / 취소 |
| 하위 목록(기준선·성공 조건·화면에 표시): `Enter` / `a` / `d` / `s` | 수정 / 추가(기준선만) / 삭제(`y`로 확인) / 자리 바꾸기(화면에 표시가 2개일 때) |
| 조건 수정 칸: `Tab`/`Shift+Tab` · `←` `→` · `Space` · `Enter` / `Esc` | 칸 이동 · 규칙 고르기 · 체크 켜고 끄기 · 저장 / 취소 |
| 환경 변수 화면: `v` | 값 보기 / 가리기(화면을 나가면 다시 가려진다) |
| 확인 줄 | `Enter`로 계속(삭제 확인은 `y`), 그 밖의 키는 취소 |
| `q` / `Ctrl+C` | 종료 확인창. **`y`만 종료**, 그 외 키는 취소(확인창에서의 `Ctrl+C`도 취소) |
| `Esc` | 한 단계 뒤로(요청·응답 → 자세히 → 목록 → 모니터, 하위 목록·변수 화면 → 칸 설정 → 모니터, 도움말 닫기) |
| 마우스 왼쪽 클릭 | 그 칸 선택(칸 격자에서만). 칸 설정 메뉴(번호 목록, 입력줄·목록 창이 안 열렸을 때)에서는 항목 줄을 누르면 그 항목으로, 이미 고른 항목을 누르면 수정. 하위 목록·변수 화면은 키로만 |
| 오류 화면: `r` / `q` | 다시 시도 / 종료 |

**오류 보기·칸 설정 화면은 5분 동안 입력이 없으면 모니터로 돌아갑니다**(키·마우스 조작만 센다 — 마우스가 화면 위를 지나가기만 하는 것은 세지 않는다. 그 위에 띄운 종료 확인창도 포함. 도움말과 모니터 위 종료 확인창은 그대로 남는다). 화면 키 줄 바로 위와 도움말에도 같은 문장이 있다(화면 높이 10줄 미만이거나 폭이 모자라면 키 줄 위 문장은 통째로 빠진다). 칸 설정에서 **입력하던 값은 저장되지 않고 버려진다**(이미 `Enter`로 보낸 저장은 끝까지 진행된다). 붙여넣기도 입력으로 센다.

- 마우스 모드를 켜 두므로 텍스트를 복사하려면 **Shift+드래그**를 쓴다.
- Caps Lock이 켜져 있거나 한글 입력기(두벌식)가 켜져 있어도 같은 키로 동작한다(ㅂ=`q`, ㅛ=`y`, ㅗ ㅓ ㅏ ㅣ=`h` `j` `k` `l`, ㄱ=`r`, ㅠ=`b`, ㄷ=`e`, ㅁ=`a`, ㅍ=`v`, 칸 설정 하위 목록에서 ㅇ=`d`, ㄴ=`s`). **입력줄에서는 이 바꿔 읽기를 하지 않는다** — 친 글자가 그대로 들어간다.
- `Ctrl`과 함께 누른 글자 키(`Ctrl+C`·`Ctrl+Q` 밖)는 모니터·오류 보기·칸 설정 화면에서 아무 동작도 하지 않는다(`Ctrl+B`가 `b`로 읽히지 않게). 입력줄에서만 `Ctrl+U`(전부 지우기)가 동작한다.
- 모니터 키 줄은 `b 테두리 · Tab 다음 보드 · ←↑↓→ 칸 이동 · e 오류 보기 · Enter 칸 설정 · ? 도움말 · q 종료` 순서이고, 좁으면 **앞 조각부터** 통째로 뺀다(`b` → `Tab` → `칸 이동` 순 — 1a·tui-readability의 `칸 이동` → `Tab` → `b`에서 바뀜). 오류 보기·칸 설정 화면의 키 줄에는 `q 종료`를 쓰지 않는다(`q`는 동작한다).

### 3-1. 테두리 모양

- `b`를 누르면 칸 테두리가 **굵은 선**(기본)과 **반 칸 블록**으로 바뀐다. 즉시 바뀐다. 화면이 너무 작아 "창을 키워 주세요"가 뜬 상태에서는 `b`가 무시되어 모양도 저장도 바뀌지 않는다.
- 선택은 `~/.config/handicap/tui.json`에 저장되어 종료·재시작 뒤에도 유지된다. `XDG_CONFIG_HOME`이 있으면 그 아래 `handicap/tui.json`을 쓴다.
- 파일을 지우면 기본(굵은 선)으로 돌아간다. 파일을 읽지 못하면 로그(§6)에 경고를 남기고 기본(굵은 선)으로 시작한다.

## 4. 화면 읽는 법

- 맨 위 줄: 보드 이름, 순번(보드가 여러 개일 때), 서버 시각, 점검 상태(끊겼으면 원인).
- 칸: 제목 · 상태 문구와 큰 값 · 연속 실패 줄 · 막대 이력(높이 = 지연, 초록 = 성공, 빨강 = 실패, 회색 = 설정 오류/확인 못 함/분기 제외) · **시각 줄** · 평균·최대.
- **큰 값 크기**: 칸이 넉넉하면 응답 시간(`413 ms`)·짧은 사유(`HTTP 503`)를 여러 줄 높이의 큰 숫자로 쓴다(L = 5줄, M = 3줄, 머리 줄은 왼쪽 제목 · 오른쪽 상태 문구). 좁으면(S) 1a처럼 위 테두리에 제목, 첫 줄에 상태 문구와 큰 값을 한 줄로 쓴다. 단계는 보드 설정(제한 시간·화면 표시 항목·평균·최대 표시)과 칸 크기로만 정해지므로 응답 시간이 바뀌어도 글자 크기가 들쑥날쑥하지 않고, 한 보드의 칸은 모두 같은 단계다. 한글 사유·`—`처럼 큰 글꼴로 못 쓰는 값은 일반 굵은 글자.
- **막대**: 여러 줄 높이로, 높이는 그 칸의 그래프 최대값(`graph_max_ms`) 대비 응답 시간 비율이다(넘으면 맨 위에서 자른다). **실패** 막대는 빨간 빗금, **설정 오류**는 회색 빗금으로 막대 영역 끝까지 올라간다.
- **기준선**: 칸의 기준선마다 그 색 점선(`╌`)을 막대 영역 가로로 긋고(막대가 있는 칸에선 막대가 보인다), 오른쪽 숫자 열에 그 값(ms)을 같은 색으로 쓴다. 숫자 열 바로 아래 시각 줄 끝에 `(ms)`. 막대 영역이 너무 낮으면 기준선을 생략한다.
- **칸 바탕**: 느림 칸은 느림 색(넘은 기준선 색), 실패 칸은 빨강이 살짝 섞인 어두운 바탕으로 물든다. 정상·그 외 상태는 터미널 기본 바탕.
- **선택 칸**: 흰 바탕의 `▶ 제목`으로 표시한다(L·M은 칸 첫 줄, S는 위 테두리). 칸이 좁아도 `▶`는 늘 보이고 상태 문구가 통째 조각 단위로 줄어든다. 테두리는 모든 칸이 같은 모양이며 `b`로 굵은 선 / 반 칸 블록을 바꾼다(§3-1).
- **시각 줄**: 막대 바로 아래 한 줄에 막대들의 실제 점검 시각(이 PC의 로컬 시각)을 눈금으로 쓴다. 보이는 구간이 10분 이상이면 `HH:MM`, 10분 미만이면 `HH:MM:SS`다. 자리를 비운 사이 지나간 실패 막대가 대략 몇 시였는지 이 눈금으로 읽는다. 양 끝 사이 눈금은 `▲`로 시작하며 `▲` 바로 위 막대가 그 시각의 막대다. 점검이 밀리거나 끊긴 구간은 눈금 사이 시각 차이가 고르지 않다. 하루(24시간)를 넘는 구간은 날짜가 없어 같은 글자로 보일 수 있다.
- 창이 작으면 "창을 키워 주세요(현재 W×H, 필요 W×H)"가 뜬다. 칸 하나의 최소 크기는 24×6이다.
- 맨 아래 줄은 현재 화면에서 쓸 수 있는 키 안내다.

### 4-1. 오류 보기 (`e`)

모니터에서 칸을 고르고 `e` → **오류 목록** → `Enter` **자세히** → `Enter` **요청·응답**. 네 화면 모두 화면 전체를 쓰고 맨 윗줄은 모니터와 같은 머리 줄이다.

1. **목록은 그 칸의 막대 구간 안 회차만** 보여 준다(최신 순, 시각 · 상태 · 사유). 기록도 막대 개수(`bar_count`)만큼만 보관된다 — 사유를 불러오는 사이 막 밀려난 회차는 사유 칸이 `기록 지남`이고, 자세히를 열면 `이 점검의 기록이 없습니다 — …`가 뜬다. 오른쪽 위에 `실패 N회 · 최근 M회(약 X분) 중`, `a`로 전체 회차를 보면 `전체 M회`이고 정상·느림 줄의 사유 칸엔 응답 시간이 나온다. 실패가 없으면 `이 구간에 실패가 없습니다`. 그 보드의 점검이 꺼져 있으면 `점검이 꺼져 있어 결과가 없습니다`. 열어 둔 동안 새 결과는 위에 더해지고 `▶`는 같은 회차에 머문다(밀려나면 바로 다음 더 오래된 줄로). 좁은 창에서는 개수 → 상태 열 → 시각 열 순으로 통째로 빠진다.
2. **사유는 화면에 보이는 줄만 그때그때 불러온다**(`/status`는 최신 회차에만 사유를 주기 때문). 불러오는 동안 `불러오는 중…`. 판정 상세(조건에서 받은 값)는 목록이 아니라 자세히 화면에 있다.
3. **자세히**: 상태·응답 시간 · `사유` · `판정 상세` · `시나리오`·`환경` 이름 · 스텝 표(번호 · 스텝 이름 · 메서드 URL · 응답 코드 · 지연, 스텝 오류는 그 줄 아래 빨간 줄). 스텝 이름은 보드 파일 안의 시나리오에서 읽는다. 반복 안의 스텝은 엔진 회차 번호 그대로 `#0`·`#1`(0부터 — GUI 기록 창과 같다), 조건 분기는 흐린 `조건 분기 → then` 줄. 스텝 칸이면 그 스텝의 **마지막** 반복 줄에 `◀ 이 칸`이 붙고 처음부터 그 줄이 골라져 있다. 응답 코드 칸은 응답이 없을 때(`—`)만 빨강이다 — 칸 조건에 따라 404가 정상일 수 있어 4xx/5xx 코드 자체에는 실패색을 입히지 않는다. 창이 낮으면 `시나리오` 줄 → `판정 상세` 줄 → 표 머리 순으로 통째로 빠진다.
4. **요청 본문은 기본 가림**이다 — `요청 본문은 가려져 있습니다`, `v`로 보기/가리기. 요청·응답 화면을 나가거나 `←`/`→`로 옆 스텝에 가면 다시 가려진다. 인증 값(헤더·URL)은 서버가 가린 그대로 `••••`이고 `인증 값은 ••••로 가렸습니다` 안내가 붙는다.
5. **JSON 본문은 들여써서** 보여 준다(키 순서·숫자 표기는 그대로). 다음은 원문 그대로: 64KB를 넘는 본문(`64KB를 넘는 본문은 원문으로 표시합니다`) · 64단 넘게 중첩된 본문(`너무 깊게 중첩된 본문은 원문으로 표시합니다`) · 잘린 본문 · JSON이 아닌 본문. `기록 상한 NKB에서 잘림`은 보드의 점검 기록 상한(`record_limit_kb`)에서 잘렸다는 뜻이고, `1 MiB에서 잘림 — 실제 응답은 더 큼`은 엔진이 응답을 잘랐다는 뜻이다(이때는 64KB 안내 없이 잘림 안내만). 문자열 안에 감싼 JSON은 풀지 않는다. 머리 줄 바로 아래 첫 줄 오른쪽 끝의 `12/40줄`은 보이는 마지막 줄 / 전체 줄 수(본문이 한 화면에 다 들어가거나 폭이 모자라면 없다). 본문·헤더·사유 속 제어 문자(ESC 등)는 `�`로, 탭은 공백 4칸으로 바꿔 그리므로 화면이 지워지거나 색이 번지지 않는다.
6. **TUI를 다시 띄우면 기록은 비워진다**(기록은 메모리에만 있다 — §8).
7. **자리를 비워도 5분 뒤 모니터 화면으로 돌아가므로** 벽 화면이 목록에 멈춰 있지 않는다(보이게 해 둔 요청 본문도 다시 가려진다).

설정 오류로 요청 전에 멈춘 회차는 `요청을 보내기 전에 멈췄습니다(설정 오류) — 요청·응답 기록 없음`, 칸 제한 시간을 넘겨 끊긴 회차는 `응답이 오기 전에 시간 초과 — 요청·응답 기록 없음`이다(GUI 기록 창과 같은 문구).

### 4-2. 칸 설정 고치기 (`Enter`)

모니터에서 칸을 고르고 `Enter` → 그 칸 설정이 번호 목록으로 열린다(1 제목 … 12 화면에 표시, 그 아래 13 환경 변수 · 14 시나리오 변수). 번호나 `↑↓`로 항목을 고르고 `Enter`로 고친다. 항목 이름은 GUI 칸 편집기와 같은 말(`점검 주기(초)`·`제한 시간(초)`·`그래프 최대 높이(ms)` — 단위는 이름에 있고 값은 숫자만).

1. **고치면 바로 점검에 반영되고 보드 파일에 저장된다.** 저장되면 맨 위 줄에 `저장됨 HH:MM:SS`가 잠깐 보인다. TUI를 다시 띄워도 고친 값이 유지된다. 서버가 값을 받아들이지 않으면(예: 제한 시간 45 → `제한 시간은 1~30초여야 합니다`) 입력줄 아래에 그 이유가 보이고 아무것도 바뀌지 않는다. `저장 중…`이 보이는 동안(보통 1초 안)은 다른 키를 받지 않는다 — **이때 종료(`q`→`y`)하면 그 수정은 파일에 남지 않을 수 있다**(`저장됨`을 본 뒤 종료할 것).
2. **백업이 두 개 남는다** — 보드 파일 옆 `<파일>.bak`(바로 전 내용)과 `<파일>.orig.bak`(GUI에서 받은 원본). `.bak`은 저장할 때마다 바뀌고, `.orig.bak`은 TUI가 쓴 파일을 다시 띄워도 그대로다(밖에서 새 파일로 바꾼 뒤 처음 저장할 때만 그 새 파일로 바뀐다). 경로는 도움말(`?`)에 나온다. 보드 파일이 링크면 링크는 그대로 두고 실제 파일과 그 옆에 쓴다.
3. **새 파일로 바꾸면 이 PC에서 고친 값은 사라진다**(§5). 바꾸기 전에 TUI를 끄고 바꿀 것 — 켠 채 파일을 바꾸면 TUI는 그 파일에 쓰지 않고 맨 위 줄에 `보드 파일이 밖에서 바뀌었습니다 — 저장 안 됨, TUI를 다시 시작하세요`를 띄운다(점검에는 반영됐지만 파일에는 없는 상태). 파일에 쓰지 못했을 때(디스크·권한)는 `파일에 저장 못 함 — 재시작하면 사라짐`이 다음 저장이 성공할 때까지 남는다.
4. **환경 변수(13)**: 그 칸이 쓰는 환경의 변수 값을 고친다(키 추가·삭제·이름 바꾸기는 GUI). **값은 가려져 있고**(`••••••••`) `v`로 이 화면에서만 본다. `Enter`를 누르면 입력줄에 그 값이 보인다(고치려면 보여야 한다). 같은 환경을 쓰는 칸이 여럿이면 화면 오른쪽 위에 `이 환경을 쓰는 칸 N개(보드 M개)`, 입력줄 위에 노란 글자 `이 값을 쓰는 칸 N개(보드 M개)가 함께 바뀝니다`가 보인다 — **그 칸들이 모두 다음 점검부터 새 값을 쓴다.**
5. **시나리오 변수(14)**: 시나리오 `variables:`의 **고정 값 한 줄만** 고친다. 저장된 파일의 시나리오는 그 값 한 줄 말고는(주석 포함) 글자 그대로다. 생성 변수(`생성 변수 — GUI에서`)와 여러 줄·앵커처럼 한 줄로 안전하게 바꿀 수 없는 값(`이 값의 모양은 TUI에서 못 고칩니다 — GUI에서`)은 고칠 수 없다. **자주 바꿀 값은 시나리오에 `${ENV}`로 빼 두면 환경 변수(13)로 고칠 수 있다.** GUI 등 다른 곳에서 같은 시나리오가 바뀌었으면 `다른 곳에서 시나리오가 바뀌었습니다 — 다시 열어 주세요`가 뜬다.
6. **고칠 수 없는 항목**: 시나리오(2)는 항상 GUI에서(`시나리오는 GUI에서 바꿉니다`). 묶음 칸의 환경(3)·점검 주기(5)는 묶음의 값이라 GUI에서(`묶음의 값입니다 — 묶음 설정은 GUI에서`). 볼 스텝(4)은 묶음 칸에서만 고를 수 있고(조건·화면 표시 값이 있으면 그것들도 새 스텝으로 옮겨진다는 확인 줄이 뜬다), 응답 시간 기준(7)은 스텝 칸이 아닐 때만. 성공 조건(11)·화면에 표시(12)는 있는 것을 고치거나 지울 수만 있고 **새로 추가는 GUI에서**(다음 버전에서 TUI 지원). 조건 수정에서는 규칙·값·대소문자/공백 무시만 바꾼다(대상 경로는 GUI). 규칙을 `←` `→`로 넘기는 순서는 GUI 드롭다운과 같다(`=` `≠` `키 있음` `값 있음` `글자 포함` `>` `<` `≥` `≤` `∈`).
7. **파일 소유자·권한**: 저장하면 보드 파일과 백업은 TUI를 실행한 사용자의 것이 되고(그룹도 그 사용자의 기본 그룹), 권한 숫자(예: 0600)는 원래 파일 그대로 따른다 — 그룹 읽기를 준 파일(0640)이었다면 저장 뒤 읽을 수 있는 그룹이 달라질 수 있다.

읽는 법:

- 시나리오·환경·스텝은 이름으로 보인다(보드 파일 안에서 읽는다).
- **`볼 스텝`의 URL은 시나리오에 적힌 그대로**다(`{{변수}}`·`${ENV}`를 채우지 않는다). 실제로 보낸 값은 오류 보기의 요청·응답에서 본다.
- 묶음 칸은 시나리오·환경·점검 주기에 `(묶음)`이 붙고 맨 아래에 `(묶음) = 점검 묶음 N의 값 — 칸마다 따로 못 바꿉니다` 각주(N은 GUI와 같은 묶음 번호 — 칸 목록에서 그 묶음이 처음 나오는 순서).
- 환경을 다른 것으로 바꿔 옛 환경을 쓰는 칸이 하나도 안 남으면 그 환경은 보드 파일에서 빠진다(확인 줄이 먼저 뜬다).

## 5. 파일 교체 (새 칸 반영)

GUI에서 칸을 추가한 뒤 보드를 다시 내보내 **같은 경로의 파일을 덮어쓰고 TUI를 다시 띄운다**(`q` → `y`로 종료한 뒤 자동 시작 명령을 다시 실행하거나 PC 재로그인). 시작할 때마다 파일을 새로 가져오므로 새 칸을 포함해 점검이 시작된다. 재시작하면 막대 이력·기록은 비워지고 처음부터 쌓인다.

**새 파일로 덮어쓰면 이 PC의 TUI에서 고친 값(§4-2)은 사라진다** — 새 파일이 그대로 쓰인다. 고친 값이 필요하면 GUI 쪽 보드에도 같은 값을 넣어 다시 내보내거나, 덮어쓰기 전에 `<파일>.bak`을 따로 챙겨 둔다. 파일은 **TUI를 끈 뒤에** 바꾼다(켠 채 바꾸면 그 뒤의 수정이 파일에 저장되지 않는다 — §4-2 3번).

## 6. 로그

`$XDG_STATE_HOME/handicap/`(기본 `~/.local/state/handicap/`):

- `tui.log` — 이번 실행 로그(실행마다 새로 씀)
- `tui.log.1` — 직전 실행 로그 하나
- `tui-check.log` — `--check` 전용 로그(돌고 있는 화면의 로그를 건드리지 않으려고 분리)

로그 파일은 권한 0600, 새로 만든 로그 디렉터리는 0700이다(`HOME`·`XDG_STATE_HOME`을 모두 알 수 없으면 임시 폴더로 대신하지 않고 "로그 없음"으로 표시한다). 터미널 화면에는 로그가 나오지 않는다. 문제가 생기면 이 파일을 본다(기본 수준 `info`, `RUST_LOG=debug` 등으로 조정). 비정상 종료 시 터미널에 "로그: <경로>" 한 줄이 남는다.

## 7. `--check` (점검 1회 후 종료)

`handicap-tui --check /home/ops/board.json` — 모든 칸을 한 번 점검해 칸마다 한 줄(`보드 / 칸  상태  큰 값`)을 출력하고 종료한다. 배포 전·문제 확인용이고 화면은 열지 않는다.

| exit | 뜻 |
|---|---|
| 0 | 모든 칸의 결과를 받았다(칸이 실패 상태여도 0 — 상태는 출력으로 본다) |
| 1 | 기동·파일 가져오기·시작 실패, 또는 종료 신호(SIGHUP/SIGTERM/SIGINT)로 중단 |
| 2 | 대기 상한 초과(⌈실행 단위 수/32⌉ × 칸들의 `check_budget_seconds` 최댓값 + 10초) |

## 8. 보드 수와 PC 부담

- 파일에 든 보드는 **전부** 시작되어 계속 점검한다(화면에서 폴링하는 것은 보이는 보드만). 한 파일 최대 50보드까지 허용하지만 저사양 PC에서는 내보낼 보드를 꼭 필요한 것만 고른다.
- 칸마다 기록(요청·응답)을 메모리에 쌓는다. 최악치는 칸 수 × 막대 수(`bar_count`, 최대 300) × 기록 상한(`record_limit_kb`)이다. 메모리가 빠듯한 PC는 GUI에서 `record_limit_kb`를 낮게 잡아 내보낸다.

## 9. 보안 전제

내장 컨트롤러의 REST는 루프백에만 열리지만 **인증이 없다** — 같은 PC의 다른 사용자·프로세스는 환경 값(평문 포함)까지 읽을 수 있다. **전용 단일 사용자 모니터 PC**에서만 쓴다.

- **이 PC에서 웹 브라우저로 인터넷을 보지 않는다.** TUI가 떠 있는 동안 악성 웹페이지가 DNS 재바인딩으로 `127.0.0.1`의 이 인증 없는 API에 접근해 환경 값을 읽을 수 있다.
- 임시 DB는 `$XDG_RUNTIME_DIR`(없으면 시스템 임시 폴더) 아래 **전용 디렉터리** `handicap-tui-<pid>-<무작위>/`(권한 0700, 안의 DB 파일 0600)에 둔다. 정상 종료(`q`→`y`)와 창 닫기·로그아웃(SIGHUP/SIGTERM/SIGINT)에서는 이 디렉터리째 지운다(신호 뒤 5초 안에 정상 종료하지 못하면 강제로 지우고 끝낸다). `kill -9`·전원 차단으로 죽으면 다음 시작 때(또는 재부팅 때) 정리될 때까지 남는다. 이는 이 전제 아래의 위생 조치일 뿐 보안 경계가 아니다.
- 로그 파일은 권한 0600이다(§6).
- 오류 보기의 요청·응답은 화면에만 그리고 파일·로그에 남기지 않는다. 화면을 볼 수 있는 사람은 응답 본문(업무 데이터)을 볼 수 있다.
- 보드 json에도 환경 값이 들어 있으니 파일 권한을 `chmod 600`으로 둔다. TUI가 만드는 백업(`<파일>.bak`·`<파일>.orig.bak`)에도 환경 값이 들어 있다 — 원래 파일과 같은 권한으로 만들어진다. **새어 나간 토큰을 TUI에서 바꿔도 옛 값은 `.bak`(다음 저장 때까지)과 `.orig.bak`(계속)에 남는다** — 필요하면 두 파일을 지운다.
- 환경 변수 값은 화면에 기본으로 가려져 있고, 고친 값·키 이름은 로그에 남기지 않는다. `~/.local/state/handicap/tui-writes.json`에는 TUI가 마지막으로 쓴 파일 내용의 지문(SHA-256)만 있다(값 없음).

## 10. 문제 해결

- 실행하자마자 `exec format error` → 대상 PC가 32비트 사용자 공간으로 설치된 경우다(이 바이너리는 x86_64 전용). `uname -m`·`getconf LONG_BIT`로 확인.
- 실기 확인 항목: 전체화면에서 `Ctrl`+`+`/`Ctrl`+`-`와 `--zoom=` 값이 글자 크기에 실제로 반영되는지(머지 후 실기 PC에서 한 번 확인).
- 터미널 창이 바로 닫힘 → 자동 시작 `Exec=`를 위 `sh -c '…; read x'` 형태로 감싸 원인을 남긴다.
- 화면 가운데에 오류가 뜨고 안 닫힘 → 파일 경로·json 내용 문제다. 원인이 화면에 적혀 있고 `r`로 다시 시도할 수 있다.
- 막대(`▂…█`)·테두리 문자 폭이 어긋남 → 터미널의 "모호 폭 문자" 설정과 로케일(ko_KR) 문제일 수 있다. 실기 확인 결과는 build-log 참고.
