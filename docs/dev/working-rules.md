# 작업 규칙 — 로컬 자동메모리 밖에서도 보여야 하는 것

> **왜 이 파일이 있나**: 사용자 피드백·결정의 상당수는 로컬 맥의 자동메모리(`~/.claude/projects/…/memory/`)에만 있었다. cloud 세션(claude.ai/code 컨테이너)은 그 메모리를 **읽지도 쓰지도 못한다**. 2026-11-12 점검에서 cloud 세션이 대부분 우연히(선례·spec 표 덕에) 따랐지만, 실수 1건(§B 번호 중복)과 사용자 지시 1건 미적용(TUI 칸 개수별 검증)이 나왔다. 그래서 **모든 세션이 지켜야 할 규칙의 정본을 여기 둔다**. 로컬 메모리 파일은 같은 규칙의 사례·서사를 가진 보조 기록이다. 규칙을 고치면 이 파일을 먼저 고친다.
>
> 루트 `CLAUDE.md`의 전역 규칙·슬라이스 파이프라인과 겹치는 것은 다시 적지 않는다. 여기에는 메모리에만 있던 것만 둔다.

## 1. cloud 세션 ↔ 로컬 맥 세션

- **cloud는 자동메모리를 쓸 수 없다** → 사용자 결정과 작업 방식 피드백("앞으로 이렇게 해라")은 반드시 **repo에** 남긴다. 결정은 그 슬라이스 roadmap §B 블록의 `사용자 결정(날짜, 다시 묻지 않는다)` 줄에, 작업 방식은 **이 파일에** 적는다. 대화에만 있던 피드백은 다음 세션에 사라진다.
- **cloud는 지정 브랜치(`ccr-*`)에만 push한다(master 불가)**. 슬라이스를 끝냈으면 roadmap §B 블록 머리에 **로컬 머지 절차**를 남긴다(선례 §B52 (0): 지금 상태 → 로컬 master 확인 → 단계별 ff-merge + 단계마다 맥 전체 게이트 → 맥에서 확인할 것 → push와 기록). 로컬 세션은 그 블록을 그대로 따르고, 끝나면 완료 표시를 한다.
- **cloud에서 못 한 검증은 "못 했다"고 남긴다**(nextest 미설치 → `cargo test --workspace` 폴백, `pnpm build` 메모리 부족, macOS 전용 동작). Linux에서만 실측한 테스트는 맥에서 깨질 수 있다. 실제로 엔진 connect 정체 픽스처가 macOS에서 RST로 끊긴 일이 있다(`crates/engine/CLAUDE.md`).
- **로컬 맥 세션은 cloud 작업을 시작하기 전에 master를 push한다**. cloud는 `origin/master`에서 갈라지므로, 로컬에 push 안 된 커밋이 있으면 ff가 안 되고 §B 번호도 겹친다(2026-11-11 merge `78abf72`에서 §B49 재번호).

## 2. roadmap §B 블록

- **새 §B 번호는 `grep -n '^### B' docs/roadmap.md`로 마지막 번호를 확인한 뒤 +1**로 정한다. 기억이나 현황판으로 정하지 않는다. 2026-11-11 cloud가 이미 있던 Windows §B48과 같은 번호로 1b 블록을 만들었고, 2026-11-12에 `§B48b`로 분리했다.
- **판단(ruling)은 비용과 해소법을 함께 §B에 기록한다**(사용자 지시 2026-10-16). 고치지 않은 리뷰 finding, 연기, 약한 테스트를 그대로 둔 것, 선재 버그를 각각 `무엇을 정했나 · cost-if-wrong · 구체 해소 경로`로 적는다. SDD ledger(`.superpowers/sdd/`)는 gitignore라 워크트리와 함께 사라진다. 블록 구성: (1) 다음 슬라이스 후보 (2) 판단과 비용·해소 (3) 선재 버그 (4) spec 연기 (5) 보안·성능 메모 (6) 테스트 공백. 선례 §B30.
- **공용 개념을 한 경로에만 적용하면 사용자에게 묻고 §B에 연기로 남긴다**(사용자 지적 2026-11-09). 응답 본문 JSON 해석, 템플릿 규칙, 판정 규칙처럼 여러 화면·경로에 걸친 개념이 대상이다. 축소를 spec 비목표 한 줄로 혼자 처리하지 않는다. 그 개념을 고치는 소형 수정에서는 `grep`으로 **같은 개념을 쓰는 형제 경로**를 함께 보여 준다. "연기 — 없음"은 그 sweep을 한 뒤에만 쓴다(감싼 JSON 풀기를 모니터에만 적용하고 시나리오 쪽을 놓친 사례 §B47).

## 3. 보안 게이트

- **`finish-slice` §0 grep은 하한선이다** — 매치가 없어도 diff가 **값을 새 sink로 옮기면**(로그 → DB, 내부 → API 응답, 임시 → 영속) `security-reviewer`를 돌린다. 그 sink에 이미 알려진 노출이 있는지 도메인 `CLAUDE.md`를 grep한다(parallel-var-scope: grep N/A였지만 평문 시크릿이 run 레코드에 들어가는 blocker가 나왔다).
- 연기 노트에는 **연기 조건**을 적는다(예: `operator-logs-only`). 그래야 나중에 그 조건이 깨진 것을 알아챌 수 있다.
- 시크릿 가림 테스트의 픽스처 값은 `{:?}` escape를 그대로 통과하는 문자셋으로 쓴다. 따옴표나 비-ASCII가 든 값은 escape되므로, 누출하는 빌드에서도 테스트가 green이 된다.

## 4. 라이브 검증

- **극단값에서도 읽혀야 한다**(사용자 지시 2026-10-22). 최대 개수, 촘촘히 몰린 값, 가장 긴 문자열, 큰 숫자, 최대 글자 크기, 범위 밖 값을 넣고 겹침(사각형 교차)과 잘림(`scrollWidth>clientWidth`)을 실측한다. 극단 설정에서 판독이 안 되면 "수용 한계"가 아니라 결함이다. 폭 제약 보드와 높이 제약 보드는 따로 본다.
- **컴포넌트가 마운트되는 모든 진입 화면에서** 확인한다. 소비처를 grep해 진입 경로를 열거하고 각각에서 US를 실행한다(신규 생성 화면은 정상인데 저장된 리소스 편집 화면에서는 기능이 없던 사례). 반대로 "부재"가 단계 차이일 수도 있으니 게이트(템플릿 갤러리 등)를 먼저 확인한다.
- **버그는 스펙보다 구현에서 나온다**(사용자 2026-06-29: "스펙은 항상 좋아. 구현했을 때 버그가 문제"). spec 의식에 과투자하지 말고 구현 뒤 검증에 rigor를 쓴다. 시각 표면은 DOM 존재나 텍스트만으로 PASS하지 않는다(rect 높이·폭 단언 또는 스크린샷). 새 UI는 스크린샷 전체를 눈으로 먼저 훑는다.

## 5. 작업 크기·UI 선호

- **소형 수정은 브랜치만으로 해도 된다**(사용자 허용 2026-11-01). 파일 3~4개, UI 한정, 엔진·와이어·마이그레이션 무접촉이 조건이다. 먼저 변경 범위(파일·줄 수·안 건드리는 층)를 제시하고 동의를 받는다. 최소 절차는 지킨다: 테스트 먼저(일부러 망가뜨려 RED 확인) → 커밋 게이트 → 라이브(극단값 포함) → build-log에 "사용자 요청 소형 수정 — spec/plan 없음" 한 단락 → ff-merge.
- **선택적 폼 섹션은 기본 접힘 disclosure로, 대량 데이터 표·미리보기는 자동 노출 금지(명시 버튼 뒤 opt-in)**(사용자 선호). seed 값이 있으면 자동으로 펼치고, 접힌 채 값이 있으면 "N개 설정됨"을 표시하며, 인접 섹션과 간격을 둔다. 히트 영역은 크게, 시각 간격은 조밀하게. 이 사용자는 간격·일관성·a11y에 민감하므로, 리뷰가 Minor로 잡은 신규 UI 일관성 항목도 바로 반영한다.

## 6. 터미널 모니터(`handicap-tui`) 사용자 결정 (2026-11-07~08, 다시 묻지 않는다)

- 대상 아키텍처는 **x86_64 확정**이다. 운영 모니터 PC는 Ubuntu 19.04 저사양이고, 실사용은 보드당 6칸이다.
- **라이브 검증은 칸 개수별(1–9) 전부 확인**한다(사용자 지시 "검증 갯수별로 다 확인"). 모니터 화면의 칸 그리기·배치·머리 줄·키 줄을 바꾸는 슬라이스에 적용한다. 바꾸지 않았으면 그 근거를 build-log에 한 줄 남긴다.
- 조작은 TUI 관용(키 안내 줄·방향키·번호 메뉴), 상태 판정은 GUI와 같게 한다. 모니터 화면의 *표현*은 GUI 전시 화면을 따른다(칸 높이를 채우는 막대·기준선·큰 응답 시간).
- "json 파일이 곧 설정"이다. 매 실행마다 빈 임시 DB에 가져오고, 수정은 같은 파일에 되쓴다. 새 파일로 바꾸면 TUI에서 고친 내용이 버려지는 것은 수용했다.
- 마우스로 칸을 클릭해 고르는 것은 포함한다. 글자 복사는 거의 안 쓴다. 글자 크기는 터미널 글꼴(`Ctrl`±·`--zoom=`)로 정하며, 한글 픽셀 글꼴은 기각했다. 테두리는 굵은 선이 기본이고 `b`로 반 칸 블록과 전환한다. 실패 막대 위의 x 표시는 하지 않는다(사용자는 GUI의 ✖도 싫어함).
- 자동 시작은 `~/.config/autostart/*.desktop` + `gnome-terminal --full-screen --zoom=1.6`.
- 시각 결정을 위한 목업은 실제 터미널 문자 격자로 그린 HTML로 만든다(`docs/superpowers/specs/2026-11-08-tui-readability-mockups/`). 목업은 보여 주기 전에 repo에 저장하고 경로를 알려 준다(임시 폴더는 정리돼 사라진다).
