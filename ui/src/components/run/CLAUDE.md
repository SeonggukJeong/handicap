# Run 설정·스케줄 폼 (`ui/src/components/run/`) 함정

이 파일은 `ui/src/components/run/` 파일을 **Read 도구로 열 때** 자동 로드되는 2단계 중첩 CLAUDE.md다(Bash grep/cat로는 로드되지 않는다). 전역 규칙은 루트 `CLAUDE.md`, UI 공통은 `ui/CLAUDE.md` 참고.

> RunDialog·LoadModelFields·DataBindingPanel·EnvironmentPicker·Criteria·sizing helper·ScheduleForm·TriggerBuilder·RunVuCell·RunListControls를 다룬다. `api/schemas.ts`·`pages/`·`runPrefill`에도 실수 지점이 걸친 run 함정은 `ui/CLAUDE.md`에 남아 있다(실수 지점 기준 — 2026-11 재분배, `docs/superpowers/specs/2026-11-06-ui-claude-md-redistribute-design.md` §3.2).

## 폼·입력 UX / 진단 표시 (RunDialog, RunDetail)

- **RunDialog의 seeded `binding`은 이중 소스가 아니라 수렴** (Area A1): RunDialog는 `binding` state를 `initial?.profile.data_binding`으로 시드 **하고** DataBindingPanel에 `initialBinding`을 넘기며 `onChange={setBinding}`로 받는다. `scenario`가 있으면 패널이 mount 후 동일 바인딩을 다시 emit해 seed와 **수렴**(충돌 아님). `scenario===null`(파싱 실패 등으로 패널 미마운트)이면 패널이 `setBinding`을 안 부르므로 **seeded `binding`이 그대로 payload에 실린다** — 그래서 seed는 load-bearing. 패널 mount 시 "binding을 null로 리셋"하는 패턴을 넣지 말 것(seed를 날린다).
- **RunDialog 프리셋 load는 명시적 사용자 액션이라 imperative reseed 허용** (Area A2): A1의 "no reseed effect" 규칙(우발적 refetch 덮어쓰기 방지)의 문서화된 예외. DataBindingPanel은 mount-시 1회 seed라, 프리셋 load 시 `panelKey`를 bump해 패널만 remount해서 새 `initialBinding`으로 재시드. 로드된 profile은 항상 `normalizeProfile`로 정규화(Zod 누출 차단).
- **선택적(optional) 폼 섹션은 접이식 disclosure로 — collapse-by-default는 기존 RTL 테스트를 깬다** (A4a follow-up): RunDialog "SLO 기준 (선택)"을 `▸/▾` 토글(`<legend>` 안 `<button aria-expanded>` + `{open && …}`, `ScenarioSnapshot` 이디엄)로 기본 접힘 전환. 함정: **접히면 입력이 DOM에 없어** `getByLabelText(/Max p95/)`가 실패한다 — 그 섹션 입력을 만지는 기존 테스트는 먼저 `await user.click(getByRole("button",{name:/SLO 기준/}))`로 펼쳐야 한다. seed(prefill)된 값 있으면 자동 펼침(`useState(()=>criteriaHasValue(initC))` + preset-load 시 `setSloOpen(true)`), 접힌 채 값 있으면 "N개 설정됨" 힌트로 활성 상태 노출. 토글 텍스트에 caret(`▸`)이 들어가므로 버튼/그룹 셀렉터는 정확매치 말고 정규식(`/SLO 기준/`). UI 선호 일반화는 auto-memory `ui-optional-sections-collapsible`.
- **타일·Segmented 셀렉터 teeth는 `getByRole("radio")`로 부족 — Segmented(`role=radio` 버튼)와 native `<input type=radio>` 둘 다 매치해 구현 교체를 *감지 못 함*** (rundialog-mockup-fidelity): 부하모델 라디오→타일 카드, 프로파일 라디오→`Segmented`로 바꾸는 슬라이스에서 `getByRole("radio",{name:"고정"})`는 라디오든 Segmented든 통과 → "tile mode가 Segmented를 그렸나"를 증명 못 함. **구분 신호 = `Segmented`는 컨테이너 `role="radiogroup" aria-label=…` 렌더**(native fieldset+legend는 `role="group"`이지 radiogroup 아님) → `getByRole("radiogroup",{name:"프로파일"})`(tile mode 존재)+`queryByRole("radiogroup",{name}).not`(radio mode 부재)로 강화. 타일 *선택* accent는 `toHaveClass("border-accent-500")`+비선택 `.not`(ternary 뒤집기 teeth).

- **번호 `Section` 재구성(분리·이동·재시퀀스)은 index `ascending`=DOM 순서가 계약 — 이동 시 블록을 옛 위치에서 삭제+정확히 1회 존재 확인** (rundialog-mockup-fidelity): 측정 블록을 판정·고급 *앞*으로 옮기고 `index={4}`로, 판정·고급 `index={3}→5`처럼 재번호할 때 `grep -c "<EnvironmentPicker"`/`"<DataBindingPanel"`/`role="switch"`/`onClick={savePreset}`로 **이동 컴포넌트가 중복 안 됐는지** + `grep "index={"`로 1~6 ascending 확인. ## 다단계 ramp UI (RunDialog stages 편집·미리보기, S-D)

- **stage 행은 string-draft 상태 — 제출 시 Number 변환, onBlur-commit 불요** (S-D): RunDialog 로컬 state `stages: {target: string; duration_seconds: string}[]`가 string으로 rows를 들고 있다가 `buildProfile`에서 `Number()`로 변환. Inspector의 `commitOnBlur` 패턴(S-A) 없이 단순 string state로 충분(RunDialog submit이 최종 commit 경계 — `targetRps`/`maxInFlight`와 동형, Zod store 미접촉이라 partial-string 무해).
- **곡선 payload는 `duration_seconds: 0` + `stages`, `target_rps` 생략** (S-D): RunDialog 곡선 모드에서 `duration_seconds: 0`(required field, >0이면 controller가 stages와 상호배타 400), `target_rps` 미포함. 고정 모드는 반대로 `target_rps` 포함·`stages` 미포함.
- **Recharts 미리보기는 jsdom explicit size + stroke `#2563eb` + `type="linear"` (piecewise-linear, `monotone` 금지)** (S-D): `StageCurvePreview.tsx`는 `width`/`height` prop이 주어지면 bare `<LineChart>`(테스트 경로 — jsdom은 layout이 없어 ResponsiveContainer가 size 0), 없으면 `ResponsiveContainer`(프로덕션). stroke 색 `#2563eb`(`TimeSeriesChart`와 통일), `<Line type="linear">`(monotone는 piecewise-linear를 부드럽게 왜곡 → 금지). `toControlPoints`는 `(0,0)` 시작점→누적 x(초) 제어점 배열. 미리보기 div `role="img"` + `aria-label` a11y.
- **부하 모드 셀렉터는 2축(loadModel×rateMode) 유지 + `LoadModelFields`/`loadModel.ts` 추출** (모드 선택기): `buildLoadProfile`(순수)이 모드별 필드 형태를, `loadModelErrors`(범위 플래그)+`canSubmit`(Run 버튼 disable)이 숫자 범위를 막는다(§7.1/§7.2 분리). http_timeout은 모드 무관 공유 입력 1개(RunDialog), max_in_flight는 open 1개(LoadModelFields). 모드 추가 시 `loadModel.ts` 불변식 테스트가 격리 회귀를 잡는다. 제출 payload는 추출 전과 byte-identical.

## 데이터 바인딩 패널 (8c, `DataBindingPanel`)

- **`BindingPolicyEnum`에 `unique` 포함 (4정책)** (unique 바인딩): `schemas.ts`의 `BindingPolicyEnum = z.enum([..., "unique"])`. `DataBindingPanel`의 정책 `<select aria-label="policy">` 테스트는 데이터셋 선택 후(`findByRole("option")` settle 대기) `unique` 옵션과 stop-VU 경고 배너를 단언할 것 — 기존 `per_vu`/`iter_*` 패턴과 동일.
- **바인딩 검증은 extract/scenario.variables로 채워질 `{{var}}`를 false-alarm으로 막으면 안 된다** (Slice 8c): "매핑 안 된 `{{var}}`가 있으면 invalid" 로직을 단순하게 쓰면, 실제로는 extract나 scenario.variables로 런타임에 채워지는 변수를 missing으로 표시해 유효한 시나리오를 blocking한다. 데이터셋이 선택된 상태에서만, 그리고 column 매핑이 실재하지 않는 열을 참조할 때만 invalid 처리.
- **함정(CRITICAL, Task6 자가적발): 멀티-카드 패널의 per-card "uncovered var" 검사는 *형제 카드*가 공급한 var를 union해야 한다 — 안 하면 분할-데이터셋(이 기능의 핵심)을 거짓 차단** (다중 데이터셋 바인딩): 이 섹션 위쪽 "바인딩 검증은 … false-alarm으로 막으면 안 된다"(Slice 8c)의 멀티바인딩 analog. DSA→`username`·DSB→`token`처럼 변수를 카드별로 쪼개면 각 카드 단독으론 "다른 var 미매핑"으로 보여 false-alarm. `coveredByOthers`(형제 카드 emit var의 **stable newline-string**)를 각 카드의 uncovered 검사에서 제외. **React 핏포인트 루프-안전**: 카드↔부모가 서로 영향 주므로 `useCallback([])` 부모 콜백 + `sameJson` deep-equal 가드(handleCardChange/Validity) + `coveredByOthers`를 Set 아닌 stable string으로 전달 — 세 방어가 각각 다른 루프 벡터를 끊는다(lint exhaustive-deps 통과≠루프 없음, 로직으로 확인). 회귀 테스트 `does NOT flag a var as uncovered when a sibling card supplies it`.

## 풀 용량 409 clamp (LAN L4·L5)

- **open-loop 409 clamp는 mode 분기 — open이면 `max_in_flight`를 줄인다(`vus` 아님)** (LAN L4): L3 줄여진행 clamp `{...buildProfile(), vus: achievable}`를 mode로 갈라 open-loop이면 **`{...buildProfile(), max_in_flight: achievable}`**(`target_rps`·`stages` 유지·`vus` 0). `Profile`에 두 필드가 다 있어 spread+override가 구조적으로 안전(RTL로 2번째 `createRun` 페이로드 `max_in_flight===achievable`·`target_rps` 불변·`vus` 미주입 단언). 프리뷰 over-hint도 open(고정·곡선)이면 `Number(maxInFlight) > idleCapacity`로 확장(`maxInFlight.trim() !== ""` 가드로 빈 입력 false). open 다이얼로그/힌트 워딩은 **동시 슬롯/요청**(VU 아님·`ko.capacityGuard` open 변형 키) + 안내문 "동시 슬롯만 줄입니다 — 목표 RPS 유지". 프리뷰 `idleCapacity`(Σ유휴 cap)는 best-effort 상한이라 `rate_peak<max_in_flight`(드묾)면 서버 achievable과 다를 수 있으나 **서버 409가 권위**(다이얼로그는 서버 `achievable`/`requested`를 표시·재계산 금지). `client.ts`/`hooks.ts`/Zod는 L3 그대로 재사용(0-diff) — UI만 clamp 필드 분기.
- **closed+curve 409 clamp는 3-way의 첫 분기 — `isCurve`를 `vus` arm *앞*에서 검사(곡선이 `vus` no-op arm에 빠지면 silent)** (LAN L5): L4의 2-way(open `max_in_flight` / else `vus`) clamp를 **3-way**로 — `isCurve = loadModel==="closed" && rateMode==="curve"`를 **최우선** 검사해 `{...buildProfile(), vu_stages: scaleVuStages(stages, achievable, peak).map(s => ({target: Number(s.target), duration_seconds: Number(s.duration_seconds)}))}`. 곡선 `buildProfile`은 `vus:0`+`vu_stages`라 만약 `vus` arm에 빠지면 clamp가 **no-op**(런타임 무증상·과부하 그대로 발사) → 분기 순서가 load-bearing. **`scaleVuStages`는 string in/out**(RunDialog stage 행=string-draft)인데 wire `vu_stages`는 number → clamp에서 `Number()` 변환 필수. `scaleVuStages(stages, achievable, peak)`(`sizing.ts` 순수): 각 `target = round(target × achievable/peak)`·**`t === peak`인 stage는 `Math.max(scaled, 1)` floor**(곡선이 all-zero로 붕괴해 엔진 `≥1 target>0` 거부되는 것 차단). `peak`은 항상 `peakStageTarget(stages)`(=실제 max)를 넘겨 최소 1개 stage가 floor 대상(caller drift 시 floor 미발화 가능=알려진 robustness nit, 단일 call site라 안전). 프리뷰 over-hint도 closed+curve면 `peakStageTarget(stages) > idleCapacity`로 확장(`overHintCurve`·role=status). 다이얼로그 문구는 **부하 divergence 명시**(제품요구 [[load-divergence-explain-confirm]]): 줄여진행=`clampNoteCurve` "곡선을 N/M배로 축소→설정보다 낮은 부하"·강행=force "과부하→목표 미달 가능". 정상 fan-out(peak≤용량)은 divergence 아님→다이얼로그 없이 실행. 신규/수정 문구 전부 `ko.capacityGuard` 곡선 변형(인라인 0)·`client.ts`/`hooks.ts`/Zod L3/L4 그대로(0-diff).
